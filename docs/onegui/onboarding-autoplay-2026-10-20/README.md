# 自动导览与手机屏幕打磨

## 改动

- 移除舞台中的点击模拟与手动重播。进入章节后自动展开、留出读屏时间、收回并继续循环；章节切换仍由用户自主选择，并保留真实功能直达按钮。
- 三维模型实际到位后才启动停留计时，准备态停留 700 ms，结果态停留 1800 ms。暂停、离屏与页面隐藏时自动冻结剩余时间；开启减少动态效果时直接展示结果态；自动轮播字幕避免重复触发屏幕阅读器播报。
- 按用户要求将导览中的手机与平板屏幕全面替换为实际运行的 OneTHU 页面截图，移除原有的手绘示意屏、平板虚拟首页及手机旁自绘的伴随卡片。截图完整保留原始视口比例，机身镜头与边框排布在应用画面区域之外，三种体验模式分别展示对应的真实首页。
- 手机改为窄边框造型并去掉背部 OneTHU 字样。单手机章节采用独立高度令牌 `--og-tour-phone-h` 与更近的镜头取景，双机碰一碰章节则保持双机完整入画。
- 截图来源覆盖课表、实用模式目录与替换入口、暂存箱发送/接收、组织与选修功能：页面组件与样式均取自真实运行的应用，示例课程、组织与收发内容由隔离数据夹具提供，原样保留应用内的按钮形态与桌面环境下的 NFC 状态提示；接收完成画面则通过测试口令走完真实收发流程后截取（实体手机 NFC 联调在真机环境下单独验证）。
- 图片仅解码并缓存一次，每个模型实例独立持有各自的 GPU 纹理；模型退场时及时释放 GPU 纹理，再次打开时直接复用内存中的 CPU 图片。加载期间保持干净过渡，当环境无 WebGL 支持或资源加载失败时，自动切换为基于同一套真实截图的 CSS 降级界面。
- 旧物件沿视锥边界平滑退场并逐帧降低材质透明度，取代原先停在固定边缘等待删除的做法。半透明过渡期间关闭深度写入，切回原章节时模型可连续恢复，快速来回切换时直接复用正在退场的实体。
- 每个实体记录自身所属模式，快速跨模式切换复用实体时同步更新截图与包围盒范围，并衔接已有的位置、速度与透明度。`rapid-mode-report.json` 验证了实用模式首页尚在退场途中快速切入极简模式首页时，画面能准确呈现对应模式。
- 自动演示全程运行在隔离沙盒内，与用户真实的白板、暂存箱及组织数据互不影响。

## 验收范围

本轮通过 `tools/onboarding-autoplay-browser-test.mjs` 验证自动循环与生命周期，通过 `tools/onboarding-browser-test.mjs` 验证真实功能入口跳转与返回。旧脚本 `onboarding-motion-browser-test.mjs` 已转发至新测试套件；上一版手动演示的 902 项记录作为历史版本留存备查，本轮以新版自动循环套件重新统计。

截图与录像均直接采集自桌面浏览器的实际绘制输出，其中手机端效果通过移动视口与触摸模拟完成验证；实体手机渲染帧率与 NFC 硬件碰一碰留待真机实测。

## 真实界面来源

资产目录：`apps/desktop/src/assets/tour/real-ui/`。三份采集脚本分别记录目标页面、示例数据、视口尺寸与 PNG 哈希，汇总索引位于该目录下的 `manifest.json`：

- `tools/capture-tour-real-ui.mjs`：两种精简首页、目录与替换入口、课表、暂存箱收发。
- `tools/capture-tour-real-ui-workbench.mjs`：完整模式桌面/手机首页、真实组织概览。
- `tools/capture-tour-real-ui-extras.mjs`：工作区、OneGO、插件、外观、学习、数据设置。

原始截图直接绑定为 `THREE.Texture(HTMLImageElement)`，无需经过 Canvas 二次重绘或界面拼图；低性能降级界面通过同一个 `selectStudioScreen` 映射直接渲染 `<img>`。`asset-gate-report.json` 覆盖了延迟加载、失败降级与实际纹理来源检查。

## 真实截图模型验收

先启动本地开发服务，再执行 `node tools/onboarding-real-screens-test.mjs`（可通过 `ONETHU_TEST_URL` 指定服务地址、`CHROME_BIN` 指定浏览器路径、`ONETHU_MODEL_OUT` 指定报告输出目录）。

`real-screen-model-report.json` 保存了最新 984 项断言结果：涵盖 21 张真实截图、三种模式共 48 个模型实例，逐一验证原图直接绑定、页面映射、完整长宽比、窄边框占比、镜头安全区避让、圆角落在前盖玻璃面内、加载失败重试及幂等释放。此前 877 项临时检查已合并进该脚本，并补充了手机背部无字标与屏幕圆角边界检查。

手机机模移除了背部 OneTHU 标志与底部实体横条，仅在顶部边框内保留微型前摄。真实截图保持 390:844 比例，占前盖玻璃宽度与高度均超过 98%，占机身总高度超过 96%。最新四档视口取景见 `phone-framing-after-*.png`；`model/` 目录留存了去标后的首轮窄边框正反面特写，最终舞台边距以最新取景图为准。

资源释放断言通过监听 Three.js 几何体、材质与纹理的 `dispose` 事件确认生命周期回收完整，并将浏览器的正常退出与清理状态一并记入报告（底层 GPU 驱动显存占用可在实机性能剖析中进一步观测）。

## 最终取景与录像

最终单手机在 390/1280 视口下高约 358 px，占舞台高度的 89.5%；在 390 宽度界面下相比调整前（舞台高约 296 px），手机主体视觉高度提升约 57%。双机碰一碰沿用原有的双机取景构图，机身微调后显示高度变化小于 1%。`phone-framing-after.json` 的 23 项检查覆盖桌面、390/320 手机与横屏视口，确认居中翻转与拉近时模型完整入画、固定页脚按钮可正常点按。
