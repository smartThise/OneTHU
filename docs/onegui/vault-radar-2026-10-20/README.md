## 实际覆盖

基于真实 OneTHU 页面与组件、配合隔离的本地模拟云盘数据，在 1280×860、390×844、320×568、844×390 四档视口下逐项验证：

- 普通单击与键盘 `Enter` 直接打开暂存箱管理面板，打开全程平稳直接、无雷达闪现；面板内搜索过滤正常可用，关闭面板后焦点准确归还至入口按钮。
- 长按页面可投递内容时才唤起雷达；持续按住至少 670ms 期间，屏蔽旧标签页背景右键菜单与来源上下文菜单，确保手势干净独立。
- 拖入雷达扫描盘松手后，暂存箱准确新增一条记录；拖至 OH 目标松手后，真实 `ohAsk` 接收到原始内容，且暂存箱保持原件数不变。
- 长按暂存箱入口自身仅用于拖动调整入口贴边位置；在有效目标外松手、系统取消手势、窗口失焦或按下 `Escape` 时，均会干净释放雷达浮层、拖拽跟随预览与手势锁，同时避免误触发来源链接跳转。
- 320 窄屏视口下先执行真实纵向触摸滚动，将原处于第三行的「研讨项目」完整滚入固定底栏上方的可视区，随后长按并拖入 OH，投递内容与计数均准确无误。
- 完整覆盖深色主题、系统级减少动态效果、应用内减少动态效果与空箱零回波状态；各视口下雷达盘面与目标提示文字均处于屏幕边界内，844×390 短横屏下扫描盘与文字左右分列、互不重叠。

桌面端通过 Playwright 驱动真实鼠标与键盘输入；移动端通过可信 CDP 触摸事件驱动，按每步最大 6px、间隔 16ms 生成连续手指轨迹。移动端中途取消采用可信 `touchCancel`，桌面端 `pointercancel` 与窗口 `blur` 采用显式派发的生命周期事件。测试中仅对 OH 接收函数挂载只读观测钩子并照常执行原逻辑，同时在无 API 密钥的隔离夹具中拦截全部外部网络请求。

## 触控采样观察与验收说明

[native-cancel-observation.json](native-cancel-observation.json) 留存了前期使用稀疏触控点诊断时的现象记录：当仅用 6 次大跨度 CDP `touchMove` 模拟拖动时，Chrome 会将该手势接管为页面原生滚动并派发可信 `pointercancel`（无论目标条目靠近底栏还是已完整滚入可视区中部均会触发，说明该现象源于稀疏触控采样而非底栏遮挡）。遇到此类中断时，应用均能干净释放拖动状态；改用贴近真实手指轨迹的连续高频触控采样（每步 ≤ 6px、间隔 16ms）后，同一条目的长按投递稳定成功。早期用于排查的 capture 阶段 `touchmove` 与空操作 `touchstart` 试验代码已全部回退，保持生产代码简洁。

本轮验收在桌面 Chrome 的移动视口与可信触摸模拟环境下运行（数据与网络层使用本地隔离夹具，Android/iOS 真机、真实云盘账号与在线模型 API 在实机联调中单独验证）。除本脚本涵盖的 309 项断言外，同轮协作任务还分别跑通了拖动生命周期（54 项）、贴边入口（37 项）、竖向标签栏（19 项）、工作区（36 项）、菜单手势互斥（7 项），以及既有暂存箱回归（50 项）与短口令回归（52 项）。

全仓基础检查同样全部通过，包括 `typecheck`、OneGUI 护栏（469 个令牌）、CSS 与文档检查，桌面生产构建正常退出（耗时 8.63 秒）。

复现命令：

```sh
node tools/vault-radar-browser-test.mjs
```

可通过 `ONETHU_TEST_SIZES` 与 `ONETHU_RADAR_OUT` 指定测试视口范围与输出目录，设置 `ONETHU_RADAR_SKIP_VIDEO=1` 可跳过录像采集；如需复现前文记录的六步稀疏触控中断现象以供诊断对比，可传入 `ONETHU_RADAR_TOUCH_STEP=0`。
