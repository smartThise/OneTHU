# 私密分享与权限边界验收


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../../README.md)（[English overview](../../en/index.md)）。


新建私密分享时，应用使用 AES-256-GCM 加密清单与附件：短口令继续作为固定长度的云盘分享凭据，公开分享链接仅返回密文，随机密钥则存放在独立的私有资料库中，依托清华云盘账号权限控制访问。密钥通过内存字节流直接上传，全程免落盘。更换接收人时会自动轮换口令与密钥并撤销旧链接；普通重命名则保留原口令。

轮换中断恢复状态保存在 `onethu.share.rotations.v1` 中，仅记录云端引用与元数据。若旧密钥已删除而旧链接撤销中断，系统会保留新分享并在下次启动后自动重试收尾，确保有效分享始终可用；组织的稳定分享位撤销中断后同样会保留可重试记录。

## 已执行

- `node tools/private-share-browser-test.mjs`：在四个独立浏览器上下文中运行真实应用模块与 WebCrypto，由 Node 端模拟服务端身份校验与 ACL 控制，覆盖匿名访问、授权账号读取、非授权账号拦截、本地邮箱伪造防御、附件解密、更换收件人、重启恢复、撤销中断重试、上传失败清理、旧码失效及组织稳定分享位，最新结果保存在 `report.json`（真实云盘实网接口验证由下方 Rust 测试覆盖）。
- Rust `seafile::tests::live_private_share_boundary`：连接真实清华云盘单账号并创建一次性隔离资料库，验证所有者身份识别、权限列表读取、纯内存上传、授权读取、匿名拒绝、公开密文读取、附件字节流接口、幂等删除与测试资源清理。
- 实网测试暴露出两处模拟夹具未能体现的服务端细节并已完成修复：新建资料库响应字段为 `repo_id`；资料库详情返回的 `owner` 为用户显示名，需从资料库列表接口读取真实账号标识。
- 组织权限同步前会先核查资料库所有者身份，并扫描已有的群组共享、全员共享、子目录共享及公开链接；若发现存在其他独立授权通道，同步流程会直接中止并给出明确提示，在保留用户原有外部共享设置的前提下提醒手动核查权限范围。

## 双账号联调入口

当前开发环境暂缺第二个实网测试账号，因此预留了以下手动联调测试入口，供具备双账号条件时随时执行验证：

```sh
cd apps/desktop/src-tauri
# 从本机安全环境注入两个不同账号的 Token，脚本不输出 Token。
cargo test --lib seafile::tests::live_two_account_permissions -- --ignored --nocapture
```

所需环境变量：`TSINGHUA_SEAFILE_TOKEN`、`TSINGHUA_SEAFILE_RECIPIENT_TOKEN`。该测试仅创建独立的私密测试资料库，依次验证读写授权、降级为只读、撤销访问与幂等清理。

GitLab 协作联调可使用 `tools/org-collaboration-live.mjs`（详见组织协作方案文档）。在安全模型上，接收方在撤权前已读取或另存到本地的内容无法远程擦除；旧版本发出的明文受限分享在发送方重新分享或点击「升级并复制」时会轮换为加密分享并撤销旧链接，而在发送方执行升级之前，已发出的旧版链接仍保持原有分享形态。
