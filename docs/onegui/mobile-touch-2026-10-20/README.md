# 手机操作与 OneGUI 收口验收 · 2026-10-20


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../../README.md)（[English overview](../../en/index.md)）。


本轮在 Chrome 移动视口（390×844、320×740、844×390）下完成浏览器端触控验收，全程使用 CDP `Input.dispatchTouchEvent` 与 Playwright 真实触摸及键盘输入（所有触摸事件均为 `isTrusted=true`，按真实命中判定执行），并逐张核验了阅读态、放大拖动、边角缩放、横向平移与横屏截图。

当前测试环境未连接实体 Android 设备（`adb devices -l` 为空），Android 原生 WebView、系统软键盘、原生文件选择器与设备 NFC 硬件交互留待真机接入后专项测试。

## 本次查出并修正的问题

1. **保存倍率持久保留**：此前自由摆放开关每次切换都会写入 500%，重新加载时又将低于 450% 的已存数值重置回 500%。现改为仅在缺少保存记录时执行首次初始化，用户显式保存的 100%、300% 等倍率均原样保留，且手机竖屏与横屏/桌面视图各自独立记忆；处于极简或实用模式时，后台未展示的白板保持未初始化状态，留待切换到完整模式时再按需初始化。
2. **触摸拖动全程连贯**：此前仅在外层条目上设置 `touch-action:none`，内层可滚动组件仍会中途抢占纵向触摸；且原生触摸移动 48×36 屏幕像素时原先仅换算写入约 10×7 世界坐标，修复后按当前倍率准确写入约 30×22。自由画布模式下内层主动让位给卡片拖动，阅读顺序模式则保留原生纵向滚动。
3. **选中瞬间防误触浮条**：点选卡片动态插入操作按钮时，手指抬起瞬间容易误触刚出现在指尖下的“固定”按钮。现已吸收同一次选中或拖动操作派生的点击事件，后续独立点按与键盘触发均正常响应；同时从自由摆放浮条中精简掉仅供阅读顺序使用的上下移与增减高度按钮。
4. **边角触控热区与倍率对齐**：将卡片边角调整手柄扩大到共享大控件的触控热区尺寸，在各缩放倍率下保持屏幕热区大小与角点对齐；390 与 320 视口下实测触摸拖拽宽高顺畅，刷新后尺寸持久保留。
5. **横向平移后模式开关常驻可见**：将「阅读顺序 / 自由摆放」切换开关移入固定工具列，画布横向平移后依然随时可点，并与 OneShot、OH 胶囊保持安全间距；旧白板提示语同步下移至顶栏下方，避开 OneShot 区域。

画布横向滚动由 `.explorer-panel` 局部承载，实测在空白处左右滑动即可顺畅浏览屏幕外内容，同时普通页面继续保持 `overflow-x:clip`，确保常规页面无意外横向溢出。

## OneGUI 收口

- 自定义卡面颜色统一接入共享媒体语义令牌，保持 Reference 作为唯一基础色料源。
- 图片取景改用新增的可复用组件 `FocalImage`（支持受控焦点与缩放，已登记至组件目录与画廊）。
- 卡面缩放改用 OneGUI `Slider`，完整保留键盘微调支持。
- OH 限额提示、手机文字排布与设置页样式从旧应用 CSS 迁入共享 recipes，尺寸全面改用结构令牌。
- 在保持原有 OneGUI 基线阈值不变的前提下，旧样式表从 9888 行缩减至 9742 行（低于既有上限 9753 行），组件库内字面颜色与尺寸违规均为 0。
