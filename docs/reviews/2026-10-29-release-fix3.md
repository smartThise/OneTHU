# 0.11.4-fix-3：升级路径与更新镜像修复

> 最后更新：2026-11-18 01:30

## 路径错误

原生 `spawn_daemon` 在独立 CLI profile 尚未建立时直接写入 `daemon-startup.log`。由于 GUI 应用数据与 CLI profile 分存两套目录，升级后仅存在 GUI 数据时 CLI 父目录可能尚未创建，文件系统原始错误便会直接传给登录流程。修复后先调用既有的私有目录初始化边界再创建日志，并将日志写入失败映射为 CLI 安装不可用；账号冲突、正在进行的二次验证、符号链接与运行时摘要失败继续保留原有安全错误。

新增测试从生产 Rust 源码提取并编译实际启动／私有目录／原子写入函数，使用独立临时路径与合成子进程执行验证（无需启动 Tauri 应用或读取真实账号）。修复前稳定复现缺失路径错误，修复后完整覆盖保留 GUI 数据但 CLI 目录缺失、路径被文件占用、可执行程序缺失和符号链接拦截；Windows 与 macOS 均已接入发布流水线，具体反馈用户的设备端登录结果待正式包发布后跟进确认。

## 更新镜像

云盘更新器绕开 WebVPN 直接调用 `http_native`，在原生接口增加必填 `epoch: u64` 后没有同步参数。该缺陷仍存在于 fix-2。此前联网更新检查的 IPC 夹具仅模拟 HTTP 响应，缺少参数校验，曾漏报为通过。

修复捕获当前原生 epoch，传入每次原生调用，重定向延续同一代次，响应后检查账号未切换。原生端已有公开发布资源的匿名客户端与 Cookie 隔离策略保持生效。新增严格参数夹具执行真实更新函数与代次函数：未登录 epoch=0、重定向、等待时切换账号、跳转前切换账号、Base64 内容均覆盖。原有超时、取消、多语言和联网检查夹具也加入必填参数断言。
