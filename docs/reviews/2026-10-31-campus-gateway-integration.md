# 校园代理：共享会话接入与 Mac dev 验收

日期：2026-10-31。分支：`web`。本轮不发布安装包，`main` 与 `dev3` 保持原状。

## 接入路径

代理管理器挂在已有 SDK 实例上，使用当前 `NodeSession` 的请求、Cookie 仓、账号 epoch 和退出生命周期。桌面经受限的原生 `cli_daemon_request` 调用私有 `gateway.control`；外部 CLI / MCP 权限开关与代理开关独立。`onethu gateway` 只连接已有 daemon，缺少运行时会明确报错。

桌面入口：完整模式设置齿轮 → Harness → 高级配置 → 模型 / MCP / 日志 → 校园超级代理。先启动代理，再打开校园浏览器。该浏览器使用独立临时配置、私有 CDP pipe 和本次 CA 公钥的进程内例外；不会安装扩展、修改默认浏览器资料、信任系统证书或覆盖系统代理。

系统接入另提供证书信任、PAC 启用及恢复操作。平台适配器拒绝覆盖正在使用的代理，采用写前记录和逐字段比较恢复，保留用户后来修改的值。账号退出与切换先撤销代理输出；即使恢复系统配置失败，旧账号也不能继续被使用。

## 实测中发现并修复的问题

1. WebVPN 的 `vpn_eval` 包装在原网址下无法运行。适配器以有界字节流移除已知函数源码包装，保留脚本内容；HTML 使用 raw-text 状态解析，避免误改注释、字符串、模板和非 JavaScript 数据块。未加入执行远程代码的 `eval` 帮助函数。
2. 网络学堂脚本需要读取其防伪 Cookie 才会向课程接口发送有效请求。网关仅投影 Learn 精确作用域、明确非 HttpOnly 的 `XSRF-TOKEN`，固定 Secure / SameSite / Path；认证 Cookie 保持在共享会话内。未知属性的 bootstrap 导入不能作为浏览器披露依据。令牌失效或不再允许披露时，清除浏览器旧值。
3. 校园网页弹出原生 JavaScript 对话框时，等待 `Page.navigate` 会使打开浏览器操作超时。现在窗口及认证处理准备好即完成打开操作；可见浏览器保留正常对话框，只有无界面的自动验收会拒绝对话框。
4. 代理独立开关需要与外部 CLI / MCP 权限分离。调整权限时保留已启动代理；退出账号、切换账号与移除运行时仍撤销代理。
5. 旧 HTTP 校园地址在 Chromium 中缺少来源元数据。仅对已配置映射且无请求体的 GET / HEAD 先跳到 HTTPS 门面，再进行正常来源校验；写请求不会自动重放。
6. 启动代理时重复调用 CLI 安装后的移交流程，可能覆盖后台更新过的同账号 Cookie。启动准备现在直接使用已就绪的同账号权威会话；只允许向具备 bootstrap 资格的空运行时移交，并将账号与 epoch 传到 SDK 的串行控制队列中再次核对。启动不改动外部 CLI 权限或任务配置。
7. 浏览器直接访问统一认证、注销与票据换取接口可能改变权威 Cookie，却没有经过 SDK 的账号生命周期。适配层在网络请求之前拦截这些账号控制入口，仍由 OneTHU 的登录入口完成认证；普通业务读写保留。

- 本轮只检查网页与只读接口；未下载真实附件，未提交作业、预约、消息或业务表单。

## 覆盖边界

已完成的是桌面当前会话、受控本机代理、校园浏览器和平台控制代码。实际系统证书信任与全机 PAC 没有在本轮改变；Windows 系统操作使用模拟平台测试，未作 Windows 实机验收。各校园站点需要分别验证网页、业务身份、附件与写操作。

手机系统入口、微信小程序、局域网配对、TUN、WebSocket 和 HTTP/2/3 尚未完成。系统代理也不能保证第三方网络库采用它。现阶段不能以网络学堂单站成功推断整个设备的全部校园服务已经接管。

Cookie 历史迁移边界：新的 SDK/core bootstrap 已保留未知 HttpOnly 属性，但旧版 native snapshot 曾将缺失属性导出为 false。投影仍严格限于 Learn 精确作用域的 `XSRF-TOKEN`；旧 native 合成记录的属性来源无法仅凭现存快照反推，后续 native 属性迁移需要单独覆盖。
