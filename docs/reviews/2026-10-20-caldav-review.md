# CalDAV 云日历复查与修复（2026-10-20）


> 归档说明：本文记录当时的代码审查与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

本次复查覆盖 `state/cloudCal.ts`、核心 CalDAV/ICS 模块、日程编辑门面与严格文件持久化。测试全程运行在隔离内存文件与模拟 DAV 服务之上，未读取真实本地账号文件，也未请求学校线上接口或改动真实云端日历。

## 历史策略核实

- MCP 早期记录「OneTHU 日程云同步 CalDAV 方案启动」对应 2026-09-08 的初始设计，后续版本已演进调整了自动上云范围。
- 提交 `433f84a7` 已下线课表自动上云，`a0c18677` 已停用作业 DDL 自动上传；本轮继续维持这两项自动上传关闭。
- 旧版 `buildHwCloudEvents()` 虽恒返回空数组，却仍会在学习数据订阅更新时触发清理远端 homework 事件。本轮移除了这一隐式清理逻辑：用户仍可手动编辑或删除云端事件，存量历史云事件则安稳保留，避免随学习数据刷新被意外抹除。
- CalDAV 云端同步与本地系统日历写入采用两条独立链路：打开日程页或手动触发同步时负责拉取 CalDAV，系统日历则由独立状态层按课表、作业与手动日程同步维护。

## 已修复问题

1. **初始化与账号隔离**：凭据读取与日历内容加载各自采用 singleflight 恢复。邮箱模块仅等待 `ensureCloudCalCredentialsLoaded()`，即使日历缓存或本地事件文件损坏，有效的邮箱凭据依然正常可用；若凭据配置文件自身损坏则明确报错拒绝。配置变更与日历内容变更分道通知，更换邮箱、更新授权码或断开连接都会及时通知邮箱消费者。云端镜像新增邮箱归属标记，未带归属的历史缓存在完成重新拉取前保持隔离，同时通过账号 epoch 拦截过期请求回写。
2. **下游消费者就绪屏障**：`ensureCloudCalMirrorReady()` 会先等待写入队列排空；遇到新账号或缺少归属标记的历史缓存时，还会等远端首次拉取成功后才开放给系统日历作为完整镜像消费，读取异常时直接向上抛出错误。
3. **并发串行与版本冲突**：扫描与增删改操作统一进入串行队列，并发刷新共享单次拉取结果；更新已有事件时沿用真实资源 `href` 与原始 ETag，新建事件带上 `If-None-Match:*`，编辑与删除带上 `If-Match`，遇到 `412` 状态码时提示用户先同步最新云端变更。当编辑草稿携带旧 ETag 时，始终以草稿打开时的版本为准检测冲突，防止后台同步刷新的新 ETag 掩盖并发修改。
4. **重复日程多实例保留**：本地镜像改为按资源 `href` 完整保存主事件（master）与全部单次例外（override），让同一 UID 下的多条实例完整共存，编辑主事件时也会一并保留同资源内的其余实例。本地同侧编辑按 `UID + recurrenceId` 精确定位更新；跨本地/云端移动整套重复系列则直接给出不支持提示，避免误删整个系列。
5. **跨侧安全移动**：`saveCalendarEvent()` 严格遵循“先写入目标侧、确认成功后再清理源侧”的顺序；若目标侧写入失败则完整保留源事件，若源侧清理失败则保留双份副本并明确提示用户。日程页与插件 `cal.edit` 统一走这一入口。
6. **底层持久化错误透传**：为 `clients.ts` 中的三个文件读写辅助函数新增可选的 `strict` 模式，并在日历模块全面开启。旧辅助函数会静默吞掉 Tauri I/O 错误，引入 `strict` 后，原生端除 `NotFound` 继续返回 `null` 外，其余读写异常均原样上抛；浏览器端 `strict` 模式使用独立 `localStorage` 键并在配额不足或写入失败时如实报错，从而为“先写后删”提供可靠保障。未开启 `strict` 的既有调用方行为保持不变。
7. **显式课表导出保护**：执行课表导出时先以条件请求写入全部新课程事件，全部成功后才清理过期旧项，避免新写入中途失败却已清空旧课表。遇到源数据缺少日期或时间格式非法时记录为 `skipped` 并中止破坏性整批导出；校园课程时刻统一锚定 `Asia/Shanghai` 时区，消除跨时区设备上的时间偏移。
8. **ICS 编解码细节完善**：补齐折行续行（continuation）前导空格处理，修正字面反斜杠转义逻辑；完整保留 `EXDATE` 与 `RECURRENCE-ID`；省略 `DTEND` 的全天事件按单日跨度解析；重复系列中的单次实例独立透传各自的提醒提前量。
9. **异常响应防护**：对格式无效的 207 多状态清单或返回 HTML 页面的异常响应直接按报错处理，防止误判为空日历而清空本地镜像；若 DAV 服务返回跨源（origin）地址则拒绝附带 Basic 认证凭据；连接配置探测阶段须确认存在可用日历后才报告配置成功。
10. **损坏配置下的重连与断开**：设置页共用的配置与断开入口直接针对凭据文件执行严格写入或删除，无需依赖日历内容先行加载成功，同时完整保留本地 cache/local 事件文件。只有在凭据落盘或删除成功后才广播新的连接状态，操作失败则维持原状态不变。更新凭据后，系统日历镜像仍须经过完整的内容就绪屏障校验；在途的慢速旧凭据读取也会被世代检查丢弃，确保已下线的旧账号彻底清空。

## 适用范围与已知边界

- 本轮验收聚焦客户端协议解析与状态机可靠性；线上学校服务器连通性、真实邮箱授权码验证、多设备并发编辑冲突表现及真实操作系统日历写入留待联调阶段实测。
- 当前 ICS 解析器面向课程表与日常日程场景实现了精简实用的 RFC 5545 子集，支持按日/周/月的基础重复规则、单次例外日期与提前提醒；涉及复杂 `RRULE`、会议参与者（Attendee）或自定义 `VTIMEZONE`/`RDATE` 的完整无损往返暂未纳入。
- 由于 CalDAV 协议按单条资源逐一提交请求，同步中途若遇网络中断或远端存储报错，已成功写入的条目会保留在云端；客户端此时会明确提示错误并完整保留本地可恢复副本，便于后续重试或核对。
- 缺少账号归属标记的历史镜像需完成首次远端同步后才会参与系统日历合并；离线状态下系统日历保持原有条目不变，避免误清空已有日程。
