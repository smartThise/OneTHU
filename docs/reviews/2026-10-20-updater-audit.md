# 整包更新执行层审查与修复（2026-10-20）


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

根据本轮更新后的需求，应用继续采用整包升级方案并集中加固执行层实现，暂不引入正式前端资源热更新（OTA）加载器、健康确认回滚或独立的签名发布平台。本轮验证均在本地隔离环境中针对正式整包升级链路开展，未实际发布新版本、读取真实签名私钥或调用系统安装程序。

## 当前链路

- 开发环境：`tauri.conf.json` 的 `devUrl` 指向本地 Vite 服务，用于开发阶段的热模块替换（HMR）。
- 正式资源：`frontendDist` 直接打包内嵌在原生安装包中，随整包安装一并更新。
- 整包更新：由 `lib/updater.ts` 拉取 GitHub 或公开云盘镜像清单、匹配当前平台并比较版本号；确认有新版后由 Rust 层下载安装包，并在用户点击安装后拉起系统安装确认界面。APK 由 Android 系统校验包名、版本与签名，桌面端则由操作系统安装器完成覆盖安装。
- 构建与签名：`.github/workflows/release.yml` 当前负责构建并上传 Actions 产物；本地 APK 脚本默认沿用既有 debug keystore，确保新构建的安装包能够顺利覆盖升级已有客户端。

## 已修复

1. **取消与并发控制**：将原先随新请求清零的共享取消标记改为每次下载独立的取消票据，并配合单任务下载闸门；等待响应头与读取 body chunk 阶段均可随时取消，取消后会直接丢弃底层 HTTP future 与响应连接，立即释放网络资源。
2. **流式传输与资源一致性**：直接复用当前 reqwest 内置的 `Response::chunk` 改为单次 GET 流式写入，移除了原先缺少 Content-Range / ETag 约束的多段 Range 拼接逻辑，也避免了整包一次性读入内存。下载仅接受完整的 HTTP 200 响应，单包体积上限 1 GiB，连接超时 25 秒、总请求超时 300 秒，超时或异常后直接返回结果。
3. **原子提交与失败清理**：每次下载使用独立的临时暂存目录，遇到正常报错、主动取消或异步任务被丢弃时均会自动清理该临时目录。仅在文件大小、哈希校验与磁盘 `sync_all` 全部通过后，才 rename 为最终完成文件，确保已下载的旧安装包、账号凭据与应用数据完好无损。
4. **输入校验边界**：生产环境强制安装包地址与重定向目标使用 HTTPS 且禁止在 URL 中内嵌凭据（隔离单测专用的本地 HTTP 开关仅限内部测试调用）；拦截路径穿越片段、控制字符、系统保留文件名、格式非法或为空的 SHA-256、超限大小及非原始传输编码。当清单未提供哈希值时明确标记 `verified=false`。
5. **安装入口校验**：桌面端与 Android 端统一经由 `updater_open_installer` 调起安装。入口会核验规范化路径是否位于更新缓存目录、是否属于当前进程成功完成的下载记录（上限 16 条），并在打开前重新核对文件大小、SHA-256 与当前平台安装包后缀，拦截外部放入的文件、下载后被改写的文件或未完成文件；应用重启后需重新下载校验再打开系统安装确认界面，全程由用户交互确认安装。
6. **APK 打包脚本**：调整为先创建输出目录再重定向构建日志；签名口令改为通过 apksigner 的 `env:` 参数读取环境变量，取代命令行 `pass:...` 明文传参，并在签名后立即执行 `verify` 校验。既有 keystore 与签名证书身份保持不变。

相关实现：`apps/desktop/src-tauri/src/updater.rs`、`update_download.rs`、`update_download_tests.rs`，`apps/desktop/src/lib/updater.ts` 的安装入口，以及 `apps/desktop/scripts/build-release-apk.sh`。

## 安全说明与后续待验范围

- **清单信任机制**：当前清单校验依托 HTTPS 传输加密与 SHA-256 文件摘要（云盘目录回退模式下核对文件大小）；若配置自定义更新源，客户端将按所配地址获取清单。独立的发行者离线签名验证留待后续版本建设。
- **真机覆盖升级待实测**：本轮通过注入隔离 I/O 异常验证了下载与校验错误处理；从旧版客户端在 macOS、Windows、Android 真机上执行完整的系统覆盖升级，以及真实磁盘空间耗尽、安装中途中断、包签名迁移与系统安装器回退等场景，仍需结合正式安装包在实机上验证。
- **暂存提交与系统安装交接**：下载层通过独立暂存目录与原子重命名保护下载文件完整性；校验通过并拉起系统安装界面后，后续包替换过程由操作系统接管。若下载途中遇到进程强杀或意外断电而未走完 Rust Drop 清理，该次临时暂存目录会留在缓存区内，不会进入已完成下载记录或被送入安装器。
- **数据目录隔离**：更新缓存目录与应用数据目录彼此分开，下载与清理操作仅读写更新缓存区，用户的账号、草稿、工作区与白板存档均独立保存在应用数据目录中；未来跨大版本若有存档结构变更，仍需由对应的数据迁移逻辑保障兼容。
- **平台覆盖范围**：目前官方发布产物覆盖 macOS、Windows 与 Android 三端；新的原生安装入口也会严格按当前系统平台校验后缀（如在 Linux 环境下拦截 DMG 文件），Linux 官方发布与自动更新链路留待后续单独规划。
