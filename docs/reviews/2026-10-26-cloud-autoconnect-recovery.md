# 云盘自动连接恢复（2026-10-26）


## 现场

原 dev 环境的设备本地授权中 `acknowledged`、`cloud`、`oh` 均为 `true`，本地无云盘配置文件（此前移除该文件的具体登出时机已无日志可查，与权限开关状态无关）。学校 Learn 会话恢复成功，而云盘直连 profile 请求连续落到统一认证登录表单；旧版静默连接仅处理 `checkSingle` 分支，尚未覆盖“已有学校主登录、但缺少直连 ID 会话”的场景。

此外，CLI 恢复路径会用后台快照整仓替换原生 Cookie 仓，导致同一账号在 GUI 中新建、但尚未同步至后台的直连云盘会话被一并覆盖。

## 修补

- 静默连接先等待设备授权初始化与持久化云盘配置读取完成，防止在配置尚未加载完毕时误判为未配置。
- 优先校验本地已保存令牌，遇到网络波动时保留原凭据，仅在服务端明确返回 401/403 时才尝试重新获取现有令牌。
- 多个启动入口共用单一连接流程；已登录的同账号可复用内存凭据与设备信任，最多续接一次直连认证，遇到二次验证要求则直接返回提示，避免循环提交。
- `InfoClient.ensureDirectIdLogin` 新增可选参数 `consumeServiceTicket`：云盘显式兑付本次认证产生的 OAuth 回调后再读取现有令牌（实测若仅建立 ID 会话便重新发起 profile，仍可能跳回登录表单）；默认行为保持原状，TUOJ 等既有调用方无需改动。
- 每个异步阶段均核对 native epoch、学校账号、云盘 credential version 和授权状态，拦截登出或换号后迟到的旧响应。
- CLI 恢复仅在持久化 GUI 账号与已验证后台账号一致时，保留后台尚未收录的直连学校服务 Cookie；同名重叠项与 WebVPN 控制 Cookie 统一以后台快照为准，换号、登出或归属未知时直接清空重建。
- 云盘授权开关与 CLI 逐次确认策略保持不变，全程未新建或删除云端资料库。

## 验证

- 真实原 dev 环境：自动取得现有访问令牌，原生 account 读取与资料库列表读取成功（共 13 个）；日志仅记录布尔状态与条目数量，未落盘令牌或文件内容。
- 云盘生命周期 30 项、私有会话交接 8 项、共享运行时 21 项、CAS 信任与服务回调 8 项测试全部通过。
- 桌面 TypeScript 检查与生产构建（含 7649 键 i18n 校验）通过。移除临时探针后重启原 dev，学校会话正常恢复，云盘配置持续保留，全程无需重新登录。
- 验证所用的临时实测探针已在交付前从源码中移除。

## 保留的边界

本地既无已保存云盘令牌、当前已登录账号也无可用内存凭据时，继续走原有的登录窗口手动连接入口。若学校服务端明确要求新的二次验证，则交由常规账号认证流程完成，恢复逻辑不会代填验证码或自动注册新的信任设备。
