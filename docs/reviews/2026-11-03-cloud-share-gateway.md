# 云盘分享页被网关误拦截（2026-11-03）


## 现象与定位

用户在数据结构课程页面点击清华云盘文件夹分享链接时，浏览器报错 `GATEWAY_CROSS_SITE_REJECTED`。本次排查直接在真实 Chrome 的课程页中点击「清华大学讲义最新版」链接，完整复现了该跳转拦截现象。

当时网关进程、系统信任 CA、PAC 分流与共享学校账号均正常运行，网络学堂、Info 门户及云盘个人资料库首页均可正常打开，问题集中在从其他校园子站点击进入云盘公开分享目录的跳转链路上。

根因位于 `packages/gateway/src/policy.mjs`：课程页面与云盘同属清华主域，浏览器点击跳转时携带 `Sec-Fetch-Site: same-site`，但该课程站点未登记为共享学校身份的受管业务 origin。旧版来源策略仅对少数固定跨站入口开放了用户主动导航放行，未涵盖云盘文件夹分享路径，导致来自同主域兄弟子站的正常点击跳转被拦截。

## 修正与边界

- 将规范的云盘文件夹分享路径 `https://cloud.tsinghua.edu.cn/d/<20 位小写十六进制 ID>/` 识别为通用只读导航入口，按格式模式匹配任意合法分享 ID。
- 用户主动触发的 `same-site` 与 `cross-site` 导航共用同一套精确入口判定：仅当请求同时满足 `GET` / `HEAD`、无请求体、无 `Origin`、`navigate` / `document` 以及 `Sec-Fetch-User: ?1` 时予以放行。
- 分享入口要求不含查询参数或 fragment 标记（含空 `?`）；其余 API 调用、写操作路径、深层子路径、非常规 ID、表单提交、内嵌资源及非用户激活跳转仍执行原有严格校验。
- 原有的同源 `Origin` 校验、本机套接字与当前用户核验、账号代际隔离、CSP、凭据隔离及请求方法限制保持不变。诊断日志仅记录 `cloud-folder-share` 类别枚举，省略具体分享 ID、完整 URL 与文件名。
