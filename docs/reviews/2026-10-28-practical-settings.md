# 实用模式设置页（2026-10-28）

## 起因

实用模式的设置沿用的是极简模式那一页「简洁设置」：单列十段，没有页签，也没有完整模式里的通知、外观、下载、帮助等分节。用户要求在实用模式另开一个设置界面，结构照搬完整模式的「个人设置」与「Harness」设置页；除白板、标签页、暂存箱、名片、组织、胶囊这类完整模式专属项，以及极客模式与帮助第一条（白板、暂存箱与组织导览）之外，其余分节全部复用。

## 实现

新增 `apps/desktop/src/pages/PracticalSettings.tsx`：七个页签（账号、通知、功能、外观、下载、帮助、关于）、同一套三栏几何（左导航加右内容，各自滚动）、手机端页签下拉；分节常驻挂载，只用 `hidden` 收放，切换页签与切换语言都不丢已填内容。页签标题、页签说明与分节锚点取自 `state/settingsMode.ts` 与设置页同一份清单。

分节内容没有第二份实现。账户、电子身份、记住的密码、版本、诊断、外观、壁纸、下载由 `pages/Settings.tsx` 导出后共用；云同步、外部作业源、通知、桌面小组件、帮助、权限与隐私、使用模式、语言、检查更新沿用各自组件。Harness 段直接渲染完整模式同一个页面，高级配置里的权限与命令概要、模型表单、MCP、日志抽成 `OhAdvancedPanels`，插件页与实用模式共用这一份。

被排除的项靠组件参数决定，不在新页面里删代码：外观分节传 `practical` 收起「标签栏默认样式」，帮助传 `compact` 收起第一条，工作空间传 `hideCapsule` 收起「点击胶囊默认打开」。这样两处差异只有参数，控件逻辑仍然一处。

两处文案按模式区分。页签说明里「外观」「功能」各自有一句只描述实用模式实际分节的说明；Harness 基础档的模型入口在紧凑模式下改为切到高级配置，说明文字同步改为在本页配置，避免指向不存在的插件页。

## 边界

- 设置浮层按模式分流：极简仍是简洁设置；实用为「个人设置」与「Harness」两段；完整仍为「我的名片、个人设置、插件、Harness」四段。
- 实用模式下名片与插件入口落到「个人设置」，插件页不会在紧凑壳里露出。
- 紧凑模式没有插件页，Harness 里的模型配置入口改为切换页内档位。

## 验证

- 桌面浏览器实测（1280×800，隔离预览数据）：七个页签、十九个分节、帮助里的「通知」直达、模式往返、极简与完整模式的原行为；截图在 `docs/onegui/practical-settings/`。
- 静态护栏 `tools/practical-settings-test.mjs`，已并入 `pnpm guard`，检查页签同构、分节同源、排除项未回流、Harness 只有一份实现。
- 类型检查、生产构建、i18n 词典检查（7698 键，0 错误）通过。
- 未覆盖：手机宽度下的视口实测。本机截图工具只有桌面视口，手机分支复用完整模式同一套结构与下拉，仍需真机复核。
- 浏览器预览里「下载」分节按平台能力返回空，与完整模式一致；打包后的桌面端显示下载位置一行。
- 安装包实测：以 `OneTHU_0.11.4-fix-1_x64-setup.exe` 覆盖安装后启动，经 WebView2 调试端口核对七页签、四个分段（完整模式）与两段式（实用模式）；切到实用模式后页签、账户、云同步均为真实数据。核对完成后已将模式切回完整模式并重新启动。当时那张截图露着本机的学号与邮箱，只留本地、不入库。
