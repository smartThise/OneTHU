# 网络学堂布局与课程快捷入口验收


> 归档说明：本文记录当时的代码审查与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

日期：2026-10-20。本轮验收在隔离浏览器环境内配合本地示例课程数据完成，全程未登录真实校园账号，也未请求学校线上接口。

## 问题定位与布局重构

- **放开宽屏列表宽度**：原先课程列表右侧留出大片空白，源于通用正文容器设定的 `1160px` 最大宽度限制。本轮专门为网络学堂主列表解除了这一宽度上限，其余正文页面继续保持原有版心宽度。
- **统一卡片等高与组件组合**：旧版课程卡在传入自定义 `style` 后会被兼容层额外包裹外层节点，导致 CSS Grid 仅拉伸了外层容器而内部卡片高度参差不齐，同时旧按钮兼容样式还干扰了卡片内部排版。新版课程卡直接基于 OneGUI 标准 `Card`、`Btn` 与 `Tag` 组合构建，样式统一收敛至 `recipes/learn.css`。
- **响应式网格与信息完整度**：课程网格采用 `--og-grid-min-xl`（`320px`）搭配 `auto-fill` 自适应排布，长课程名、任课教师与上课教室均可自然完整折行；手机窄屏下自动切为单列卡片，顶部四个汇总统计入口呈 `2×2` 网格排列。
- **独立平级快捷按钮**：卡片上的“网络学堂”“雨课堂”来源标签以及“未交”“通知”“文件”计数项均重构为彼此独立的平级按钮（计数为 `0` 时亦稳定保留位置），彻底消除了课程主卡片、收藏星标与快捷入口之间的按钮嵌套。
- **精准直达对应子面板**：点击网络学堂侧快捷入口会携带 `courseId/courseTab` 直达对应栏目；点击雨课堂侧入口则携带 `extCourseId/extCourseName/courseTab` 跳转，并同步为雨课堂课程页补齐了作业、通知、课件三类聚合视图（完整保留原有全量列表与细分类筛选），同名课程合并规则维持不变。

## 真实浏览器多视口验证

完整运行 `node tools/learn-layout-browser-test.mjs`，进程以退出码 0 结束，累计 **366 项断言全部通过**：

| 浏览器 | CSS 视口宽度 | DPR |
| --- | --- | --- |
| Chromium、WebKit | 1920、900、780、390 | 1 |
| Chromium、WebKit | 1536 | 1.25 |
| Chromium、WebKit | 1280 | 1.5 |

每组视口与缩放比组合均逐一核验了课程总数、同名课程合并、独立雨课堂保留、同行卡片严格等高、长文本完整折行无截断、页面无横向滚动溢出以及旧版兼容类名清理。在 `1280` 桌面视口下通过真实鼠标点击及 `Enter`、`Space` 键盘按键逐个触发来源与内容入口；在 `390` 手机视口下则启用真实触摸事件逐项点按验证。

针对排在列表最末尾、三项计数均为 `0` 的独立雨课堂卡片，脚本先滚动至页面底部，核验各按钮中心点未被底部常驻的 OneShot 浮层遮挡，随后执行真实触摸进入课程内页，并确认对应的 OneGUI 分组选项卡准确处于选中态。

注：首轮调试时曾遇到“点击卡片后断言仍停留在列表路由”的现象——排查确认真实点击事件与页面 DOM 均已顺利切入课程详情页，只是页面内部加载了带 Vite HMR 查询参数的路由模块，而测试脚本动态 `import` 了无参数路径，从而读到了另一份隔离的模块实例。将测试夹具改为复用页面实际加载的模块 URL 并同时校验路由状态与可见 DOM 后即全部通过，点击触发条件本身未做任何放宽。

此外，测试脚本还内置了三组配置自检（传入未知浏览器名、空视口列表或显式指定未安装的 WebKit），确认三者均会在启动浏览器前以退出码 1 报错中止，防止因配置拼写失误出现“0 项执行却静默通过”的假绿灯。
