# OneTHU 0.11.2 发布执行记录


在准备第二轮修订包期间，按用户指示直接升级版本号发布 0.11.2，将新版更新提醒弹窗、校内新闻发布单位语种同步与手机白板添加确认触摸优化一并合入，同步更新三端安装包与全部公开下载渠道。

## 当前阶段

应用源码冻结、三端正式构建及全套验包均已完成。GitHub Release `v0.11.2` 已正式公开并设为 Latest；清华云盘三端安装包、校验文件与自动更新清单已完成同步，三个平台通过真实更新器函数完成了主备双源读取与故障回退实测。官网下载快照生成与部署核验记录见下文。

升级版本号前在本地试构建的 0.11.1 APK 仅作为过程产物留存，线上已发布的 `v0.11.1` Release 保持不变；GitHub 与校内镜像仓库的 `v0.11.1` 标签均已对齐至线上实际发布的 `7413291a34e3b941a46481f9abafdf0b31dc6770` 提交，因改发新版本而中途停止的两次旧版构建任务已清理取消。

## 本轮交付内容

- 三种使用模式统一接入新版更新提醒弹窗，支持一键“前往更新”或选择 1 小时、1 天、7 天后再次提醒；延后到期时间按具体版本号持久化保存在本机，重启后继续生效，遇到更高的新版本时仍会正常提醒。
- 更新弹窗会自动避让正在显示的模态对话框、新手导览与导览实践返回条，支持键盘 Escape 与 Android 系统返回键延后关闭；点击“前往更新”后自动滚动定位至当前模式的软件更新区域并直接复用已获取的检查结果，后续下载与安装交由用户主动触发。
- 软件更新模块的检查源名称、进度提示、切源说明与安装引导均随界面语言实时切换；学校接口或原生系统返回的原始报错文本与版本发布说明保持原文呈现。
- 校内新闻读取按信息门户的中英文协议自动同步会话语言，切换语言与随后的数据拉取在客户端队列内串行执行，首页新闻组件与独立新闻页共享统一入口；本地缓存按语言维度隔离，防止迟到的旧语言响应覆盖当前视图，搜索结果与已打开文章顶部的发布单位名称也会随语言同步刷新。
- 极简与实用模式首页精简了两句重复的说明口号，清爽展示今日待办与今日课程，顶部日期格式随当前界面语言切换。
- 手机端白板添加组件的确认按钮改为独立接管触摸手势，兼容按钮内小幅自然手指滑移；滑出按钮边界、大幅移动或系统中断手势保持取消行为，抽屉退场动画期间保留当前详情预览以避免组件目录重挂载卡顿。
- 一并包含同日完成的 Android 学习会话与网关恢复、跨设备壁纸媒体打包备份、横屏平板白板显式编辑开关、学习页面磨砂玻璃一致性修复以及桌面端 OH 悬浮球单实例生命周期管理。

### Windows 单实例的实际代码核验

早期验包脚本曾通过搜索 `tracing::warn!` 字符串来确认单实例补丁已编入二进制，而编译器在 Release 优化下裁剪了该可选日志字面量。现已将验包工具升级为直接解析 PE 导入表、x64 ABI 寄存器传参与机器码分支目标：经对安装器内解包出的 `onethu.exe`（SHA-256 为 `4b6cfa7abaef68254e5c20a81c45fd84f983f9aa179b616ae69827116264ee2a`）静态反汇编分析，确认二进制内完整包含最多 40 轮窗口探测、每轮 25 ms 休眠等待、携带 `WM_COPYDATA` / `SMTO_NORMAL` / `10000` ms 超时参数的 `SendMessageTimeoutW` 调用，以及轮询耗尽或唤醒消息发出后的进程退出路径。

9 组机器码特征核验全部通过；同时使用原文件与 10 份单字节篡改样本进行正反双向校准，共 11 项夹具测试全部通过。最终验包流程直接针对正式发布包重跑校验，并将主程序、安装器、源码提交与 Actions run 哈希相互绑定。完整的反汇编片段与核验报告保存在产物目录下的 `verification/windows-native-code-review.md`、`windows-single-instance-disassembly.txt` 与 `windows-native-code-check.json`。静态机器码审查确认单实例控制流已准确编入正式构建，无需为适配旧版日志字符串判据重新打包；Windows 桌面下的双开唤回交互留待实机进一步确认。
