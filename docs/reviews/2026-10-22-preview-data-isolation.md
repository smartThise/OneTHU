# 组件预览示例进入正式搜索 · 2026-10-22


## 用户反馈与根因

有用户反馈自己本学期并未选修高等数学，首页的搜索组件中却搜出了“高等数学A(1)”“第一次小作业”和“第二讲 课件.pdf”，且显示的截止日期恰好是当天往后推两天。核对文案与动态日期规则后确认，这几条内容正是 `state/data.ts` 内置的组件预览示例数据。

定位到的具体链路如下：旧版 `PreviewDataProvider` 会在 `useLayoutEffect` 中调用 `seedPreviewData`，直接向全局共享内存缓存与模块级学习快照写入示例数据，并通过全局布尔开关暂停真实学习数据加载。当用户在组件添加抽屉尚未完全卸载时向白板添加搜索等真实组件，新挂载组件的业务 Hook 在初始化 React 状态时便会直接读到全局缓存里的示例条目；此后即便预览抽屉卸载并还原了共享缓存，已挂载组件内部持有的初始状态依然残留着示例数据。此外，多个预览实例并发挂载与卸载时的还原顺序还会把期间刚拉取完的真实刷新结果覆盖回去。

## 修复

- 引入基于 React Context 的独立数据作用域：`createPreviewDataset` 仅在内存中纯函数式生成示例数据集，每棵预览组件树各自持有一份独立的只读 `Map`。
- 彻底移除 `PreviewDataProvider` 中的全局缓存写入、全局加载开关及卸载还原副作用；切换界面语言时仅局部重建预览子树的数据集。
- 15 个关联业务数据 Hook 升级为优先读取当前所处 Context 作用域内的缓存：在预览子树内触发 reload 既不会请求学校接口，也不会改动真实缓存，预览中的学习类卡片同样不再订阅全局真实学习广播。
- React 组件树之外的后台学习、校园与校历快照逻辑继续直接读写持久化真实存储，后台定时同步与刷新完全独立于组件预览。
- 早期自动化浏览器脚本使用的全局 fixture 注入入口严格限定为仅 `DEV` 开发模式可用（生产构建调用直接拦截报错），产品自身的组件预览已完全脱离该机制；既有的二级课表浏览器回归脚本仍可在测试环境中正常验证真实刷新链路。
- 发布构建工作流已同步纳入预览数据隔离边界测试。
