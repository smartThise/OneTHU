# 作业截止时间的数据源检查


> 归档说明：本文记录当时的代码审查与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

日期：2026-10-20。本轮在排查日程页显示问题时一并核查了底层真实取数链路，全程在本地离线分析与测试，未请求学校线上接口，也未读取真实账号或用户作业内容。

## 排查结论与修复

应用的 Learn 后台刷新仅检查登录就绪状态，在完整、实用、极简三种界面模式下均会自动运行；日程页（`SchedulePage`）同样无条件挂载了 Learn 与外部作业数据源钩子。此前的浏览器矩阵测试直接向缓存注入示例数据并开启预览模式，绕过了真实网络请求环节，因此本轮专门针对 HTTP 异常分支做了深入核查。

排查定位到数据层存在一处独立的容错隐患：`LearnClient.getAllHomework` 在逐门课程拉取“未交”“已交未批”“已批”三类作业列表时，内部逐项捕获并吞掉了请求异常、直接返回空数组。一旦遇到 `429` 限流、网络超时或单门课接口报错，不完整的返回结果便会被上游视作正常全量数据，进而覆盖本地原有的作业截止时间快照。现已将其改为“任一子请求失败即整包报错中止”，确保日程页、到期提醒与系统日历始终只消费完整的作业快照。

与此同时，`state/data.ts` 在刷新失败时会妥善保留当前学期的上一份完整快照，向界面报告错误并开放手动重试。前后台刷新任务均记录目标学期 key 与单调递增版本号，无论是切换学期、`A→B→A` 往返切回，还是提交作业触发同学期缓存失效，过期的在途旧请求都会被精准拦截；后台并发刷新也按版本号安全合并，同时保持历史学期常驻标签页原有的独立加载体验。

至于用户最初反馈的“完整模式下可见、极简模式下看不到作业截止项”现象，主线结合仅含条目计数的运行诊断确认：当时底层作业数据已正常载入，根因在于极简模式下容器可用高度计算为 `0` 且列表底部滚动受阻。该界面高度与滚动缺陷由日程页与外壳布局专项修复，本文的数据源加固则为其提供可靠的底层快照保障。

- `node tools/learn-snapshot-test.mjs`：12 个隔离用例全部通过，直接运行真实的 `LearnClient` 与 `state/data.ts`（仅将底层 HTTP 与持久层替换为可控模拟桩），覆盖全量失败、单门课子请求失败、合法零作业课程、作业提交状态更新、模拟 HTTP `429` 限流下旧快照保护、前后台跨学期竞态拦截以及同学期失效重取。
- `node --import ./tools/ts-resolve-register.mjs tools/learn-session-recover-test.mjs`：既有的会话有效性自检、掉线恢复与并发去重回归全部通过。
- `node tools/learn-silent-relogin-test.mjs`：既有的静默重登恢复链路回归通过。
- `@onethu/desktop` 与 `@onethu/core` 的 TypeScript 类型检查及改动文件的 `git diff --check` 均顺利通过。

补充记录：目前 Learn 全量数据包仍需等课程通知与课件列表一并拉取完毕后才对外发布，若某门课课件列表响应较慢，首次打开时截止时间的展现也会相应延后。为确保系统日历每次拿到的都是完整一致的同步快照，本轮继续保持整包原子发布策略；后续若收集到真实弱网环境下的分项耗时指标，可再评估首屏渐进展示方案。
