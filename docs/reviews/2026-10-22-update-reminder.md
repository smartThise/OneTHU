# 0.11.2 更新提醒与语言切换验收


日期：2026-10-22。目标版本：0.11.2。本文记录新版更新提醒与动态语言切换的源码实现及隔离浏览器验收过程；三端安装包构建、渠道上传与真机安装核验另见同日发布执行记录。

## 行为与接入

极简、实用、完整三种模式现在共用挂载于 `Layout.Shell` 内的 `UpdatePromptHost`，以支持直接交互的更新提醒对话框取代原先启动时一闪而过的单次 toast 提示。应用启动约 3 秒后首次读取远端更新清单，检查成功后每隔 6 小时复查一次，网络失败则约 15 分钟后静默重试；应用从后台切回前台或网络恢复连通时，若已到达检查间隔也会自动触发检查。底层继续复用既有的 GitHub / 清华云盘双源更新链路，后台检查阶段仅拉取轻量版本清单与安装包元信息。

检测到新版本时，弹窗提供“前往更新”与延后提醒操作，延后时长支持选择 **1 小时、1 天、7 天**（默认选中 1 天）。所选提醒到期时间保存在本机 `onethu.update.snooze.v1` 中并与具体目标版本号绑定，到期前保持静默，若期间发布了更高版本则会立即重新提醒；旧版客户端曾保存的“忽略此版本”记录依然向后兼容。按键盘 Escape 或触发系统导航返回时均执行延后操作，保持当前正在浏览的主页面不受打断。

点击“前往更新”会将当次已拉取到的版本检查结果直接移交给共享的 `SoftwareUpdateSection` 组件：完整模式自动打开“我的 → 设置 → 关于”并聚焦至软件更新卡片，极简模式与实用模式则打开各自的精简设置页并平滑滚动到软件更新区域。进入设置后直接展示方才获取的版本详情，后续下载安装包与拉起系统安装器仍由用户点击确认后执行。

弹窗展示遵循界面避让规则：当屏幕上存在可见的设置页等模态对话框（`role=dialog` / `aria-modal`）、新手导览隐私页、常规导览步骤页或 `.tour-resume` 导览实践返回条时，更新提醒会自动挂起等待，待上述交互结束后再行弹出；本轮浏览器用例重点覆盖了设置对话框与导览流程的避让衔接。

## 验收过程中修复的问题

首轮浏览器自动化测试发现，实用模式手机端点击“前往更新”打开设置后，滚动条仍停留在设置页顶部。定位原因是 `SoftwareUpdateSection` 在首次 `useEffect` 执行时便消费清空了交接结果并设置滚动定时器，而在开发模式 React `StrictMode` 的二次挂载检查中，首次 effect 的清理函数取消了尚未触发的定时器，第二次执行 effect 时交接槽位已被清空。现改为通过组件内部 `ref` 妥善接住交接结果，使重新执行的 effect 依然能够完成平滑滚动定位，随后三种模式在手机与桌面端的跳转落点全部通过验证。

另一处修复针对检查过程中的动态切语言：原先更新源名称与“已检查……”状态提示在网络请求返回瞬间便拼成了固定语种的字符串，导致随后切换界面语言时仍残留旧语种文案。现已改为在状态中保存结构化的 `source ID`、文案描述符与切源尝试列表 `attempts`，在组件渲染阶段按实时界面语言动态解析翻译；由学校或发布渠道返回的原始错误详情与版本发布说明（Release Notes）则忠实保留原文。

此外，已从 `SimpleExperience` 中移除了极简与实用模式首页顶部两句冗余的解释性口号，并将首页日期格式化接入实时 `uiLocale`，切换至英文界面时自然展示英文月份、星期与日期语序。

## 浏览器验收方法

`tools/update-reminder-browser-test.mjs` 在独立 Chromium 上下文中运行，复用公开演示环境的虚构课程、作业与账户夹具。远端更新清单在浏览器网络路由层直接拦截模拟：默认让 GitHub `latest.json` 返回虚构的新版本 `0.11.3`，验证“更高版本突破旧版延后锁”时动态切换为返回 `0.11.4`；四个平台的安装包链接统一指向不可达的 `example.invalid`，其余外部 HTTP 与全部 WebSocket 连接均予以阻断。

版本号比较、`checkForUpdate`、延后状态管理、React / OneGUI 对话框、设置面板与页面导航栈全部直接运行真实生产代码。1 小时、1 天与 7 天的延后到期唤醒通过 Playwright Clock API 快进虚拟计时器完成验证，不影响宿主机系统时钟；通过页面 reload 与新建全新浏览器上下文读取同一份本地存储记录，分别验证了页面重载与冷启动重启后的状态持久化。

导览避让用例专门选取了“白板 → 首页”实践路径，以便独立验证 `.tour-resume` 实践返回条的避让恢复（搜索实践在结束体验时按既有设计会保留已打开的搜索面板，因此提醒弹窗也会继续等待搜索面板关闭后再弹出）；设置页退场则通过点击真实的关闭按钮触发验证。测试辅助加载器对当前页面文档首次解析的 Vite 模块做了实例缓存，防止开发态 HMR 查询参数变化产生双份状态单例。

## 测试环境与实机待测项

本轮浏览器验收全程在离线隔离环境中完成：更新清单由网络层拦截返回虚构版本，校园数据采用公开演示夹具，未连接真实校园账户、未读写个人云盘，也未下载或执行真实安装包。自动化用例完整验证了前端检查调度、延后期限持久化、三种模式的设置定位以及实时语言切换；线上 GitHub 与清华云盘的清单可达性、安装包签名完整性与哈希比对则在正式发版环节专项核验。

Android 返回键测试直接调用了原生返回监听器挂载的同一套前端 JS `back()` 导航链路，确认更新弹窗可优先响应返回操作并保持底层首页稳定展示；桌面 Chromium 移动视口模拟已验证多尺寸响应式布局，Android 实体 Activity、各品牌系统 WebView、边缘侧滑返回手势及系统安装器的真机交互体验将在装机升级后进一步确认。
