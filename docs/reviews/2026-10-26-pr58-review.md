## 1. [P1] 按 MIME 补后缀绕过附件登录页检查

位置：[apps/desktop/src-tauri/src/lib.rs:1102](https://github.com/smartThise/OneTHU/blob/08b1caa4ebede7e12f810b48d76e2bd6f7d7bb72/apps/desktop/src-tauri/src/lib.rs#L1102)。

`ensure_extension` 在登录页检查之前，先根据响应 `Content-Type` 给文件名补齐后缀。当附件名缺少扩展名、且会话过期导致学校返回 HTTP 200 的 HTML 登录页时，`text/html` 会把原本的 `下载` 改写为 `下载.html`，致使随后的 `name_is_html` 变为 `true`，跳过整段 HTML／重定向校验，最终把登录页当作正常附件成功落盘。

提取并编译运行 PR 中的实际 Rust helper 复现，输出为 `filename=下载.html`、`htmlValidationRuns=false`，确认原有的过期拦截分支发生了回归。修复时应先依据响应原始显式文件名、跳转地址和认证页面特征完成登录页校验，通过后再按 MIME 补齐推断后缀，仅对原始文件名本身即以 `.html` 结尾的网页附件放行。

## 2. [P2] 折射功能使用被伪装的 UA 判断真实内核

位置：[packages/gui/src/pipeline/refraction.ts:65](https://github.com/smartThise/OneTHU/blob/08b1caa4ebede7e12f810b48d76e2bd6f7d7bb72/packages/gui/src/pipeline/refraction.ts#L65)。

影响范围说明：此项仅涉及新增的 SVG 边缘折射增强管线；PR 对常规 CSS 背景模糊、透明材质、阅读面与暗色对比度的改进独立于该判断，在 Windows 客户端中可如作者实测那样正常改善视觉表现。

SVG 折射管线的能力判断要求 `navigator.userAgent` 中的 Chromium 版本号至少为 96，而桌面端 `tauri.conf.json:23` 为兼容学校统一认证固定配置了 `Chrome/79.0.3945.88`。因此即便 Windows WebView2 与 Android WebView 的实际内核支持 SVG backdrop filter，探测结果仍会返回 `false`，使生产环境客户端落入降级分支（macOS WebKit 走降级路径则符合预期设计）。

纯函数复现表明，传入配置中的固定 UA 并将两项 SVG/CSS 能力探测均设为 `true` 时，返回值依然为 `false`。建议在保持既有学校请求 UA 不变的前提下，改用真实运行时能力、Client Hints 或宿主侧内核信息识别渲染引擎。

仓库中的 `home-shell-appearance-browser-test.mjs` 运行于标准 Chromium 并附加 Windows platform hint，`glass-optics-test.mjs` 的现代分支与旧内核分支则分别使用浏览器默认 UA 和 `Chrome/90` UA，尚未覆盖主窗口固定 `Chrome/79` UA 的组合，补充该组合用例即可覆盖生产环境配置。

## 3. [P2] 折射节点移除后不释放，24 个候选名额永久耗尽

位置：[packages/gui/src/pipeline/refraction.ts:356](https://github.com/smartThise/OneTHU/blob/08b1caa4ebede7e12f810b48d76e2bd6f7d7bb72/packages/gui/src/pipeline/refraction.ts#L356)。

`MutationObserver` 仅监听 `addedNodes`，未处理移除节点；`update()` 也只过滤 `isConnected`，未从 `lenses` 集合删除断开记录或调用已定义的 `forget()`。由于 `discover()` 在 `lenses.size >= 24` 时直接拒绝新候选，反复开关临时面板或关闭标签页会逐步占满全部 24 个配额，并残留已卸载 DOM、观察器和滤镜引用。

在隔离的无头 Chrome 中加载 PR 实际模块，依次挂载并移除 24 个 `.lens` 节点：前 24 个均成功挂载折射，第 25 个即便位于视口内且材质与尺寸完全合规，也无法再获得折射效果。建议在扫描新节点前先清理已断开连接的 lens，同步释放对应的观察器与 filter。

## 4. [P2] 新增日夜壁纸设置经过云端存档恢复会丢失

位置：[apps/desktop/src/state/wallpArchive.ts:97](https://github.com/smartThise/OneTHU/blob/08b1caa4ebede7e12f810b48d76e2bd6f7d7bb72/apps/desktop/src/state/wallpArchive.ts#L97)。

PR 将运行态 `WallpaperDoc` 升至 v3 并新增 `day`、`night` 字段，但存档导出格式未写入这两个字段，导入逻辑又显式将两者置为 `null`。由于 `wallpsync.ts` 正是通过这对导出／导入函数完成云端上传与恢复，用户在同步恢复或换机后日夜壁纸配置会被清空。

实际调用导出→导入往返验证：`day=builtin:aurora, night=builtin:dusk` 导入后双双变为 `null`。建议在存档结构中保存并校验这两个引用，将其关联媒体计入资源去重与体积预算，同时兼容不含这两个字段的旧版存档。
