## 已实现

### 1. 客户端归因

- Mac 端 `lsof` 精确 TCP 客户端记录新增返回 PID / UID 详情的描述接口，同时保留原有返回布尔值的授权接口以保持兼容。
- 延续 `-b -w -nP` 参数组合，避免在 WebDAV 等远端挂载卷上触发阻塞式文件系统查询。
- 微信进程路径严格限定在本机 `/Applications/WeChat.app/Contents/` 下，同时核验 Apple 代码签名链、开发者团队 `5A4RE8SF68` 与腾讯微信 Bundle ID，避免依赖易伪造的进程名或 `User-Agent`。
- 实机核验发现 App Store 版微信采用 Apple 应用签名叶证书，其证书 `subject OU` 与开发者团队 ID 不同；因此改为先校验证书的 Apple 签名链，再读取可执行文件的代码签名团队与标识，本机微信主进程及 network helper 均通过验证。
- Windows 端新增当前用户 SID、精确 TCP 客户端 PID、可执行文件运行路径及有效腾讯 Authenticode 签名核验；PowerShell 采用固定程序路径与编码参数调用，限制最多 4 个并发归因查询并配合有界队列缓冲，已通过 16 并发请求模拟测试。

- 通过代码签名核验的微信连接进入受限分流通道：共享身份通路仅接受已登记小程序与已登记 ITS 服务的只读表单入口，并严格校验小程序 `Referer` 或官方业务来源。

### 3. GUI 与后台共享身份

实测表明，即便 GUI 内清小搭已完成登录并将 Cookie 回传后台，直接请求这两个 ITS 服务入口仍会收到 `authenticated=false` 的密码表单，说明仅同步共享 Cookie 尚不足以让小程序直接免密进入业务。为此，最终方案改为由 GUI 按需获取并转交学校官方签发的单次未兑换服务票据，精准衔接各服务的独立认证流程。

- SDK 新增纯内存态的受限续接队列，仅在内存与私有本机 IPC 中传递服务枚举、随机请求 ID 及学校签发的单次服务票据，全程零传递密码、验证码、长期令牌或身份 Cookie；界面状态与诊断日志仅记录服务枚举。
- GUI 在原窗口内直接调用既有的清小搭 / 来访客户端与“记住密码”会话逻辑完成续接，将学校真实签发的未兑换短时服务票据转交给受限后台请求，无需开启 OH 或用户侧 CLI 总开关。
- 队列具备完整的账号与 `epoch` 校验、单次领取消费、超时回收、冷却限流及退出即刻撤销机制，每笔完成回执严格对应其所属的单次请求。
- 网关设置页新增“续接微信校园登录”按钮，用于提前就绪学校统一身份认证会话（腾讯微信客户端账号本身仍由用户在微信内正常登录）。
- 学校确认表单移除了新设备登记字段，统一沿用既有安装指纹与已建立的设备信任因子；清小搭登录日志同步脱敏，移除了姓名、证件号及带票据参数的 URL。
