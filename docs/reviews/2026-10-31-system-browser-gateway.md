# 系统浏览器代理与多平台代理共存验收

开发分支：`web`。本轮保留当前 Mac dev 窗口及既有账号，仅更新共享后台。网络设置变更由用户的系统代理接入请求授权。未提交作业、预约或修改学校业务记录。

## 修复原因与实现

1. 信息门户能显示页面框架，但栏目为空：页面读取的防伪 Cookie 未投影给浏览器。适配器现在为 Info 和 Learn 分别按精确域名、路径和明确的非 HttpOnly 属性投影 `XSRF-TOKEN`，学校认证 Cookie 继续留在共享账号运行时。
2. 独立校园浏览器点击课程后新标签页停住：新目标处于暂停状态时，初始化顺序等待了需要恢复运行才能完成的 `Page.enable`。调整为先建立代理认证，再恢复目标，最后等待页面事件准备。用真实可见链接点击验证，不再以直接访问提取的 URL 代替。
3. 常用浏览器系统接入：新增 macOS 同用户 TCP 连接鉴权监听。操作系统 PAC 将校园来源导入这个监听，无需逐个浏览器输入代理密码。每条请求仍校验来源、Host、SNI 和账号 epoch。
4. 与其他代理共存：按每个网络服务保留 HTTP、HTTPS、SOCKS 和绕过规则，生成独立 PAC。未知 PAC、WPAD、认证代理及无法表达的规则在变更前拒绝。外部软件后续修改设置会报告冲突，不反复覆盖。
5. 统一认证浏览器入口：原配置把 `id` / `oauth` 导入代理后又拒绝账号接口，导致用户无法访问。现将两者从浏览器 PAC 接管名单和 CA 来源名单移除，按原代理或直连规则访问；共享代理的自定义名单也不能绕过这一边界。临时恢复原代理后，已在用户普通 Chrome 验证账号设置及其既有登录态正常。
6. 全新浏览器的 Learn 空白：进一步复验发现 WebVPN Cookie 镜像中的防伪值 A 与当前课程 HTML 已公开的值 B 不同。相同只读学期接口使用 A 返回 403，使用 B 返回 200 JSON。现在只从已知 Learn 课程文档的有界前缀识别同源业务 URL 中唯一的公开 nonce，并按账号 epoch 暂存供浏览器使用；静态资源响应不会再把旧 A 写回浏览器。认证 Cookie、密码和请求内容保持原处理，不用重放业务请求掩盖失败。

### 恢复流程中发现的问题

`networksetup` 无法把 PAC URL 设置为空。首个修补尝试逐服务使用 SystemConfiguration / JXA 清除地址，导致用户连续收到系统授权提示。这是本轮引入的问题；已停止相关进程并完整移除该实现。

最终实现只关闭原本未启用的 PAC，保留无效力的地址字段，恢复原手动代理。返回值通过 `retainedInactivePacUrls` 说明这个差异。不会为了清理停用字段另行请求管理员授权。恢复途中遇到 OS 权限拒绝会停止后续变更，保留 `restorePending` 供显式恢复；状态界面不会再把部分恢复显示为正常运行。

## 平台设计与边界

macOS 的已有手动代理组合在本轮实现。已有任意 PAC 不直接拼接执行，避免改变其逻辑和认证语义；TUN 的路由、DNS 和进程排除仍需与对应代理软件实测。系统代理监测到其他软件重写配置后，交由用户选择恢复或重新接入。

Windows 已有 CurrentUser 证书与系统 PAC 适配器，尚未完成同用户免代理密码入口及现有手动代理组合。WinINet、WinHTTP 和自行设置代理的客户端必须分别验收。微软文档说明 WinHTTP 客户端需正确配置或解析代理，不能以修改浏览器配置代替所有客户端覆盖：[WinHTTP AutoProxy Support](https://learn.microsoft.com/en-us/windows/win32/winhttp/winhttp-autoproxy-support)。

Android 保持 App 内共享会话。本轮没有实现系统 VPN 接入。后续方案需要处理 VPN 授权、常驻通知、前台服务、`protect()` 避免代理套回自身，以及与现有 VPN 的冲突。Android 同一用户或工作资料仅能有一个活跃 VPN；不能承诺与另一个 VpnService 同时独立运行：[Android VPN](https://developer.android.com/develop/connectivity/vpn)。

用户安装 CA 并不使所有 Android App 接受它。现代 App 的信任配置、证书固定和网络栈会影响兼容性，微信小程序需单独验证：[Network Security Configuration](https://developer.android.com/privacy-and-security/security-config)。

本轮不包含 LAN 扩散、WebSocket、HTTP/2/3 和任意应用流量接管。PAC 下载失败、后台崩溃、休眠恢复的完整自动恢复仍需单独实现和验收；已加载 PAC 对校园入口没有 DIRECT 后备，不等于整个操作系统具备网络隔离保证。
