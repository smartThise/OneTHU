# i18n 工程、学校英文兼容与安全修补交付


> 归档说明：本文记录当时的代码审查与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

工作分支 `exp`，日期 2026-10-20。本轮直接基于最新主线业务代码推进国际化底座接入与安全加固，完整保留了近期迭代的新版页面架构，并同步完成了翻译交接清单与多项安全审查收口。源文总键数、候选译文数与分批明细以 [交付清单](../i18n/catalog.json) 为准。

最终生成的交付清单共含 **7,296 条源文、拆分为 92 个批次**；其中英文词典已有 **564 条待复核候选译文，另有 6,732 条待填入**。实测执行 `--locale en-US --complete` 发布门禁检查时，工具按预期准确拦截了仍含空值的未完稿词典。

## 翻译交接职责与运行时底座

后续翻译批次只需填入 `apps/desktop/src/i18n/locales/en-US.ts` 中对应批次的字符串值，配套规范与首批发包见 [翻译指南](../i18n/TRANSLATOR_GUIDE.md)、[术语表](../i18n/GLOSSARY.md) 与 [批次 001](../i18n/batches/001.json)。自动化批次校验器会严格核对工程基线，一旦发现占位符失配、缺键、混入可执行逻辑、源文版本漂移、跨批次越界改动或触碰业务与测试文件，均会直接报错拦截。

前端运行时现已打通语言偏好持久化、跨窗口实时同步、完整/极简/实用三模式语言切换入口、`document.lang` 同步、OneGUI 组件库默认中英双语、全局确认框/表单/Toast 描述符、稳定设置项路由定位以及基于语言的展示缓存重算。全仓 29 个业务及插件表单入口的固定标题与字段文案已升级为消息描述符，处于打开状态的表单在切换语言时可即时刷新标签，同时完整保留字段默认值、用户已输入草稿与选项内部标识。语言切换全程原地更新组件树；`t()` 函数在调用时动态读取当前语言，避免为普通事件回调附加多余的 `locale` 依赖而意外重发网络请求。

中英文词典始终保持完全一致的键集合：英文留空项表示待译，运行时自动回退显示中文；已有的 564 条候选译文也将在对应批次中一并人工审校。目前国际化工程基础设施已率先就绪，英文全量覆盖与译文语言润色将按批次继续推进。

针对批量提取过程中识别出的业务协议边界，本轮逐一做了隔离加固：THOS 待办中文状态比对、洗衣机设备稳定标识、跨校课程公告检索词、系统日历底层名称以及系统默认首页的存储标识均保持固定原值；导航菜单、全局搜索与页面标签的可见标题则在渲染期动态解析；网络学堂课程行的 Atom 引用统一绑定学校原始课程名，防止切换语言后在暂存箱内生成重复条目。

Android 桌面小组件也已接入同一套词典体系：每次推送快照时一并附带当前语言码与 62 条专用消息模板，使原生后台定时重绘继续沿用快照所属语言；用户在应用内切换语言时会主动刷新快照，并通过世代号拦截在途旧异步采集覆盖新语言。此外还一并修复了插件小组件槽位读写结构不一致、以及读取桌面实例列表失败时误删已存配置的问题，详见 [小组件验收](2026-10-20-native-widget-i18n.md)。

## 学校英文页面兼容

- 网络学堂本身提供校方语言切换与课程 `englishName` 字段：应用处于中文界面时展示原课程名，处于英文等非中文界面时优先展示学校提供的 `englishName`（缺失时平滑回退原名），本地搜索同时匹配中英文课程名。
- 用户提供的第二份参考附件对应 Info 英文门户首页（英文选课系统内页样本尚待选课季补充）。解析器现已补齐中英文双语表头识别、分页提取、会话状态判定与业务报错提取：遇到未知页面结构时直接报错提示，避免误判为空课表；遇到明确选课失败响应时即时透传错误，防止被本地旧的已选记录掩盖。
- 作业提交仅在收到校方接口明确的机器成功状态字段时才判定成功；退课与志愿调整操作须经服务端回读并核对准确课程标识后才确认生效。客户端全程尊重用户在校方网页上的原有语言偏好，不会私自改写远端设置。
- 鉴于原始附件含有个人敏感信息，仓库内仅保留脱敏后的匿名结构样本用于离线回归，期间未登录真实学校账号，也未执行真实作业提交或选退课操作；线上全流程表现留待选课开放窗口期进一步验证。

详细排查与测试记录见 [学校英文解析与身份报告](2026-10-20-school-language-parser.md)。

总控集成阶段依次跑通了 `pnpm test:i18n`、`pnpm guard`、`pnpm guard:onegui`、`pnpm typecheck`、`pnpm test`、`pnpm --filter @onethu/desktop build` 与 `git diff --check`。词典检查器同时覆盖了非法语言码拦截，开发态 Vite 插件与生产打包均会拒绝含可执行语句的词典文件；生产构建原有的大体积 chunk 提示亦如实保留。

此外，在模拟真实翻译交接流程时发现并修复了批次检查器对带引号属性名 `"messages"` 的解析兼容问题（此前 AST 比对仅识别无引号的 `messages` 标识符，导致自动生成词典中的合规译文改动被误判拦截）。配套新增的端到端回归在独立临时 Git 仓库中拷入真实词典与首批任务单并调用生产 CLI：验证仅修改本批词条时顺利放行，跨批改值或篡改对象结构时依然准确拦截，整套 `pnpm test:i18n` 全绿通过。

## 后续推进与发布前验收项

1. **多语言覆盖与真机排版**：英文词典接下来进入按批翻译阶段；全量长译文合入后的多端排版、更多目标语种接入，以及实体手机与 Windows WebView2 宿主上的触控与字体表现将在发版前集中验收。
2. **多账号与校内线上联调**：组织协同接口与入口已就绪，待补充第二个测试账号后开展跨账号权限实测；学校英文选课系统内页、真实作业提交及线上 SSO 登录同样留待真实校园网窗口期核验。
3. **上游依赖通告持续跟踪**：`pnpm audit --prod` 中保留的 Quill（低危）与 `sprintf-js`（中危）两项上游通告均已通过编辑器格式白名单、DOMPurify 清洗及前端打包树裁剪隔离了运行期触发路径，审计记录保持原样以便后续跟进上游版本升级。
4. **本地凭据加密与插件运行模型**：本轮通过私有文件权限（`0600`）与日志脱敏大幅收紧了本地明文暴露面，后续可进一步结合操作系统钥匙串实现凭据落盘加密；原生插件继续遵循用户显式安装授权的本机进程模型，用户设备上的历史调试日志则交由用户按需清理。
5. **更新包签名与覆盖安装实测**：客户端自更新当前依托 HTTPS 传输加密与安装包 SHA-256 校验，后续可规划引入独立的发行者代码签名校验，并在发布流水线中补充跨版本覆盖安装、签名迁移与异常中断恢复实测。
6. **持续工程演进**：本轮安全加固聚焦上述已梳理的核心数据流与失败恢复分支；前端构建保留的大 chunk 提示后续可结合路由级按需加载逐步拆分。
7. **原生客户端重打包**：Rust 与 Kotlin 层面的各项安全与多语言修复目前已完成源码合入与编译测试，待下一次构建并安装桌面端与 Android 原生安装包后即可在终端设备上正式生效。

本轮工作全程在本地离线收口，未执行版本发布或远端分支推送，也未读取真实用户凭据或修改线上校园账号与云端数据。
