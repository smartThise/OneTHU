# PR 57 白板部分审查与模板修复


> 归档说明：本文记录当时的代码审查与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

审查对象：PR 57 的首个提交 `9426f7fc382c225c6fbeea0859b0fe1bf569f60c`，对照本地 `exp` 分支基线 `f3ba4dd6`（PR 后续的国际化提交由另一份专项报告独立审阅）。本轮有选择地采纳了“恢复默认首页”修复并独立重构了白板预设模板尺寸，未整包合入原 PR，也未引入强制默认吸附。

## 审查结论与取舍

- **采纳并强化“恢复默认首页”修复**：让设置页的恢复默认操作真正重建首页白板组件。
- **保持自由无感拖拽**：暂不引入原 PR 中“默认全局开启、仅靠按住 `Alt` 临时关闭”的边缘吸附机制，同时继续沿用清爽的 7 组件默认首页，不将四列高密度排布设为新用户初始首页。
- **独立修正三套预设模板的尺寸失真**：保留初始默认首页布局，将其余三套预设模板统一对齐至 `1104px` 画布基准，改用舒展的宽幅卡片与自然纵向滚动。
- **保护用户存量自定义排版**：用户已保存的自定义白板与新建的 OnePage 均保持原样；预设模板仅在用户主动点击套用时替换当前画布，“恢复默认”也严格限定作用于系统首页。

## 原 PR 改动拆解

在数据结构层面，原 PR 的四列排布仅体现在新建默认首页的初始坐标预设上，底层画布依旧采用自由像素坐标存储：其 `boardCore.ts:339–359` 将初始默认组件从 7 个扩充到 13 个（按四列、每列 `264px` 摆放），而 `migrateHomeCanvas` 的版本号检查依然保留已有 `v2` 存档原封不动。

但在交互手感上，原 PR 的 `FreeBoard.tsx:760–795` 在拖拽移动与边缘缩放的每一帧都会默认执行 `snapMove` / `snapResize`，唯有按住键盘 `ev.altKey` 时才跳过吸附。界面上既无显式开关也无操作提示，触屏设备与手写笔更无法借助 `Alt` 键临时解除。尽管其吸附阈值按 `8 / displayScale` 做了屏幕像素换算，但默认强行干预落点与当前白板主打的自由摆放体验相冲突。

此外，原 PR 在收集对齐候选边时遍历了画布上的全部组件，未对垂直轴距离或当前视口可见范围做裁剪（`boardSnap.ts:80–105`）。单独提取该提交的纯函数实测可见：位于 `(104,20)` 的卡片会被远在屏幕下方 `y=5000` 处的离屏卡片横向吸往 `x=100`，并在画布上拉出一条跨越 `5080px` 的对齐辅助线。日后若规划推出可选的辅助对齐开关，需先加上视口与邻域距离过滤。

## 定位到的具体缺陷

### P2：西侧/北侧缩放在触及最小尺寸上限时推走了对侧边

问题位置：原 PR `apps/desktop/src/state/boardSnap.ts:133–150`。

传入矩形 `(x=100,y=100,w=120,h=64)` 与最小尺寸限制 `minW=120,minH=64` 时：

- 当西边（左边）向右吸附至 `x=105` 后，宽度被下限夹回 `120`，导致原本应当纹丝不动的东边（右边）从 `220` 被推到了 `225`。
- 当北边（上边）向下吸附至 `y=105` 后，高度被下限夹回 `64`，导致原本应当固定的南边（底边）从 `164` 被推到了 `169`。

这违背了单边缩放时“仅移动当前拖拽边、保持对侧边锚定不动”的几何直觉。正确做法是将西/北向候选吸附坐标预先限制在 `right-minW` 与 `bottom-minH` 以内，超出最小尺寸限制的候选线直接放弃吸附。该缺陷已通过从 Git 历史读取该提交纯函数直接运行复现（复现输出归档于 `/tmp/onethu-pr57-board-snap-repro.json`，全程未改动当前工作区源码）。

### 保护主线已有的暂存箱手势接管锁

原 PR 的 `FreeBoard.tsx:802–819` 在 `pointerup` 与 `pointercancel` 中共用了同一套落盘分支——只要 `liveRef` 非空便写入白板状态，且 `onMove` 也只读取瞬时的 `gestureOwner()`。而当前 `exp` 主线已经将手势接管锁贯穿整个按压生命周期：一旦暂存箱中途接管拖拽，便立即清空白板侧的 `live` 预览态，确保被收入暂存箱的原卡片留在原位不动。因此必须保留主线现行的 `FreeBoard.tsx` 手势状态机，避免回退到早先“暂存箱已亮绿命中、松手后原白板卡片却跟着挪窝”的冲突状态；日后若补充对齐参考线，同样需在接管或取消时一并清空。

## 既有三套预设模板拥挤的根因

排查基线代码可见，`boardTemplates.ts:33–58` 中的“今日”“学习”“极简”三套模板仍沿用早期的四格栅格坐标，`boardCore.ts:169–176` 将其换算成了主卡仅 `286px` 宽、侧边栏仅 `90px` 宽的局促尺寸；而 `FreeBoard.tsx:834–837` 在套用模板时又统一调用 `rectFromCell` 转换并强行打上 `manual:true` 标记。由于桌面端 100% 缩放下的画布参考宽度至少为 `1104px`，即便在宽屏 Mac 上打开，整套模板也只缩在画布最左侧窄窄一列，拉大窗口也无法舒展原本写死的过小像素宽度。

原 PR 仅替换了初始默认首页，并未触及这条预设模板套用链路；且其新增四列预设中的通知与作业卡片尺寸仅为 `264×116px`，在展示长列表标题时依然十分局促。

## 本轮落地改造

- **`boardTemplates.ts`**：三套预设模板直接声明宽敞的原生像素 `rect`（同步派生的 `cell` 字段仅作插件与 OH 历史协议兼容）：其中“今日”与“学习”模板的主列卡片宽 `540px`、列表高 `392–480px`；“极简”模板采用 `1104px` 通栏抬头搭配 `740px` 课表卡与 `340px` 校园卡余额；卡片间距统一不低于 `24px`，且每次套用均深拷贝生成独立数据实例。
- **`FreeBoard.tsx`**：套用模板时直接采用模板声明的原生 `rect` 与尺寸归属标记；未锁定固定高度的卡片继续支持按内容自适应伸展，用户随后手动拖拽缩放时再无缝交由既有的 `withRect` 接管。仅在用户显式点击套用模板时将当前画布视图复位至 `100%` 倍率与 `1104px` 参考宽度，日常自由拖拽与缩放手感保持原样。
- **`board.ts` / `Settings.tsx`**：“恢复默认”操作现会完整重建系统首页横竖两套朝向的默认组件，同步清除旧版布局偏好并拦截在途的异步旧自由板回写，同时完整保留用户自建的全部 OnePage、当前激活页签与排序设置。重置后首页各视图缩放倍率同步归位至 `100%`，并通过专用同步事件通知已挂载的画布刷新参考宽度（常规编辑保存不会误触发该复位事件）。

本轮全程未引入强制吸附，未改动任何存量用户卡片坐标，也未触碰首页历史版本迁移与原有的 7 组件初始布局。
