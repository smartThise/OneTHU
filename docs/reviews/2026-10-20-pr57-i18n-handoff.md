## 2. 批量翻译前需先行解决的工程问题

以下 E1–E5 按建议的实施先后顺序排列（均针对 PR 57 副本定位，主线承接时可在批次 0 集中解决）：

### E1：顶层 App 订阅未覆盖同级全局弹窗宿主（已完成最小复现）

代码现状：

- `apps/desktop/src/App.tsx:171` 在 `App` 组件顶层调用了 `useLocale()`，代码注释预期借此驱动整棵组件树重绘。
- 然而在 `apps/desktop/src/main.tsx:120` 中，`App`、`ConfirmHost` 与 `FormModalHost` 是并列挂载的同级兄弟节点。
- `apps/desktop/src/lib/formModal.tsx:36` 仅订阅了表单自身的 pending store，底部按钮在 `:81`、`:87` 直接调用非响应式的 `i18n` 函数。
- `apps/desktop/src/lib/confirm.tsx:133` 的 `PromptHost` 同样仅订阅 prompt pending store，按钮在 `:159`、`:160` 直接调用非响应式的 `i18n` 函数。
- 根据 `apps/desktop/src/i18n/index.ts:116`，只有调用 `useT()` 钩子才会注册语言变更订阅，直接导入调用 `t` / `i18n` 仅做一次性求值。

最小隔离复现：直接加载 PR 真实的 `FormModalHost`、`ConfirmHost` 与 `i18n` 运行时，严格保持 `main.tsx` 的同级节点结构，在真实 React / ReactDOM / Chromium 环境中运行（仅将外层 OneGUI 视觉壳替换为轻量原生 DOM 节点以隔离无关业务，并在探针内存词典中为四个默认未译按钮临时填入 `Cancel/Submit/OK`）：

```text
切换前按钮：取消、提交、取消、确定
调用 setLocale("en-US") 后：
  App 订阅值 = en-US
  t("auto.lib.formModal.1") = Cancel
  已挂载按钮 = 取消、提交、取消、确定
```

探针以退出码 0 跑完，清晰证实：当通过跨窗口同步或程序化调用切换语言时，已处于打开状态的同级弹窗宿主不会随之刷新按钮文案。

**修复方案**：让直接渲染多语言文案的组件及全局公共弹窗宿主显式订阅 `locale`（使用 `useT()` 或订阅 store），并在缓存已格式化展示文本的 `useMemo` 中将 `locale` 列入依赖数组。切忌在顶层 `<App key={locale}>` 上粗暴通过改 `key` 整树卸载重挂——那样会直接丢失用户填到一半的表单草稿、对话输入与滚动位置；用户已落盘的自有内容也应保持原貌。

**模块级静态常量核查**：本轮全仓排查未发现模块顶层在加载期直接调用 `t()` 冻结译文的缺陷；`NAV_REGISTRY` 存储键名并在渲染期动态读取（`state/navigation.ts:155`）、`PAGE_TITLES` 仅存消息键（`state/explorer.ts:229`）的设计均十分稳健。后续落地时只需一并核查三处细节：`TabHost.tsx:256` 中 `useMemo([st.tabs])` 里的首页标签标题、`GlobalOrb.tsx:152` 的 `memo` 包装组件，以及独立原生悬浮窗口的跨窗通知。至于 `useCallback` 内部在点击事件发生时才调用 `t()` 的写法，触发时天然读取最新语言状态，保持原样即可；`DockMsgList` 也会随父级重绘接收新函数属性，可在集成后按实际表现核验。

### E2：缺键与占位符护栏存在漏检盲区（批量补译前必修）

代码现状：`tools/i18n-test.mjs:42` 允许非默认语言存在缺失键，同时 `:84` 的源码调用扫描仅用正则匹配少数固定命名空间与双引号字面量调用；由 `state/navigation.ts:162` 动态拼接的 `navreg.*` 键族、`misc.*` 与 `tour.*` 命名空间以及 `tOr(...)` 辅助函数均落在扫描范围之外。此外，`tools/i18n-test.mjs:7` 文件头与 `i18n/types.ts:5` 注释写有“逐语言全键一致”，与脚本实际放行局部翻译的逻辑存在口径出入。

在独立副本中依次注入以下三处人为故障（每次测完立即还原），实测现有 `tools/i18n-test.mjs` **三次均以退出码 0 放行通过**：

1. 将 `en-US` 中 `shell.addToHome` 的译文从 `"Add {name} to home"` 删改为丢失参数的 `"Add to home"`。
2. 从中英两张词典里同时删掉源码静态引用的 `tour.mcp.aria` 键（界面会直接裸露原始键名）。
3. 从默认中文词典里删掉导航动态引用的 `navreg.learn.name` 键（在回退逻辑掩盖下悄然漏检）。

**修复方案**：

- 改用基于 TypeScript AST 作用域绑定的引用分析，精准追踪从 `i18n` 模块导入的 `t` / `tOr` 及 `useT()` 返回值（业务代码中另有名为 `t("primary")` 的主题色板函数，基于真实 import 绑定解析即可彻底消除重名干扰）。
- 显式枚举所有动态拼接键族（如导航注册表 `id` 派生的 `.name/.note`、页面/标签/分类映射表等），一旦注册表新增条目却漏配默认词条立即报错。
- 严格校验每条非空译文的占位符集合一致性、键值类型、无重复属性键以及调用处的必传参数，并为词典键与参数生成精确的 TypeScript 类型约束。
- 明确区分“开发态增量回退模式”与“语种完稿发布门禁（`--complete`）”：日常开发允许未译词条回退中文，当指定批次或语种进入发布验收时则强制要求 100% 键覆盖与非空校验。
- 补齐非法语言码回退、响应式订阅与本地持久化单测；日后接入第三语种时，直接在真实 Vite 构建产物中验证自动注册流程。

注：现有的 9 组带参数词条目前中英文完全匹配；另外核查发现 `tOr(key, fallback, params)` 在词典未命中直接返回 `fallback` 时跳过了参数插值（`i18n/index.ts:107`，如 `tOr("missing", "Hi {name}", {name:"A"})` 会原样返回 `"Hi {name}"`），虽当前导航调用均传静态纯文本故未触发问题，建议在预修阶段一并补齐 `fallback` 插值支持。

源码中存在多处将一句完整话语拆成碎片键再拼入数字或标点的写法，单纯填写词典无法排出地道英文语序：

| `pages/Schedule.tsx:1085` | 年份数字 + “年”键 + 月份数字 + “月”键 | 仅替换两个单位字仍被锁定在“先年、后月”的中文语序里 |

### E4：日期时间格式化、文档 `lang` 属性与多窗口同步待打通

- `apps/desktop/index.html:2` 固定写死了 `lang="zh-CN"`，而 `setLocale`（`i18n/index.ts:81`）仅更新内存变量、写入 `localStorage` 并通知内存订阅者，尚未同步修改 `document.documentElement.lang`，会导致系统读屏软件在英文界面下仍尝试按中文语音规则朗读。
- `pages/Schedule.tsx:691` 硬编码了 `toLocaleTimeString("zh-CN", ...)`，而 `pages/Settings.tsx:510` 的 `toLocaleString()` 则直接跟随操作系统区域设置，两处均未与用户在应用内选择的 UI 语言联动。
- 当前运行时尚未监听跨窗口的 `storage` 事件或原生广播，独立悬浮小窗各自持有独立内存态；多窗口实时语言联动需在预修阶段一并打通并补齐自动化验证。

**修复方案**：封装统一的公共 `formatDate`、`formatTime`、`formatNumber` 与 `formatRelative` 工具并绑定当前 UI locale；同时严守校园校历日期、教学周推算与作业截止时刻的 `Asia/Shanghai` 时区及计算口径不变——本地化格式化仅作用于最终展示字符串，发往接口的参数与本地存储的日期 key 一律保持固定机器格式。每次切换语言时同步刷新所有窗口的 `document.documentElement.lang`（未来若扩展从右向左书写的 RTL 语种，再按语种元数据配置 `dir` 属性），并补全异常语言码容错、无存储环境降级与重启恢复测试。

### E5：极简/实用模式缺少语言切换入口，导航搜索词库尚待对齐

- 语言切换下拉框目前仅出现在完整模式的 `pages/Settings.tsx:568` 中；极简与实用模式挂载的 `SimpleSettings.tsx:22–44`（经 `SettingsOverlay.tsx:34/:84` 渲染）尚未放置语言选择器，导致首次进入极简模式的用户需先切到完整模式才能更改界面语言。建议将语言选择作为基础通用偏好，在三种模式的设置面板中均提供清爽直达的入口。
- `state/quickAccess.ts:38–39` 中五个 OneShot 快捷入口的默认名称仍为硬编码中文；`PracticalFeatures.tsx:35` 的分类筛选胶囊直接渲染了内部中文分类值 `c`（尽管下方的分组标题已接入翻译函数）。
- 导航菜单标题函数 `navName` 读取 `navreg.*` 键族，而英文词典尚未补入这 70 个键。直接运行副本中的真实导航模块可见：执行 `setLocale("en-US")` 后，`navName("learn")` 依然返回 `"网络学堂"`（即便另一处 `nav.learn` 已译为 `"Courses"`），调用 `matchNavQuery("Courses")` 搜索也会返回空数组。补齐 `navreg.*` 英文译文并将当前语言显示名纳入搜索索引后即可打通英文全局检索。

**修复方案**：围绕稳定的功能 `id` 建立统一的“本地化显示名 + 多语种检索别名”注册表，同时支持用英文名、中文原名、清华校内惯用简称及插件原名检索定位；快捷入口的持久化 `id` 与内部筛选枚举继续保持原值。针对默认名称，只需区分“用户尚未重命名的系统默认态”与“用户手动修改后的自定义名”，对前者在渲染期动态按语言展示即可，切勿遍历改写 `localStorage` 中的用户历史存档。

## 3. 提取安全准则：值得沿用的实践与严格禁翻清单

抽查 PR 57 已提交的翻译替换、`select/option` 键值以及导航、设置、选课模块可见，现有改动较好地保护了底层协议比较逻辑；后续向剩余百余个业务文件推进提取时，请继续严守以下边界准则。

PR 中值得继续沿用的正确做法：
