# 白板组件尺寸档清单（逐个设计排版用）


> 0.11 工程参考：现行组件与设计令牌统一收录在 `packages/gui`，旧有业务变量仅用于向下兼容；主题、壁纸与布局均可按需调整。设计说明见 [OneGUI](design-language.md)（英文版见 [Design system](en/design-language.md)）。

> 生成于 2026-10-11，设计口径由霖在本次会话确认（见 §0）。
> 代码定义位于 `apps/desktop/src/state/widgets.ts` 的 `SIZE_PLANS` 与 `freeSizeWidgetIds()`。
> 本清单列出**需要按不同尺寸专门设计排版**的组件；其余组件维持自由缩放。

---

## 0. 本次确认的口径

1. 除**分割线、标题（文字）、入口按钮、列表**四类特殊组件维持自由缩放外，其余组件均取消自由缩放。
2. 其余组件改为**档位控制**：每个档位对应一套专门排版，尺寸从该组件的档位清单中选取。
3. 档位沿用本仓库基准网格：1 单位 = 手机 1 列。提案涵盖 1×1 / 2×1 / 2×2 / 4×1 / 4×2 / 4×4。
4. 「添加组件」抽屉的展开态改为**横向滑动的档位列表**：滑到对应档位后，点击底部「添加」即可放入该尺寸组件。
5. 长按菜单「改变大小」**复用同一个抽屉**：打开时自动选中当前档位，底部按钮显示「修改大小」，
   确认后直接更新原位置组件的尺寸，四周组件按既有重排算法自动让位。
6. 档位组件固定采用所选档位的网格尺寸，高度保持恒定，随档位切换排版。
7. 已有白板存档无需一次性迁移；尺寸在**渲染**与**写入**两处自动向最近的有效档位吸附。

## 3. 逐档排版的落地方式

样式与结构两种接入钩子均已就绪，具体组件按需选用其一即可。

### 3.1 只改样式：槽位的 `data-widget` 与 `data-size`

每个槽位带 `data-widget="custom:<id>"` 与 `data-size="<w>x<h>"`。示例：

```css
.board-slot[data-widget="custom:mine-gpa"][data-size="1x1"] .mine-stat-label { display: none; }
.board-slot[data-widget="custom:mine-gpa"][data-size="2x2"] .mine-stat-num { font-size: 28px; }
```

### 3.2 需要换结构：渲染器的第二个参数

卡体渲染器签名是 `(props?, size?) => ReactNode`，`size` 即当前档位。示例：

```tsx
[cardRendererKey("mine-gpa")]: (_props, size) => <MineGpaCard size={size} />,
```

抽屉里的档位预览走同一套渲染器与同一个 `data-size`，因此设计出的排版在预览与白板上一致。

## 5. 另外的细节问题

部分卡片（如今日概览、校园卡、GPA 等）自身内容仅占槽位上方约 7/8 高度，底部会露出一截主题默认底色，观感不够协调；另有一些组件缺少独立底板，在抽屉预览界面中只剩悬浮文字，后续需统一补齐自足卡体与高度填充。
