# OneTHU 翻译交接指南


0.11 版本的国际化工程以当前 `dev3` 分支为准，业务源文案与调用位置均由交接工具直接提取生成。本目录已准备好目标词典、上下文清单和分批文件，翻译时只需填写目标词典中的字符串值。

## 文件与工作边界

| 文件 | 用途 | 翻译者是否修改 |
| --- | --- | --- |
| `apps/desktop/src/i18n/locales/zh-CN.ts` | 中文事实源 | 否 |
| `apps/desktop/src/i18n/locales/en-US.ts` | 英文译文，空字符串表示待译 | 仅本批 `messages` 值 |
| `docs/i18n/catalog.json` | 完整源文、当前调用位置、参数及源文版本 | 否 |
| `docs/i18n/batches/001.json` 等 | 每批最多 80 条、目标文件、已有译文和用途 | 否 |
| `docs/i18n/GLOSSARY.md` | 术语和容易误译的动作区别 | 否 |
| `tools/i18n*`、组件、状态、请求和解析代码 | 工程实现与验证 | 否 |

`pending` 表示待翻译；`prefilled-review` 表示已填入来自运行时、OneGUI 或旧版匹配条目的候选译文，仍需结合当前上下文逐条复核润色。所有条目均完成复核并通过批次校验后，该批次方可交付提交。

每个批次的 `sourceHash` 对应整份中文词典快照。中文源文案更新后，校验工具会拦截过期批次，此时由工程负责人重新生成批次文件即可，请保持 hash 与批次清单原样。键名末尾的短摘要仅用于稳定定位条目，翻译时请以中文源文案与上下文为准。

## 开始与验收

开始前由工程负责人提交干净的工程基线并检出工作目录。同一份目标词典建议单线程按批推进：先完成首批翻译并校准语感与术语质量，通过校验并提交后，再将该提交作为下一批的新基线。翻译阶段专注于词典文案本身，提取脚本与业务代码均由工程侧维护。

在开始修改前记录工程基线：

```sh
ONETHU_TRANSLATION_BASE=$(git rev-parse HEAD)
```

仅修改该批允许的英文字符串，随后在仓库根目录执行：

```sh
node tools/i18n-test.mjs \
  --locale en-US \
  --batch docs/i18n/batches/001.json \
  --base "$ONETHU_TRANSLATION_BASE"
```

该命令会自动核验词典语法、重复/缺少/未知键、占位符集合与出现次数、批次源文版本及本批非空状态，并确认改动范围仅限本批允许的字符串值（保持导入导出、键名、词典结构及其他工程文件原样，避免触发整文件格式化）。若校验报错，直接按提示修正对应译文即可。

全量工程检查允许其他批次暂时为空：

```sh
pnpm i18n:check
```

英文准备发布时必须通过全覆盖检查：

```sh
node tools/i18n-test.mjs --locale en-US --complete
```

在英文词典尚未全部填完的阶段，全覆盖检查会如实报告剩余空值；界面运行时虽会自动回退显示中文以保障日常可用，正式发布前仍需补齐全部英文条目并通过 `--complete` 校验。

接入新语言时，由工程负责人预先创建与中文键集一致的纯数据词典文件（如 `fr-FR.ts`），Vite 会自动完成注册并同步到三种界面模式的语言选择器中，运行时、类型定义与注册表均无需改动。除运行内置语言种子的 Node 单元测试外，新增语言还需在真实 Vite 构建与浏览器环境中完成界面验收。

## 文案格式

只使用已经存在的 `{name}` 具名占位符，可以调整顺序，但名称、大小写和出现次数必须一致。

```text
源文：同步失败：{reason}
译文：Sync failed: {reason}

源文：第 {week} 教学周
译文：Week {week}
```

运行时按纯文本模板解析字符串，仅识别 `{name}` 占位符，请勿写入 ICU 语法（如 `{count, plural, ...}`）、HTML/JSX 标签或 Markdown 链接。按钮、链接或强调文本等富文本节点同样通过 `{name}` 槽位由工程代码注入，译文只需根据语序安排槽位位置。示例里的 LaTeX 公式、JSON 片段等花括号内容已作为参数传入，保持原有占位符即可。

遇到结构较复杂的句子时，可结合 `parameters` 与 `locations.context` 查看参数来源；自动生成的 `value`、`value2` 等名称属于稳定参数名，阅读调用表达式理解含义后原样保留即可。无参数的条目保持纯文本，复数条目按工程已拆分好的分支逐条翻译。

`native.widget.*` 对应 Android 桌面小组件的 62 条文案模板，同样直接在目标词典中填写。带有 `.zero/.one/.two/.few/.many/.other` 后缀的条目按目标语言的复数规则分别翻译并保留 `{count}`。应用会将当前语言与模板快照同步给原生小组件供后台刷新使用，Kotlin 代码与中文兜底资源无需手动改动。

按钮文案力求简明有力；提示与确认说明则需完整传达权限要求、数据影响范围（如“仅本机”“尚未同步”“需要负责人权限”）及操作后果，并保留原有段落换行，让用户在执行敏感或不可逆操作前充分知情。

## 保留原文的内容

- 学生与教师姓名、课程、作业、新闻、邮件、文件名、用户创建的组织及自定义标题均属动态业务数据，保持原文。
- 路由与标签页 ID（route/tab/section ID）、学校接口状态码、API 字段、文件路径、权限枚举、CSS 类名、代码片段及系统日历标识符保持原样。
- 学校接口返回的原始报错信息会通过 `{reason}` 参数直接展示，解析器代码无需为此改动。
- OneTHU、OH、OneGUI、OneGO!、OnePage、OneShot、MCP、GitLab、THUBook 等品牌与协议名称保留原名。
- 功能导览中的应用实机截图与系统窗口画面独立于文本词典，后续需要多语言配图时由工程侧在真实界面重新截取。
- 已写入系统的日历事件与通知、IM 自动回复、远端云盘资料库名称等外部数据各自维护独立状态，切换界面语言时保持已生成内容不变。

网络学堂课程在中文界面下展示原课程名，切换其他语言时优先展示学校接口提供的 `englishName`，未提供英文名时回退显示原名，搜索框同时支持中英文检索。课程 ID、收藏记录与暂存对象的标识保持不变。应用仅在本地读取并兼容学校中英文页面结构，保持用户在学校网站上的原有语言设置；翻译其他语种界面时，课程名称同样遵循上述回退规则，避免自行翻译学校课程名。

## 给翻译模型的任务模板

> 在干净的工程基线上翻译 OneTHU，目标语言为 `en-US`，本批清单为 `docs/i18n/batches/001.json`。先阅读本指南、术语表和该批上下文，仅修改 `apps/desktop/src/i18n/locales/en-US.ts` 中本批列出的 `messages` 字符串值，其余文件、键名、导入导出、`label` 与代码格式均保持原样。
>
> 逐条完整翻译并复核已有候选译文，严格保留所有占位符名称与出现次数。按钮文案简明，权限说明与风险提示完整准确；保留用户数据、学校专有内容与品牌原名，纯文本输出（勿引入 ICU、HTML、JSX 或代码语法）。
>
> 开始前记录 `ONETHU_TRANSLATION_BASE`，完成后运行本指南中的批次校验命令。若个别条目缺乏足够上下文，请列出对应 key 与具体疑问，保持业务代码与校验脚本不变。完成后汇总本批已填键数、校验结果及待确认项即可。

## 工程维护

`pnpm i18n:handoff` 由工程维护者运行，它会综合提取记录、显式种子、OneGUI 词典与当前代码调用位置生成最新词典和分批文件：中文源文案未变动的条目会自动保留既有译文，源文案已更新的条目则会重新标记为待译。

生成交接文件时会一并同步 Android 端的中文兜底资源快照，并由工程检查确保其与中文主词典一致；英文及其他新增语言均通过运行时快照下发给原生层，只需维护前端词典这一份译文。

`extract-current.mjs`、`merge-messages.mjs`、`fix-static.mjs` 属于前期工程迁移的一次性辅助脚本，日常翻译无需调用。涉及学校接口协议与持久化标识的改动均需人工逐项审阅，新增界面文案请按模块局部接入词典，避免全量盲目重扫覆盖。
