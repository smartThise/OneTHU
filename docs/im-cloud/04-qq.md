# QQ Bot 通道调研（官方开放平台 + 非官方个人号）

> 归档说明：本文记录当时的 QQ 机器人通道调研与技术评估；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

> 最后更新：2026-11-18 01:30
> 结论先行：**QQ 开放平台官方机器人合法免费、支持纯出站 WebSocket 接入，但受限于现行平台规则（2025 年 4 月起停发主动消息、暂未开放通用文件传输、群聊被动回复窗口较短），更适合承担「轻量问答与群内 @ 助手」角色；非官方 NTQQ 方案（NapCat、Milky 系）虽功能齐全，但面临持续的平台风控与账号冻结风险，不宜默认集成。**

## 1. 官方 QQ 开放平台机器人

### 1.1 接入路径与注册

- 平台入口：[QQ 开放平台 q.qq.com](https://q.qq.com/)，使用手机 QQ 扫码即可注册登录；**创建机器人**后获取 `AppID` 与 `AppSecret`（`AppSecret` 仅在生成或重置时展示一次，需及时妥善保存）。支持个人开发者实名注册，沙箱测试环境与正式环境相互独立，正式发布需经过平台审核（当前个人开发者审核通过率与类目要求**待实测核对**）。
- openclaw 生态中也有腾讯 QQ 开放平台团队官方维护的插件 [`@tencent-connect/openclaw-qqbot`](https://docs.openclaw.ai/channels/qqbot)（基于 WebSocket 网关接入）。

### 1.2 认证与事件接入

- 凭据换取：使用 `AppID` + `AppSecret` 换取动态 `access_token`（遵循 `client_credentials` 授权模式，具体有效期与自动刷新机制按官方 SDK 规范实现）。
- 事件订阅：支持 **WebSocket 长连接**为主的纯出站事件接收（官方 openclaw 插件即内置 WebSocket 连接、断线重连与 `resume` 续传序列），同时也可选配 Webhook 模式；**免公网入口**的特性对本地桌面端或内网环境十分友好。

### 1.3 消息发送规则（直接影响交互形态）

来源：官方 bot-docs [发送消息](https://bot-docs.qq.com/)（原文：[send.md](https://raw.githubusercontent.com/tencent-connect/bot-docs/master/docs/develop/api-v2/server-inter/message/send-receive/send.md)）：

> **主动推送能力于 2025 年 4 月 21 日起不再提供，接口调用会收到错误信息**（参见[官方公告](https://q.qq.com/miniapp#/news/detail/974e66a946a5e54c441ca983585a7aab)）。

| 场景 | 被动回复（带 `msg_id` 回复） | 主动消息 |
| --- | --- | --- |
| QQ 单聊（C2C） | 有效窗口 **60 分钟**，单条消息最多回复 **5 次** | 原配额 4 条/月/人，**2025-04-21 起停用** |
| QQ 群聊 | 有效窗口 **5 分钟**，单条消息最多回复 **5 次** | 原配额 4 条/月/群，**2025-04-21 起停用** |
| 文字子频道 | 有效窗口 5 分钟；单子频道 ≤5 条/秒 | 每子频道 20 条/天（限 2 个子频道/频道/天） |
| 频道私信 | 有效窗口 5 分钟 | 2 条/人/天，全频道累计 200 条/天 |

- 群聊场景默认需 **@机器人** 才会触发事件；用户也可在客户端设置中自主关闭接收机器人消息。
- 回复正文中若包含外部 URL，需预先在 `q.qq.com` 管理后台配置「消息 URL 白名单」方可正常发出。
- 发送被动回复时，通过递增序号 `msg_seq` 配合原消息 `msg_id` 实现幂等防重。

### 1.4 文件收发能力核验

- 富媒体接口（[rich-media.md](https://raw.githubusercontent.com/tencent-connect/bot-docs/master/docs/develop/api-v2/server-inter/message/send-receive/rich-media.md)）：调用 `POST /v2/users/{openid}/files`（单聊）或 `POST /v2/groups/{group_openid}/files`（群聊），其中 `file_type` 取值为：**1 图片（png/jpg）、2 视频（mp4）、3 语音（silk）、4 文件（暂不开放）**；媒体源文件目前仅支持传入公网 `url` 供 QQ 服务器主动拉取（本地二进制直传 `file_data` 标注为「暂未支持」），返回的 `file_info` 带有 TTL 有效期，且单聊与群聊素材彼此独立。
- 按上述公开接口规范，官方通道目前仅覆盖图片、视频与语音，**尚未开放通用文档或压缩包等文件收发**，且出站媒体需具备公网可拉取的直链地址。入站方向上，用户发来的图片、视频与语音事件附带限时有效的 `file_info.url` 可供下载，公开文档暂未列出通用「文件」入站事件类型（**待实测核对**）。
- 值得注意的是，openclaw 的 `qqbot` 官方插件文档提到单聊与群聊支持 files 收发，且 ≥5 MiB 文件会走「QQ 分块上传端点」，这与公开版 `bot-docs` 中「`file_type=4` 暂不开放」的说明存在出入，推测插件可能接入了特定灰度或内部端点（**待进一步验证**）。
- 小结：**按当前公开文档口径，官方 QQ 通道适合承载文本与音视频图片交互，通用文件转存清华云盘的核心需求仍需依托微信 iLink 与飞书通道完成**。

### 1.5 SDK 与平台合规

- 官方提供 Python `qq-botpy` 与 Node.js `qq-bot-sdk`，TypeScript 实现也可直接参考腾讯官方维护的 `@tencent-connect/openclaw-qqbot` 插件源码；Rust 暂缺成熟官方封装，按 HTTP + WebSocket 协议自行对接工作量不大。
- 合规层面：官方免费开放，按机器人应用维度进行名称、能力与内容审核治理，不涉及个人 QQ 账号逆向风险。

## 2. 非官方 QQ 个人号方案（高风险对照）

来源：[海豹手册 QQ 平台页](https://docs.sealdice.com/deploy/platform-qq.html)（长期跟踪 QQ 机器人生态的社区文档）及各开源项目仓库。核心背景：

> 「QQ 官方一直在对第三方实现进行技术与非技术层面的多重打击。当 QQ 账号用作机器人并被检测到时，会被警告、封禁、临时甚至**永久冻结**。这些方案实质上以 QQ 官方角度等同于『外挂软件』。」

| 方案 | 原理 | 2026-10 现状 | 风险 |
| --- | --- | --- | --- |
| **NapCat**（[NapNeko/NapCat](https://github.com/NapNeko/NapCatQQ)） | 基于无头（headless）官方 NTQQ 客户端内核运行，对外暴露 OneBot 11 接口 | 保持活跃维护；社区存在风控掉线反馈（如 [#1728 登录被风控检测频繁掉线](https://github.com/NapNeko/NapCatQQ/issues/1728)），且宿主 QQ 客户端版本需锁定以防升级失效 | **高**：占用桌面端登录槽位、风控策略持续演进、存在账号冻结案例 |
| **Lagrange.OneBot** | 纯 C# 模拟 NTQQ 协议 | **已停止维护**：LagrangeV2 不再支持 OneBot 11，V1 代码库已归档停更（参见[官方文档 FAQ](https://lagrangedev.github.io/Lagrange.Doc/v2/)） | **高**（社区主线已迁移至 Milky） |
| **Lagrange.Milky / Yogurt** | 基于 LagrangeV2 / acidify-core 实现新一代 [Milky 协议](https://milky.ntqqrev.org) | 保持活跃开发；运行需接入外部签名服务（Signer Token），公共签名服务存在随时中断的不确定性 | **高** |
| **LLBot**（原 LLOneBot） | LiteLoaderQQNT 客户端插件形态 | v8.0.9+ 需向维护团队申请中心化 `AUTH TOKEN` 方可运行 | **高** |
| **Go-Cqhttp** | 早期 Android QQ 协议模拟 | **已全面停用**，社区文档均建议迁移 | 不可用 |

**共性风险**：非官方方案普遍与特定 QQ 客户端版本强耦合、占用桌面端登录位，一旦触发账号冻结往往难以申诉解封；即便采用 Docker 无头模式部署，容器与异地网络特征也更容易触发平台安全检测。因此 **OneTHU 默认功能中不予集成非官方 QQ 协议**。

## 3. 对 OneTHU 的结论

1. **官方通道定位轻量问答助手**：适合承担私聊（60 分钟被动窗口）或群内 @ 提及的快捷查询交互，通用文件转存主路径交由微信 iLink 与飞书通道承担；针对群聊 5 分钟被动回复窗口对长耗时 Agent 任务的限制，后续可实测验证能否通过 Markdown 或卡片编辑接口原地刷新进度。
2. **坚守官方合规边界**：尽管 OneBot 11 与 Milky 等非官方生态支持群文件收发，综合账号封禁风险与高频版本维护负担，产品内坚持只接入官方开放接口。
3. **排期优先级**：列为 P2 备选通道（排在微信 iLink 与飞书之后）；后续若校园用户对 QQ 机器人有明确呼声，再以官方 WebSocket 通道小范围试水。
