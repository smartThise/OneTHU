# 动效设计规范（local/anim-delight）


> 0.11 工程说明：现行组件与设计令牌统一收敛于 `packages/gui`，旧业务变量仅作平滑过渡的兼容映射，同时支持自由调整主题、壁纸与布局。详细规范请参阅 [OneGUI](design-language.md)（[Design system](en/design-language.md)）。

分支定位：自用分支，主题聚焦于动效打磨。目标是把「丝滑、有回应、不喧哗」的观感铺到各个角落，对齐 Apple 一类系统级动效的细腻手感。本文记录该分支的实现约定，并由 `tools/motion-test.mjs`（77 条断言）在提交前自动把关。

## 1. 为什么需要一份规范

动效真正的难点在于做出来之后如何长期保持一致的手感，常见问题往往出在这些细节上：

- 时长、曲线各处硬编码，同一类交互在不同页面手感参差不齐；
- 入场动画使用 `animation-fill-mode: both`，动画结束帧把 `transform` 锁在终值，压过 `:hover` / `:active`，导致按压回弹与悬浮抬起整体失效（本轮实测曾遇到此问题）；
- 为了让动画「看得见」而不断拉长时长、加大位移，页面从顺滑变得拖沓；
- 忽略 `prefers-reduced-motion`，对前庭敏感或晕动症用户造成负担。

因此，这套约定直接落成工具可自动校验的规则，在提交阶段由脚本持续守护。

## 2. 五条硬纪律

| 编号 | 纪律 | 校验方式 |
| --- | --- | --- |
| M1 | 只动 `transform` / `opacity` | 解析全部 `@keyframes` 体，出现 `width/height/top/left/margin/padding/font-size` 即报错 |
| M2 | 时长与曲线走令牌，四档分级 | `--dur-1..4` 存在、递增、均 ≤ 600ms；CSS 内无超过 700ms 的动画 |
| M3 | 入场动画统一用 `backwards` | `both` 仅允许出现在退出动画（提示条淡出、描边勾） |
| M4 | 尊重系统「减弱动态效果」 | CSS 降级块 + JS 侧 `prefersReducedMotion()` 双重保障 |
| M5 | 重效果按端分级：桌面启用模糊，手机启用涟漪 | `backdrop-filter` 限定在 `hover:hover and pointer:fine` 媒体查询内；涟漪按 `is-phone` 密度层触发 |
| M6 | 保留既有动画选择器，按清单受控接管 | 扫描 `global.css` 与 `motion.css` 中声明了 `animation` 的选择器，交集须登记在允许清单内并注明原因 |

补充：无限循环动画仅限白名单三项——骨架流光 `shimmer`、状态点呼吸 `m-breathe`、进度斜纹 `m-stripes`；其余动画均只播放一次。

## 3. 令牌

全部动效令牌集中定义在 `apps/desktop/src/styles/motion.css` 顶部，保持固定命名。其中 **MD3 原语（§3.6）**为基准定义，下方的 `--dur-*` 与 `--ease-*` 作为兼容别名映射，让现有组件沿用原变量名即可统一接入新曲线：

```
--md-sys-motion-easing-emphasized              (0.2, 0, 0, 1)      大容器 / 页面转场
--md-sys-motion-easing-emphasized-decelerate   (0.05, 0.7, 0.1, 1) 进场（起步快、尾巴长）
--md-sys-motion-easing-emphasized-accelerate   (0.3, 0, 0.8, 0.15) 退场（起步慢、收得快）
--md-sys-motion-easing-standard                (0.2, 0, 0, 1)      常规状态切换
--md-sys-motion-easing-standard-decelerate     (0, 0, 0, 1)
--md-sys-motion-easing-standard-accelerate     (0.3, 0, 1, 1)

--md-sys-motion-duration-short-2/4             100 / 200ms
--md-sys-motion-duration-medium-2/4            300 / 400ms
--md-sys-motion-duration-long-2                500ms

兼容层（组件里的写法不变）：
--dur-1: 140ms                       微反馈（按压、悬浮）——保留原值，MD3 的 100/200 档在这太钝
--dur-2: short-4 (200ms)             常规（淡入、状态切换）；原 220ms
--dur-3: medium-2 (300ms)            容器（弹层、页面）；原 340ms
--dur-4: long-2 (500ms)              大场景（首屏揭示）；原 520ms

--ease-out       = emphasized-decelerate   进场曲线
--ease-in-out    = standard                对称过渡
--ease-spring    轻弹簧（MD3 没有，本项目的品牌抖动，只给"被点/被弹出来"的元素）
--ease-ios       = emphasized              页面与大容器转场

--rise-1/2/3     位移基准 4 / 8 / 14px
--stagger        列表逐项间隔 26ms
```

**进出场采用不同曲线**是核心原则：进场统一使用 decelerate，退场统一使用 accelerate（涵盖 `.is-closing` 相位、底部抽屉下滑与轻提示淡出）。区分进退曲线能让界面收起时利落有方向感，避免产生「进场动画倒放」的迟滞感。

**错峰出场（stagger）**：为容器添加 `stagger` 类后，其直接子元素会按 26ms 递增依次上浮（前 14 项通过纯 CSS `nth-child` 驱动，更长的列表由 JS 注入 `--i`）。错峰动效在同一视图中只作用于**单一层级**，避免父子容器叠加进场造成视觉杂乱。以「待办」页（`tasks-learn`）为例，错峰层设在「筛选行 → 卡片流 → 统计/入口」这一级；卡片流内部的单张卡片则留给拖拽手势独占 `transform`，互不干扰。

## 4. 页面转场：纯 CSS 进场过渡

`App.tsx` 中的 `.page-anim` 以 `key={page}` 重新挂载并播放一次淡入上浮动画，旧页面随即卸载。转场方向由 `useNavDirection` 对比前后页面层级得出：进入二级页为前进，返回列表为后退，各自匹配对应曲线；二级页还会叠加横向滑入效果（`data-level="sub"`）。

### 4.1 为何弃用 View Transitions 快照转场

2026-09-22 真机实测与用户反馈表明，整页标签切换若采用快照交叉淡入，旧页面截图会在新页面**下层**短暂半透明残留，两张整页画面叠在一起，每次切换都会出现「旧页面在底下闪一下」的视觉伪影。快照转场更契合「列表卡片 → 详情页」这类局部共享元素的过渡场景；整页视图切换直接采用轻量 CSS 进场动画更为干净利落。

因此项目中移除了该路径与 `withViewTransition`，并在 `tools/motion-test.mjs` 中加入回归检查，确保源码不再引入 `startViewTransition`、`::view-transition` 与 `withViewTransition`。后续若为「列表卡片 ↔ 详情页」设计共享元素过渡，将针对局部元素单独实现。

## 5. 覆盖范围一览

| 位置 | 动效 |
| --- | --- |
| 按钮 / 图标钮 / 芯片 / 可点行 | 统一按压回弹，时长 140ms 弹簧曲线 |
| 桌面端悬停（hover） | 仅可点击跳转的入口大卡轻微上浮；数字卡片与列表行保持原位，仅切换边框与底色 |
| 列表 / 统计卡 / 网格 | 逐项错峰进场，间隔 26ms，前 14 项由 `nth-child` 提供延迟 |
| 侧栏当前项 | 左侧强调条平滑展开 + 图标轻微放大 |
| 抽屉导航 | 面板沿用 `global.css` 的 `drawer-in/out`，仅内部导航项逐项进场 |
| 页签（信息 / 生活 / 预约 / 收藏夹） | 容器保持挂载以保留页签状态，仅切换类名重播一次进场过渡 |
| 弹层（确认框 / 表单 / 插件 Sheet / 订阅 / 排课 / 导览 / 论坛） | 遮罩淡入 + 面板弹簧进场 |
| 文件预览 | 面板同款弹簧进场 + PDF/pptx 逐页淡入 |
| 提示条 | 进入时弹簧下落，退出时先进入 `closing` 相位播放 200ms 淡出再卸载 |
| 统计数字 | 纯数值从旧值平滑滚动至新值；`–`、`¥12.34` 等格式化字符串直接展示 |
| 主题切换 | `<html>` 短暂挂载 `.theme-anim`，色彩在 320ms 内平滑过渡，420ms 后移除类名 |
| 移动端顶栏 | 向下滚动超过 8px 时浮起并渐显阴影 |
| 折叠箭头 / 开关旋钮 | 旋转与缩放均采用弹簧曲线 |
| 触摸反馈 | 水波纹涟漪，仅在 `is-phone` 密度层启用，由全局单一监听器驱动 |

## 6. 覆盖既有动画的两起典型问题（M6 的由来）

2026-09-22 实测报障中，有两起异常均源于动效层意外覆盖了组件原有的动画规则：

**抽屉消失**：`.drawer` 的基础样式为 `transform: translateX(-100%)`（入场前隐藏在屏幕左侧），展开后的停留位置依赖 `global.css` 中 `drawer-in … forwards` 维持终值。动效层将其改写为 `backwards` 后，展开动画一结束便退回基础隐藏态，导致抽屉瞬间消失；关闭时 `drawer-closing` 又被同特异度的后置规则覆盖，出现「闪现一次再播退场」的异常。

**提示条偏心**：`.toast-host` 的基础定位包含 `transform: translateX(-50%)`（水平居中）。新动画的关键帧中遗漏了 `-50%` 偏移量，导致入场过程中提示条先跳向右侧再弹回居中位置。同时排查出一处选择器错配：退出动画误写成了 `.toast.is-closing`，而组件实际渲染节点为 `.toast-host.is-closing`，致使退出相位一直未能触发。

经验总结：动效层专注补充新动效，保留既有组件自带的动画定义；确需接管既有动画时，统一登记到允许清单并注明原因（目前仅限 `.content` 与 `.toast-host`），由 M6 规则在提交前自动校验。
