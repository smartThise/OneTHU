# 应用服务为主体，CLI 为可选适配器


状态：已实现，正在验证安装产物与发布渠道。

早期实现将外部 CLI 授权、OH 内部服务与桌面登录绑定在同一个必装的 Node 进程上，同时由 SDK 和图形界面各自保存本地日程。这种耦合带来了明显副作用：切换外部开关会影响手机端 OH 服务，桌面界面与终端之间会出现两份彼此独立的日程数据，应用安装包也默认附带了用户未必需要的运行环境。

调整后，应用内服务成为核心主体，其权限由学校账号登录态、OH 服务授权及具体操作权限共同决定；外部调用入口则单独受 CLI 开关控制。后台常驻调度始终保持单一归属：已安装 CLI 的桌面端交由 CLI 常驻任务负责，移动端与未安装 CLI 的桌面端则运行应用内置调度。即便运行期出现异常，系统也维持单一调度实例，避免拉起第二个调度器引发并发冲突。

日历与日程共享统一通过私有账号文档接口完成，使 SDK 和 GUI 读写同一份事件数据与邮箱配置。历史数据的迁移过程留有记录，每次写入均附带内容版本号，GUI 内存态则通过刷新接收后台常驻任务写入的变更。该私有接口仅开放给主窗口调用，独立于 MCP/模型工具注册表之外，确保账号凭据始终留在宿主内而不会随模型结果返回。卸载 CLI 前，系统会先将数据导出至应用存储，并保留原有的 CLI profile，方便后续重新安装时平滑恢复。

CLI 改为由用户按需主动安装，可执行文件打包为独立 ZIP 随正式 Release 分发。安装流程会依次校验目标平台、版本、SHA-256、安装路径、解压大小与逐文件摘要，全部通过后以原子替换方式完成落盘；卸载时则先通知进程正常退出再清理文件。界面上也将外部访问开关与运行文件的安装状态分开展示，方便独立查看与管理。
