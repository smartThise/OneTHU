# OH 应用服务


小 OH 通过 `app_services` 查询应用内建服务，通过 `app_call` 发起调用；原有的学校信息查询、白板、OneFlow、插件、主题和页面导航等专用工具继续可用，而插件清单与已启用技能清单则专门管理外部扩展内容。

每轮对话开始时，OH 都会从宿主实时读取最新的已审核服务目录；新增服务须先登记至审核目录，模型随之获得实际操作名、参数列表与写操作标记。在应用内部发起调用无需开启对外 CLI 端口监听，只需授权智能体服务；涉及本机后台常驻任务的操作则仍需开启 CLI 授权。

## 已接入的应用功能

| 功能 | 查询 | 操作 |
| --- | --- | --- |
| OneTHU 通讯录 | `contacts.list`、`contacts.get`：好友、收到的名片 | 名片交换与好友通道授权在通讯录页面完成 |
| 组织 | `organizations.list`、`organizations.get`：成员、项目、公告、云盘与 GitLab 资源引用 | `create`、`update`、`saveProject`、`removeProject`、`saveAnnouncement`、`removeAnnouncement` |
| 清小搭 | `xiaoda.status`、`agents`、`models`、`balance`、`conversations`、`conversation`、`skills`、`skill`、`installed` | `importSkill`、`enableSkill`、`removeSkill`、`ask` |
| 暂存箱 | `vault.list`、`items`、`item`、`readText` | `create`、`rename`、`addText`、`addAtom`、`addFile`、`removeItem`、`share`、`importCode` |
| 白板、OnePage、OneGO、标签页、工作区 | 原有 `onePage_*`、`ext_onepage_*`、`ext_tab`、`ext_workspace_*` 等专用工具 | 保留原有编辑和确认流程 |
| 插件、主题、OneFlow | 原有 `ext_plugin_*`、`ext_theme_*`、`ext_flow_*` 等工具 | 保留现有安装与写操作审批 |
| 常驻任务 | `tasks_query` | `tasks_manage`，按本机后台授权执行 |

可直接问 OH：“我的 OneTHU 好友都有谁”“看看我的组织有哪些项目”“在清小搭技能广场找课件整理技能”“查看暂存箱里的文字”“把这段笔记收进暂存箱”。

## 发现与调用

开发者可以先查询分组，再按返回的 `parameters` 传位置参数数组：

```json
{"tool":"app_services","arguments":{"query":"contacts"}}
{"tool":"app_call","arguments":{"operation":"contacts.list","args":[]}}
```

不带 `query` 调用 `app_services` 会返回全部分组与专用工具索引，也可传入关键词按组织、清小搭、暂存箱、插件或白板定向检索。执行写操作时需具备明确的用户意图并传入 `confirm:true`，最终由宿主应用的真实审批弹窗或本机配置的自动执行策略决定放行——执行权限始终由宿主侧审批状态把关，独立于模型输出的对话文本。

这组接口直接读写当前运行中的 App 数据，调用时需保持客户端在线。独立 CLI 守护进程支持的能力以其源码 `commands` 目录登记的命令为准，本地通讯录与暂存箱数据仅驻留在客户端内。

## 数据与权限

- **通讯录范围**：仅读取已保存在 OneTHU 内的名片（列表默认返回个人好友，可显式请求组织名片），与微信、QQ 及系统通讯录完全隔离。
- **敏感字段脱敏**：名单与详情结果会自动过滤好友共享口令、通道密钥、邀请信息、头像原图和本地暂存路径；需要生成分享口令时须显式调用分享操作。
- **归属与在线校验**：读取通讯录和组织数据时会核验个人资料归属；拉取远程组织详情会重新向 GitLab 验证成员身份，若访问受拒则直接返回真实错误，确保在线状态准确反映服务端权限。
- **组织写入与协作**：修改组织项目与公告会复用权限检查和版本冲突检查；创建组织时先建立本地索引，后续开启共享协作、调整成员角色与绑定资源授权均在组织页显式确认。
- **清小搭技能状态**：技能广场目录与本地已安装列表分开查询。依赖 Python、Node 或外部环境的技能会说明运行要求，既有 QuickJS 沙盒限制继续生效；新导入的技能默认处于待启用状态，须手动启用并调用后才会运行。
- **向清小搭提问**：`xiaoda.ask` 会向指定的学校智能体发送问题并创建独立会话，调用前须先查询真实 agent id，再通过写操作审批。
- **暂存箱分段读取**：暂存箱文本读取会返回 `totalChars`、`nextOffset` 与 `complete`，支持长文分段续读；存储文件的 UTF-8 文本单次读取上限为 8 MiB（超限将报错提示），二进制格式则交由预览组件处理。
- **暂存箱分享与接收**：通过口令接收内容时会创建新暂存箱并保留当前箱；发起分享会优先复用有效短码，上传全程持续复核授权与账号状态。现有跨端交换接收器单条文字上限为 4096 字符，超长内容分享时会提示先保存为文件，本机读取则保留完整正文。
- **模式与账号切换**：上述新增应用功能在完整模式下开放；运行期间若切换界面模式或登录账号，未完成的在途操作会自动中止。

工具返回结果、公告正文、名片备注、暂存文字和技能文档在对话中均作为纯数据资料传入，宿主授权状态与沙盒运行环境始终由客户端配置独立掌控。
