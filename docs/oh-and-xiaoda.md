# OneTHU Harness、插件与清小搭


中文 · [English](en/oh-and-xiaoda.md)

## 搜索与 OH 的关系

胶囊栏内的搜索框用于快速查找应用功能与校园内容，OneTHU Harness（小 OH）则提供可调用工具的对话入口。三种界面模式均保留这两项入口，并按模式开放不同范围的工具与设置：精简模式提供基础对话、自定义 API 与微信/飞书接入；完整模式进一步开放学校模型源、扩展工具、插件与技能管理。

小 OH 结合当前所选模型与工具实时返回的数据生成回答。模型可提出工具调用建议，而服务权限校验、账号登录状态与写操作确认均由宿主应用统一把关，所有权限须经用户在应用内显式授予。

## 模型、限流与会话

完整模式支持切换已配置的学校模型源或自定义兼容 API。应用会分别检测学校令牌有效性、校园网直连与 WebVPN 连通性——遇到 HTTP 429、403 或临时网络波动时，通常属于接口限流或网络链路异常，无需重新输入账号密码。触发服务端临时限流时，客户端会按照 `Retry-After` 与退避策略自动等待恢复，稍候再试即可。

所填 API Key 仅用于请求当前选定的模型服务，对话消息与当轮工具上下文会一并发送至该服务端。隐私说明与排查方式见 [故障处理](privacy-and-troubleshooting.md)。

## 插件

插件可提供主题、命令、功能页、数据源及其他扩展能力，完整模式下可在「我的 → 插件」中集中管理。插件安装后按清单声明逐项授权；停用插件会暂停其运行并保留本地设置，卸载则会移除插件包与相关授权。原生插件、JavaScript 插件与 Android 内嵌组件运行在各自的宿主环境中；市场收录与运行时权限校验主要约束接口调用边界，安装第三方插件前仍建议审阅其源码来源。

完整接口清单由当前类型定义自动生成，共包含 **36 个命名空间、255 个方法入口**（含嵌套入口），数量随源码演进同步更新。开发指南与完整接口定义见 [插件开发](plugin-development.md)、[API 语义](api-reference.md) 与 [完整声明](api-surface.md)。

## 清小搭 in OneTHU

清小搭页面集中提供对话、历史会话、专用智能体与技能广场。既可以选择专用智能体开启新对话，也可以随时接续历史记录。清小搭维护独立的服务令牌生命周期，首次使用或令牌过期时需在清小搭页面单独完成登录授权。

## 轻量技能

1. 从广场导入完整技能包时，应用会自动检查依赖与运行兼容性；新导入的技能默认处于未启用状态。
2. 兼容的说明文档、参考资料以及无外部依赖的同步纯 JavaScript 技能，可在完整模式下手动启用并交给小 OH 调用。
3. 技能包内容更新后需重新确认启用。停用技能会立即撤销其索引、加载、文件读取与按技能运行入口，已生成的对话记录则原样保留。
4. 涉及 Python、Node、安装器、外部服务或未知依赖的技能包，会整包保守标记为需要电脑端 Agent 运行：桌面端直接保存完整目录，手机端可导出 ZIP 后传至电脑处理，应用本身仅负责包归档管理，免去在本地自动安装第三方依赖的风险。

内置 QuickJS 引擎每次执行都会新建独立环境，限制单次运行 2 秒、32 MiB 堆、256 KiB 栈及 64 KiB 代码/输入/输出体积，专注于纯同步计算，屏蔽了宿主文件、网络、子进程、模块加载、环境变量及异步执行等 Node 侧能力。其中 `skill_compute` 作为通用纯计算工具向对话开放，与单个已安装技能的权限相互独立。

小 OH 侧的工具入口为 `skills_search`、`skill_load`、`skill_read_file`、`skill_compute` 与 `skill_run`，插件门面对应 `ext.skill*`。前期抽查的六份真实广场技能包均带有外部依赖，需交由电脑端环境完整运行；对于包含可选外部依赖的技能包，当前也统一采取整包保守归类策略，暂未在应用内拆分局部功能。

本地技能库与启停状态按设备及账号分区存储在本机，保持本地离线管理而免于云端同步。调用技能时，相关说明与参考资料会随工具调用发送给当前所选模型。安全边界上，owner 分区用于隔离日常多账号本地数据，QuickJS 负责应用层脚本资源限额，两者均工作在宿主进程内部（若需操作系统级进程隔离或跨进程认证边界，请交由独立容器或电脑端外部环境执行）。

## 微信、飞书与 MCP

微信与飞书通道可在设置中扫码接入，消息收发依赖当前设备上的客户端在线运行——桌面进程退出、设备休眠或移动系统后台冻结期间会暂停接收消息。仓库中关于 QQ、企业微信与 Telegram 的文档属于前期技术调研记录，现阶段正式开放的接入通道以设置页提供的微信与飞书为准。

MCP 集成区分「OH 对外提供 MCP 服务」与「OH 连接外部 MCP 服务」两个方向。其中外部 stdio MCP 的路由调度、阻塞读取超时与权限接线仍在持续完善中，现阶段仅适合受控调试场景；日常轻量技能统一走应用内独立的宿主方法与 QuickJS 沙盒路径，详见 [实现报告](plans/2026-10-21-xiaoda-oh-skills.md)。
