# 隐私、账户与故障处理


中文 · [English](en/privacy-and-troubleshooting.md)

## 数据流与存储

| 内容 | 位置与用途 |
|---|---|
| 登录状态、记住的凭据、API 配置 | 本机存储；相应服务请求使用对应凭据 |
| 白板、模式与布局 | 本机设置与应用数据；切换模式保留完整存档 |
| 个人名片、好友与组织索引 | 完整模式连接云盘后可同步到私有 OneTHU-Profile |
| OH 记忆 | 按配置保存在 OH-Memory，与个人资料库相互独立 |
| 分享内容 | 按分享操作上传清单/文件并设置可访问范围 |
| OH 对话与工具上下文 | 发送给当前选用的模型服务 |
| 清小搭技能 | 本机账号分区；启用后相关资料可进入模型上下文 |

凭据与配置保存在当前操作系统账户的应用数据目录下；多人共用同一台设备时，建议配合系统级多用户账户隔离，妥善管理本机目录与密钥访问权限。个人资料同步仅上传名片、好友与组织索引，密码与 API Key 始终留在本地；访问组织关联的 GitLab 仓库或云盘目录时，仍按各服务的独立授权校验。

## 登录、公钥与信任设备

提示「公钥获取失败」通常与返回页面异常、网络连接波动、接口限流或信任设备数量达到上限有关，可结合诊断分类定位具体环节。0.11 统一了设备认证指纹的读写逻辑，修复了重复发起二次登录与部分 2FA 时序问题，并补充了按阶段归类的诊断信息。

发起新登录请求后设有 20 秒冷却期，同一轮并发提交共用同一条认证链，手动刷新页面时冷却计时继续保持。输入验证码会在当前认证链上继续完成校验；若验证码发送失败会直接提示当前错误状态，验证码过期后按页面提示重新发起登录即可。

当学校账号的信任设备数量达到上限时，本次验证通过后仍可正常进入应用，仅跳过新增信任设备记录。如需清理早先绑定的旧设备，可前往学校统一认证管理页面操作。

## 刷新与网络

强制刷新按钮短按重新拉取当前页面数据，长按可拖动调整位置；已保存的登录凭据、服务端限流窗口与本地客户端版本保持不变。开启 TUN 或系统代理会影响 DNS 解析、路由走向与证书校验；若关闭代理后请求依然受阻，建议结合客户端版本、运行平台、请求阶段与错误状态进一步排查。

Windows 版在 0.11 中修复了跨线程创建 WebView 引发的网页区域无响应问题。如果遇到窗口边框可拖动而页面内控件无法点击的情况，建议先记录当前构建版本号与运行日志再反馈，避免反复提交触发登录冷却。

若提交登录信息后提示统一认证未返回可用登录表单，新版已支持识别标题含认证标记、正文为空的二次认证过渡页。日志中出现 `unexpected-page / credential-entry` 时，还需结合上下文日志确认凭据是否已发出：在 Windows 上可按 Win + R 打开 `%APPDATA%\app.onethu.desktop\logs`，从 `onethu-debug.log` 中提取报错前后的 AUTH-PHASE、AUTH-FAIL、ILIB 和 NATIVE-HOP 行协助排查（提交时请略去密码、验证码、Cookie 与网页正文）。诊断信息中的 Chrome/79 为应用兼容校内系统所设置的固定请求 UA 字符串，系统实际运行的仍是本机 WebView2 内核。

## 云盘归属与资料同步

云盘元数据解析已兼容群组库与共享库的字段差异。当目标个人资料库归属未确认、旧版宿主缺少对应接口或遇到共享库与虚拟子库限制时，应用会暂停自动建库、删除与同步操作，以防误改共享目录；此时可在清华云盘网页端核对资料库归属与写权限后再继续操作。

首次启用跨设备同步时，请先在存有本地资料的设备上升级并完成一次上传，随后即可在其他新设备上拉取恢复。互不冲突的修改会自动合并；同一字段出现双端修改冲突时，界面会展示版本对比卡片供手动选择。切换账号或体验模式时，应用会自动拦截上一状态的未完成异步写入，确保当前资料互不干扰。

## 反馈与诊断

提交问题反馈时，附上应用版本、构建信息、运行平台、复现步骤与脱敏诊断摘要即可协助定位。内置诊断仅记录请求状态、脱敏路径、页面长度和错误阶段，自动略去密码、验证码、Cookie、完整认证网页与 API Key；当系统剪贴板受限时，界面会直接展开可手动框选复制的诊断文本。

| 现象 | 核对入口 |
|---|---|
| 数据空白或过旧 | 当前页面刷新、服务登录状态、筛选条件与学期 |
| 作业 DDL 未显示 | 相同日期的作业列表、日程来源开关、截止时间解析 |
| 同步资料为空 | 当前账号、旧设备是否上传、模式、资料库归属 |
| 通知未到 | 系统通知权限、精确闹钟、静默时段与厂商后台限制 |
| NFC 不稳定 | 优先短口令；核对设备与原生构建支持 |
| 技能不能启用 | 核对运行时依赖与环境要求；重型技能可导出给电脑 Agent |

## 更新机制

应用主程序升级通过下载并安装新版客户端完成，已安装的 JS 插件则可在插件管理页内独立检查并拉取仓库更新；本地开发调试时使用的前端热重载（HMR）仅作用于本地开发环境。
