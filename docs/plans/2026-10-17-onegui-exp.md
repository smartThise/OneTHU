# OneGUI exp Implementation Plan


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

**Goal:** 在本地 dev3 的 exp 分支建立清爽克制的中性工作台视觉语言，完整保留 OneTHU 既有的交互结构与核心使用体验。

**Architecture:** Reference → Semantic → Structure → Material → Components → OneTHU recipe。OneGUI 作为视觉令牌的唯一来源，宿主应用专注于路由、业务数据与几何布局；现有设置继续驱动明暗模式、主题色、密度与材质档位，并将主题强调色与主要操作按钮解耦。

**Tech Stack:** React 19 / TypeScript / CSS custom properties / Vite / Playwright。

## 视觉定案

采用中性工作台路线：白与炭灰面阶、清晰克制的边界、黑白高对比主要动作、低饱和业务色、圆润输入区与严谨字阶。对比评估过的另外两个方向——照搬纯对话流布局会打断现有工作台习惯，继续加重毛玻璃特效则会让多套材质彼此干扰——因此收敛到这套中性工作台体系，同时完整保留首页自由画布、程序坞、标签页与工作空间、OH、OneGO、设置抽屉及手机端导航。

## 实施

1. 梳理现有设计令牌、样式管线与基础组件，基于 `90eec5b2` 基线创建 `exp` 分支。
2. 重整中性色参考阶、明暗语义、动作/输入/壳层角色、控件密度、圆角、排版字阶、阴影与动效令牌。
3. 重做材质分层：保留可选的四档毛玻璃效果并由统一的透明度公式推导，确保输入控件与弹出浮层始终清晰可读。
4. 让按钮、卡片、输入框、分段控制器、菜单与焦点环共用统一语义角色，保持主要动作色与主题 accent 相互独立。
5. 将存量兼容别名与应用外观配方统一收归组件库；应用层旧样式文件仅保留几何布局，清理已被接管的外观声明，确保全局只有单一主题来源。
6. 修复切回默认主题时残留旧 accent 变量的问题，同时完整保留用户本地存储数据。
7. 运行 typecheck、build 以及 OneGUI、令牌、CSS、对比度护栏；在真实浏览器中逐一核验桌面与手机视口、明暗模式、毛玻璃档位及设置、搜索、菜单交互。
8. 归档实测截图与验收报告，明确记录存量遗留项与待实机验证范围，并同步更新长期记忆。

## 验收标准

- 同类控件共用同一组语义角色，组件层 CSS 零硬编码色值与孤立尺寸。
- 默认主要按钮在明暗两档下对比度均达到 4.5:1 以上，次要说明文字清晰易读，键盘焦点环醒目可见。
- 手机端无横向溢出、元素遮挡或旧版标签条残留；桌面工作空间与白板坐标保持原有存储格式。
- 验收报告清晰区分预览环境已通过的核心工作台范围，以及后续待推进的存量页面迁移、校园账号登录后子页与真机测试项。
