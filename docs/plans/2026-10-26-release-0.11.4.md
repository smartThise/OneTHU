# OneTHU 0.11.4 发布计划


**目标：**完整保存当前 `main` 工作区改动，使 `dev3` 与 `main` 指向同一份冻结源码，正式发布 macOS、Windows、Android 三端 0.11.4 安装包并核对全部更新渠道。

**方案：**先提交 Harness 子模块，再提交主仓库，`dev3` 分支通过快进合并对齐并完整保留提交历史。桌面端双平台由同一标签触发 GitHub Actions 构建，Android 端在本地使用正式证书签名构建，确保所有发布包均与同一提交、构建流水线及文件校验摘要严格对应。

1. 核对各端版本号字段、CLI/SDK 构建接入与正式应用包名身份，筛除本地测试凭据、临时构建产物与调试探针。
2. 整理版本发布说明并完成全套上线前验证：覆盖统一认证、云盘边界、CLI/SDK、OH 能力、新增业务接口、i18n 词典、TypeScript 类型检查与前端生产构建。
3. 推送 Harness 子模块、提交 `main` 并快进同步 `dev3`，在冻结源码上打上 `v0.11.4` 标签以触发桌面端 Actions 构建。
4. 在本地完成 Android 正式签名构建，逐项校验版本号 `0.11.4` / `versionCode` `11013`、签名证书、标准 Logo 与内嵌前端资源；同步下载并核验桌面端构建产物及随附的 CLI 运行时。
5. 将安装包上传至 GitHub Release 草稿及清华云盘各系统目录，更新 `.sha256` 校验码与 `latest.json` 清单，复核无误后将 GitHub Release 设为公开 Latest。
6. 同步更新官网中英文版本号、在线文档与下载页快照，完整回下三端云盘镜像复核哈希摘要，并将发布记录归档至长期记忆。

验收说明：发布报告将安装包静态核验、协议回归测试与实机登录测试分项列出，如实说明 Windows 与 Android 的真机测试范围；外部模型服务端偶发的 502 网关波动作为远端可用性状态单独附注。

**完成状态：**2026-10-26 三端安装包、GitHub Latest、清华云盘与官网中英文更新渠道已全部就绪。详情参见 [发布验收](../reviews/2026-10-26-release-0.11.4.md)。
