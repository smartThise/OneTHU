# 雨课堂 CLI 与 OH 查询贯通


针对用户反馈 OH 提示“雨课堂未接入”的问题展开排查：当时图形界面虽已具备完整的雨课堂只读客户端，但插件门面仅开放了外部作业快照与刷新接口；独立 SDK 虽包含部分 `exthw` 查询，却缺少桌面端雨课堂会话的同步通道，OH 侧也尚未注册对应的专用查询工具与能力提示词。

本次改造复用既有的 `createYuketangSource`，为 GUI 门面、CLI/SDK 与 OH 统一补齐显式的 `yuketang` 查询集，涵盖连接状态、课程列表、课程内容目录、作业列表、作业详情、课件／视频详情及公告详情。返回目录自带可供后续详情查询直接引用的源 `id`，同时清晰说明默认时间窗口与登录方式，并完整保留原有的 `exthw` 命令兼容。

当桌面端开启 CLI 或智能体服务授权时，会通过既有的原生私有通道将雨课堂 Cookie 与学校标识同步给后台运行时。同步数据按学号与会话 epoch 严格隔离，认证凭据全程留在底层传输层，与模型上下文、公开服务返回值及运行日志隔离。桌面端断开连接时仅清理自身同步过去的凭据；若独立 CLI 本地已配置了另一份不同的会话，则返回冲突提示并妥善保留原有配置。移动端继续直接调用应用内客户端，整套桥接严格限定在只读查询范围内，维持原有的审批与作业提交边界。

OH 侧同步新增清晰可发现的只读雨课堂查询工具，并在提示词中分别说明学校统一身份登录与雨课堂微信扫码登录各自的状态。配套补齐中英文 CLI 文档与纯模拟回归用例，逐一覆盖能力目录、权限校验、账号切换、凭据脱敏、会话同步与断开清理，并跑通全量类型检查、生产构建与 Harness 工具回归。实机验证仅对已登录会话发起只读查询，全程零消息发送、零作业提交。

## 实现与验收

- 已落地共享的纯 core 查询服务、GUI 门面、CLI/SDK 七项 `yuketang` 查询命令、OH 内置 `query_yuketang` 工具，以及两份内置清单的 `exthw:read` 权限声明；独立智能体提示词也已补充双平台各自的登录接入说明。
- 桌面私有方法 `yuketangSync` 已加入原生层与 daemon 的精确白名单，对公开 MCP 与外部服务目录保持隐藏；支持按账号与 epoch 同步、断开仅撤销自身凭据，并可通过 `yuketang.status` 中的 `desktopSync` 字段查看独立配置冲突状态。延迟到达的旧心跳 Cookie 回写也补充了凭据与账号归属校验。
- 内容目录查询会自动翻页遍历并对重叠条目去重，遇到拉取失败的课程或重复分页时显式标记 `incomplete`。作业时间窗口（horizon）与桌面界面保持一致：完整保留历史作业，未来截止日期默认覆盖 30 天并支持按需显式调整；课程内容目录则拉取全量条目，免受该时间窗口截断。
- SDK 195 项、CLI 74 项、私有同步编排 5 项与 Harness 66 项回归测试全部通过；全工作区类型检查、前端生产构建、原生主程序构建及 sidecar release 构建均一次通过。通知附件与既有 CLI 保护性回归保持全绿，中英文 `i18n` 检查零错误。
- 本地 dev 应用的雨课堂会话已成功同步至 CLI（`desktopSync=synced`），学校主账号登录保持 `ready`；首次向学校接口发起真实课程查询时返回 HTTP 401，提示需重新扫码刷新雨课堂登录态后再继续拉取真实课程内容。
- 当前代码保留在本地工作区，暂未打包发布新版本；详细审查记录参见 `docs/reviews/2026-10-26-yuketang-agent-access.md`。
- 联调期间还定位并修复了 CLI 启动早于原生授权恢复、进而意外关闭后台开关的时序问题，补充了初始化等待逻辑与回归用例（共享运行时测试增至 20 项）。经与用户确认后已恢复原有的 `enabled=true`、`automatic=false` 配置，再次重启后查询链路保持畅通，并准确返回雨课堂会话过期提示。

## 后续联调修正

进一步排查确认，上述 HTTP 401 除登录态过期外，还涉及 SDK 传输层重建 Cookie 时引发的假失效问题；改为按服务分配专属的隔离 Cookie jar 后，常驻 CLI 已能稳定读取真实的雨课堂作业数据。完整的修复过程及微信凭据覆盖问题排查详见 `docs/reviews/2026-10-26-rain-wechat-recovery.md`。

此后用户再次反馈微信端 OH 回复“没有雨课堂插件”，排查发现运行中的二进制已经内置对应工具，只是历史对话上下文诱导模型跳过了实际工具调用而直接复述旧结论。为此新增了确定性的只读预取机制：当用户当前消息明确提出雨课堂查询需求时，先通过原有工具与权限门面拉取真实数据再交由模型组织回答（历史对话仅用于辅助解析指代对象）。修复后在保留完整历史对话的前提下，通过真实 IM 的 `askOh` 调用链路完成只读验收，全程保留原有会话记录且无需对外代发微信消息；底层工具若发生异常也会原样透传真实错误，预取过程严格保持纯只读，无自动安装、改配置或提交副作用。
