# 作业显示、i18n 与全量质量修复顺序


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

2026-10-20，工作分支 `exp`。本文梳理全量质量修复的推进顺序并同步本轮交付进展；本地工程回归完成后，译文审校与跨真实账号/真机验证将作为后续独立环节跟进。

## 1. 先完成三模式作业和同步修复

根据用户最新确认的现象：同一周内完整模式能够正常显示作业，而切换到极简与实用模式后，列表视图虽能看到作业，时间轴视图却缺失对应条目，且列表最下方的作业被遮挡无法滚动触达。为此验收环节在检查 DOM 节点渲染之余，同步引入了真实可视区域几何检测与指针输入命中校验。

本轮排查定位到的具体根因如下：

- 简洁外壳在桌面端同样将底栏 OH 胶囊固定在视口底部，但日程样式配方误清除了底部安全留白，导致晚间截止的时间块卡片与长列表末尾条目容易被常驻底栏遮住。
- 早期的浏览器测试夹具仅构造了下午截止的作业与空白课表，加上自动化点击会触发浏览器默认滚动，掩盖了晚间作业被底栏遮挡的问题。现已补充矮窗口、23:59 截止作业、超长列表、原生滚轮滚动与真实坐标命中检查。
- 处于简洁模式时，完整模式已挂载的标签页在后台隐藏，其容器高度为 0 属于正常的保活状态；排查与日志诊断已统一改为绑定当前活动可见面板进行测量。
- 网络学堂分项拉取接口报错时曾被静默兜底为空数组，导致本地原本完整的作业快照有被残缺结果覆盖的风险。现已将分项取数异常处理与过期请求回写拦截拆解加固，确保拉取失败时稳妥保留上一份完整快照。
- 本地日历、系统日历镜像及清华邮箱同步链路中梳理出的账号隔离、初始化就绪时序、并发写入竞态及异常吞没问题，均已在对应专项报告中逐一修复，并在上游数据不完整时严禁执行覆盖性删除。

验收标准：覆盖 Chromium 与 WebKit 双引擎、三种使用模式、桌面矮窗口与手机视口；23:59 晚间截止作业无需借助自动滚动即可直接点中，超长列表通过鼠标滚轮或触摸滑动可顺畅抵达末尾最后一项并点击打开，跨页面来回切换导航后依然稳定有效；物理手机真机触控与学校线上服务写入留待实机环节复核。

当前进度：代码修复与本地多引擎视口矩阵已全部完成，新增的 313 项布局与输入命中断言全数通过；真实校园账号同步写入与原生手机实机操作待后续执行，详见 [本轮验收](../reviews/2026-10-20-schedule-sync-acceptance.md)。后续所有界面可见性回归统一采用真实视口几何与指针命中标准验收。

## 2. 工程先完成 i18n，再交小模型翻译

详细架构与交接规范见 [工程接入与翻译文件指南](2026-10-20-i18n-engineering-and-translation-plan.md)。

当前 `exp` 分支已基于最新业务代码完成 i18n 工程底座搭建：提取完整自然语句词条、接入组件级语言订阅与 `Intl` 格式化、打通 OneGUI 内置默认文案动态翻译、支持已打开弹层实时刷新语言，并配套了严格拦截缺键、插值参数失配及跨批次改动的静态校验器。全程跳过 PR 57 中已过时的旧业务文件，仅在中文源文完全匹配时吸纳历史候选译文。

目标语言词典骨架、只读分批文件、调用上下文与校验命令均已就绪，详见 [翻译指南](../i18n/TRANSLATOR_GUIDE.md)。后续翻译模型只需填写指定批次的译文字段即可（当前英文词典尚有待译空值）。网络学堂官方英文课程名称仅用于界面展示，选课与学堂解析器已同步补齐中英双语页面兼容，同时完整保留用户在学校服务端的原有语言偏好。

## 3. 分领域做软件整体审查并修复

按风险优先级分批推进：优先根治可能引发越权访问、数据丢失、敏感凭据外泄及跨账号状态串扰的隐患，随后系统收敛运行稳定性、交互一致性与历史遗留代码。每一项均完整记录复现路径、根因定位、修复方案、验收证据与已知环境边界。

| 领域 | 必查内容 | 完成证据 |
| --- | --- | --- |
| 身份与权限 | 学校登录/SSO、OAuth/Token 生命周期；组织成员、文件、项目、公告与分享的服务端授权；退出/切账号后的旧请求 | 跨账号与角色失败路径测试；暂缺第二账号时预留真实联调脚本并列明待验范围 |
| 隐私与凭据 | 日志、错误提示、调试导出、剪贴板、口令分享、缓存和持久化中的密码/Token/个人数据；邮件正文与附件 | 数据流梳理清单与脱敏回归；仅读取必要字段，报告中零真实凭据或私人内容留存 |
| 网络与账号稳定 | 429/超时/取消、单飞与有界重试、会话恢复、前后台切换、离线/半成功、账号 epoch、请求队列 | 模拟网络失败/恢复与乱序响应回归；涉及真实线上服务的操作单独标注 |
| 本地与云同步 | 版本/冲突、条件写入、并发编辑、部分失败、持久化错误、删除与同步竞态、重复任务 | 异常时保留本地副本、支持重试、严防误清空；原生设备专项验收单列 |
| 外部输入与原生边界 | HTML/Markdown/邮件渲染、URL 打开与跳转、文件路径与附件、插件/IPC/能力权限、远端资源地址 | 面向边界的恶意载荷注入测试；严格拦截越权调用与凭据跨域泄露 |
| 整包更新与发布链 | 已有更新源、传输、取消、大小/哈希校验、安装入口和签名口令处理 | 本地真实 HTTP/文件系统故障注入测试与跨平台编译；正式资源热更新按用户后续安排移出本轮 |
| 功能与模式一致 | 三模式数据保留、导览直达、权限提示、待办/作业/日程口径、导航与工作区、暂存箱/口令/NFC | 从真实用户界面入口端到端操作验收；确保切换使用模式时本地数据完好无损 |
| OneGUI 与可访问性 | 令牌与样式来源、层级/遮挡、滚动、长文案、主题对比度、键盘/触摸、Windows/WebView 布局 | 桌面与手机多视口及平台矩阵验证；留存实拍截图、坐标命中与真实交互记录 |
| 废弃代码与工程质量 | 重复状态源、旧样式、退役订阅、无调用入口、过期依赖、无效测试、构建/护栏 | 确认零调用且无存档迁移依赖后再行清理；保持旧存档兼容，通过全量构建与有效回归 |
| 性能与资源释放 | 首屏包体积、后台轮询、重复请求、页面/窗口退出后的订阅、缓存上限、附件与大列表 | 基于真实指标测量与内存/订阅释放核查，设定合理的缓存容量与有界重试上限 |

对于依赖第二个真实校园账号的组织协作线上联调，按用户指示先行完成全部服务端校验逻辑并留好自动化联调入口，同时照常推进其余所有可在本地及单账号环境下落地的审查项，将跨账号实测清晰列入待办清单。

各领域的审查总结均按实际验证覆盖面如实记录，逐条列明已修复问题、暂未复现线索、当前环境限制及留待真机或双账号补验的具体条目。

### 更新范围的最终决定

用户随后明确指示：“真正热更新……实现不了，别管了”。据此更新本轮交付边界：不再新建前端静态资源 OTA 热更新、签名发布后端、启动健康度上报或自动回滚基础设施。

开发期继续保留 Vite HMR 热替换，生产侧集中精力加固现有整包更新链路的安全性与可靠性。关于真实下载中途取消、篡改安装包拦截、唤起安装前二次哈希校验及 APK 打包脚本的改进详情，可参阅 [整包更新审查](../reviews/2026-10-20-updater-audit.md)（相关验证已通过本地文件系统与 HTTP 故障注入完成，未在当前宿主机上执行覆盖安装）。
