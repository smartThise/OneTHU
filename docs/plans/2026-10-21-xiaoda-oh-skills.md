# 清小搭技能广场 → OH：实包调查与接入方案


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 现行功能与使用说明请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

日期：2026-10-21。状态：接口与样本实包调研已完成，广场列表分页缺陷已修复；运行层分期方案见正文，同日落地的跨端内置轻量运行环境见文末补充记录。

## 结论

清小搭技能广场具备接入 OH 的完整条件：OH 目前已拥有智能体工具循环、校园工具、OneFlow / 插件体系与探索浏览器工具，接下来需要补齐面向标准 Agent Skills 的包加载、资源按需读取与脚本执行层。大模型本身可以直接阅读 `SKILL.md` 中的方法说明，而技能包附带的本地脚本与第三方依赖则需要宿主提供匹配的运行环境。桌面端可按阶段逐步扩展受控的本地运行能力（无需额外部署云端执行后端），Android 端则结合移动沙箱特点提供轻量、自包含的可运行子集。

前序背景参见 `2026-10-18-feedback-round2.md` 第 4 节。标准技能包由 `SKILL.md` 及可选的 `scripts/references/assets` 目录组成，具体脚本语言支持范围由宿主环境决定（规范参见 https://agentskills.io/specification ）。

## 已核实的学校接口

依托现有校园认证，以只读方式拉取了广场元数据及 6 个代表性技能包 ZIP 做离线结构分析。当时动态广场共有 273 个技能条目，所选 6 个样本旨在覆盖不同依赖类型做定性剖析；拉取请求仅触发常规下载接口（可能计入广场下载次数），全程未运行包内脚本、未安装外部依赖，也未发起对话或发布内容。

| 功能 | 接口 / 参数 |
| --- | --- |
| 分类、统计 | `/api/skill/plaza/categories`、`/overview` |
| 列表 | `/api/skill/plaza/list?currentPage=1&pageSize=10`，另有 category/sort |
| 搜索 | `/api/skill/plaza/search?keyword=…&page=1&pageSize=10` |
| 详情 | `/api/skill/plaza/detail/{id}` |
| ZIP 下载 | `/api/skill/plaza/download/{id}`；使用 token 头鉴权 |

OneTHU 旧版仅接入了分类、统计与列表接口，点击详情页当时只是复用列表摘要，尚缺独立的详情查询与 ZIP 下载能力。服务端详情接口返回版本号、更新时间与示例提问等字段，但未提供结构化的运行环境依赖声明。

**同步修复线上分页缺陷**——旧版客户端请求翻页时传入 `pageNum=2`，服务端实际一直返回第 1 页；改为 `currentPage=2` 后即可正确拉取第 2 页不同数据，已通过真实 `XiaodaClient` 在线验证。此外，未登录状态下接口仍返回 `HTTP 200` 并在 JSON 正文中以 `code=2002` 表示 `token` 为空，客户端需同时校验业务状态码。

ZIP 下载需走二进制传输通道：现有 `transport.ts` 已支持 `body_b64` 二进制响应（区别于仅解析 JSON 的 `apiGet`），且导入链路应在 Rust 原生下载层直接限制包体体积，避免超大文件经 `base64` 编码涌入 WebView 内存。

接口协议核对自清小搭官网线上前端产物：
- https://www.xiaoda.tsinghua.edu.cn/assets/index-CQn9xufO.js
- https://www.xiaoda.tsinghua.edu.cn/assets/index-gHF6L1pI.js
- https://www.xiaoda.tsinghua.edu.cn/qingxiaoda/skills/INSTALL_GUIDE.md

其中静态安装指南提到的“72 个安装型 + 3 个完整包”对应早期静态批次，而线上动态广场已扩充至 273 项；指南中列出的静态下载目录实测返回 `404`，客户端实际拉取统一走带 `token` 鉴权的下载接口。

这 6 个线上 ZIP 均将 `SKILL.md` 直接放在压缩包根目录，而官方静态安装指南则描述外包一层同名技能目录。因此导入器需同时兼容“根目录直放 `SKILL.md`”与“单层外包目录”两种合法布局，并拒绝包含多个并列顶层目录的歧义压缩包。抽检样本中未发现路径穿越或符号链接，正式解包与执行层仍按严格不可信输入标准实施完整校验与隔离。

## OH 现有架构与待补齐环节

对照 Harness 子模块 `plugins/OneTHU-Harness`（调研基线 `925a7ed796b01aa4535e1c261360d08e36411ad1`）：

- `core/src/agent.rs:143,343`：当前拼装固定系统提示词、内置静态工具与 MCP 工具，尚无技能摘要索引与按需加载入口。
- `core/src/tools.rs:816` 与 `apps/desktop/src/state/userext.ts`：`ext_tool_create` 面向固定的 `ns.method` 校园 API 编排序列，标准技能包的动态参考文档与脚本目录需通过专门的技能层承载。
- 客户端未内置通用 shell / Python / Node 执行工具，安装包也未捆绑外部语言解释器（`build-harness.mjs` 仅打包 Rust 二进制与品牌图标）。
- `geek_eval` 运行在桌面探索浏览器的网页上下文中，专职页面 DOM 交互，与本地 Node 脚本运行环境相互独立。
- Android 端以原生库形式内嵌同一套 Rust core，在移动系统沙箱内运行，无桌面端外部进程派生环境。
- 现有 MCP 模块支持基于 `stdio` 的 `tools/list` 与 `tools/call`（每次调用冷启动子进程），暂未接入 `HTTP/SSE` 传输及 `resources/prompts` 接口。

在引入外部脚本运行环境之前，还需留意既有 MCP 模块中的四处实现细节：
1. `tools.rs:1587–1594` 在剥离 `mcp_` 前缀后仍用带 `mcp_` 的名称做二次匹配，导致动态 MCP 工具路由未能命中。
2. `mcp.rs:108–117` 的超时检查位于阻塞式 `read_line` 循环外部，当子进程静默挂起时无法及时中断，且尚缺输出体积上限与取消信号传播。
3. 修复上述路由后，动态 MCP 分支会直接调用并返回，需同步接入与内置工具一致的用户确认策略后再向第三方扩展开放（受限于第 1 条路由问题，该分支此前实际上未被触发）。
4. MCP 子进程当前直接继承宿主环境变量，后续若承载不可信脚本还需补齐显式的环境变量裁剪与沙箱边界。

上述四点系本次源码走查记录，独立于本轮广场分页修复与轻量技能层改造。

## 分期演进方案

技术选型上采用原生标准技能包层，完整保留原始 `SKILL.md` 说明与参考资源——既避免将丰富技能强行裁剪为固定的校园 API 步骤串，也无需额外部署重型云端代码执行后端。

### 第一期：跨端可用的轻量技能与资料按需加载

- 打通广场关键词搜索、分类筛选、详情查询与完整 ZIP 下载，配套完整的本地技能库管理（记录来源、版本号、启用/停用切换与卸载删除）。
- 实施严格有界解包：拦截绝对路径、`../`、Windows 盘符、符号链接/硬链接及大小写路径碰撞；限制单包文件总数、解压总字节数、单文件上限与压缩膨胀比；先解压至临时目录校验无误后再原子切换生效。
- 持久化原始来源 `id/version/hash` 与许可证信息；识别引导安装壳包并单独标注，跳过执行包内安装命令；完整保留参考资源子目录的相对路径。
- 为 OH 新增 `skills_search`、`skill_load`、`skill_read_file` 三个工具：常驻系统上下文仅注入已启用技能的名称与简短摘要，详细说明与参考资料在对话需要时按需拉取。
- 技能文本统一包裹在第三方工具返回上下文中，严格服从宿主系统安全规则；包内声明的 `allowed-tools` 等元数据仅作能力范围参考，实际工具权限始终由宿主统一管控。
- 按精细状态呈现每个技能：已导入、可用能力、缺少运行环境、待填写配置、当前设备受限、待人工确认；仅在全部依赖核验齐备后才标为就绪。
- 手机端可直接启用满足当前模型与校园工具条件的纯说明型及校园工具编排型技能，各设备均按本机实际环境独立计算可用状态。

### 第二期：桌面端按需托管运行环境

- 在桌面端支持按需初始化由 OneTHU 独立托管的 Python / Node 运行环境，面向普通用户零开发环境起步，自动探测解释器版本、依赖包与系统工具。
- 将基础运行时与单技能专属依赖隔离存放并锁定版本/哈希；安装前向用户清晰展示依赖清单与体积预览，获单次明确授权后再装入私有目录，零污染用户全局 `pip/npm install` 环境。
- `skill_run` 采用显式解释器路径、脚本文件与参数数组调用，配备独立任务工作目录、明确输入文件映射、可追溯产物收集、执行超时与手动取消、子进程树回收、标准输出限流及最小化环境变量。
- 鉴于进程参数数组、工作目录与超时控制仅约束调用入口，尚不足以限制本地 Python / Node 代码读取用户磁盘文件，在落地平台级系统沙箱或清晰的本地受信脚本确认模型之前，仅开放经审查或受限的受控执行通道。
- 当脚本运行环境暂未就绪时，若技能同时具备独立的纯文本指导部分，可在向用户明确说明脚本能力缺席的前提下开放文本辅助；所有脚本计算结果均严格取自真实运行时输出。

### 第三期：引导安装壳包、外部服务诊断与跨端协同

- 针对 ClawHub 等安装壳包，仅解析其指向的明确来源与固定版本号，下载目标技能包后重新走完整的静态检测、安全审查与哈希登记流程，跳过直接执行第三方文档中的 `npx latest` 命令。
- 为依赖本地代理、外部 API 或 MCP 服务的技能提供显式配置面板与实时连通性探测，依据真实探测结果展示服务就绪状态。
- 移动端重型计算技能未来可探索委派给用户本人配对的桌面端执行；所有涉及校园会话或本地个人文件的操作，始终严格限定在用户显式配置并授权的端点内运行。

## 分期目标验收标准

1. 导入 `high-eq-consultant` 后，OH 能自动检索并按需读取包内真实说明与案例文档，桌面端与 Android 端均核实真实工具调用链。

4. `travel` 配套的本地代理未启动时，快速给出“本地服务未配置或未启动”诊断提示，避免长时间挂起等待 `localhost`。
5. `academic-writer` 清晰标注为安装引导入口，待目标包拉取并核验通过后再切换为可用技能。

7. 配套覆盖 ZIP 路径穿越与压缩炸弹、提示词注入、标准输出爆栈、子进程挂起、权限拦截与跨平台路径差异回归测试，并结合客户端真实点击与 OH 对话完成端到端验收。

## 2026-10-21 最小轻量环境落地补充（dev3）

随后用户进一步明确产品要求：桌面端与手机端统一内置开箱即用的轻量运行环境，遇到重依赖技能直接清晰说明原因，并支持将完整技能目录导出给电脑端外部 Agent 使用。据此本轮选用内嵌原生 QuickJS 引擎构建跨端一致的受控沙箱，而将上文第二、三期的 Python / Node 托管环境与外部服务留作远期扩展方向。

### 已实现能力

- 清小搭技能广场闭环：接入真实的线上搜索、详情拉取、流式下载与解包预检；ZIP 下载在 Rust 原生层直接限流读取，避免整个压缩包经 Base64 进入 WebView；下载请求严格锁定学校官方域名与路径，仅携带独立 `token` 请求头，剥离校园主站 Cookie 且禁用跨跳重定向。
- 本地技能库：按设备与当前登录账号分目录隔离存储，新导入技能默认处于“未启用”态，支持随时启用、停用与彻底删除；当更新包内容变化（SHA-256 变更）时自动重置为待重新启用，更新失败则无损保留旧版本；首次启用时明确提示技能文档内容会随对话发送给用户所选的大模型。
- 静态能力分级：纯提示词与参考资料包可直接读取，零宿主依赖的同步纯计算 JavaScript 脚本可在内置沙箱中运行；一旦静态扫描发现 Python、Node、包管理器安装命令、系统脚本或二进制文件、外部本地服务端口或未知文件类型，整包统一稳妥归类为“需电脑外部 Agent”，并在界面上锁定 OH 启用开关。静态启发式扫描与运行期引擎限制双层配合，确保只有契合纯计算沙箱边界的脚本得以运行。
- 接入 5 个真实 OH 工具：`skills_search`、`skill_load`、`skill_read_file`、`skill_compute`、`skill_run`，全部打通宿主桥接与 Rust 原生实现。读取到的第三方技能文档统一附带 `untrusted` 标记且零额外权限提升；`skill_run` 与 `skill_compute` 的计算结果全部由原生 QuickJS 引擎实算返回。
- `skill_compute` 作为独立的内置通用纯计算工具常驻可用。当用户停用某个技能时，立即撤下其摘要索引并阻断后续对该技能文档与脚本的加载、读取及运行调用，既有对话历史与通用纯计算工具保持正常可用。整套技能工具仅在完整模式下开放，极简与实用模式下全程隐藏，异步执行返回时还会二次复核模式修订号与当前账号是否一致。
- 完整目录导出：桌面端调用系统原生目录选择器，在确保目标路径无同名覆盖冲突的前提下完整写出 `SKILL.md` 与全部附属资源；Android 端通过系统下载保存面板导出原始 ZIP 包，方便传至电脑解压使用。两端导出流程均为纯文件写出，零执行包内脚本或联网安装器。
- 前端界面全面采用 OneGUI 的 `SectionCard/Row/Modal/Btn/Chip` 组件构建，同步配齐中英文词条与翻译种子；页面上的“运行环境检查”按钮会真实调用原生 QuickJS 计算 `2+3+5` 并校验返回值，直观反馈引擎实际就绪状态。

### 原生安全与资源限制

- QuickJS 每次调用均新建全新独立上下文，严格限定单次执行时长 `2` 秒、堆内存 `32 MiB`、调用栈 `256 KiB`，源码、输入 JSON 与输出 JSON 单项上限均为 `64 KiB`，并挂载底层 `interrupt handler` 确保死循环可在引擎指令级被强制中止，配合外层 `Promise` 超时共同守护执行边界。
- 零宿主能力暴露：引擎内不含任何宿主桥接函数、模块加载器、进程控制、环境变量、网络套接字、文件系统、DOM、Node 或 Python 接口；仅接受明文 JavaScript 源码，拒绝加载第三方预编译 QuickJS 字节码，并拒绝返回未决异步 `Promise`。
