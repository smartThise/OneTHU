# PR #58 修复与保留本地开发的合并计划


**Goal:** 修复 PR #58 审查中发现的问题并合入主干，同时完整保留 PR 新增的视觉与学习页功能，以及本地工作区已有的 CLI、共享会话和通知附件改动。

**Architecture:** 基于 PR 原始 head 拉出独立的隔离 worktree 完成修复，沿用现有的 OneGUI 材质能力与分级降级机制，保持学校认证请求的 UA 稳定不变。补丁提交先推送到原 PR 并完成验证，合入 GitHub `main` 后，再在本地通过可恢复快照与三方合并接回未提交的本地开发改动。

**Tech Stack:** TypeScript、React、Rust/Tauri、pnpm、Playwright、GitHub CLI。

## 保护与实施

1. 提前备份本地主仓库与 Harness 子模块的补丁、原始文件及 SHA-256 清单，妥善保留本地构建产物与用户运行数据，远端继续保留 PR 原作者的提交记录。
2. 附件处理：先依据原始文件名校验返回响应是否为正常附件，再根据 MIME 类型补齐缺失后缀，同时保留真实的 HTML 附件与原有扩展名。
3. 光学材质：借助 UA Client Hints 与真实 Blink 引擎特性识别，兼容应用固定的 `Chrome/79` UA；同时保留 WebKit、旧版内核、低资源设备与无障碍模式下的平稳降级。DOM 节点卸载断开后及时释放滤镜、观察器与折射名额。
4. 壁纸备份：归档包同步携带日间与夜间（`day`/`night`）双套壁纸引用，对重复媒体文件做去重复用与容量预算控制，并向后兼容旧版 v2/v3 存档格式。
5. 国际化：将新增与改名词条全部登记至 seed，重新生成词典并验证连续二次生成结果完全一致。
6. 在隔离环境中依次跑通纯函数单测、原生附件校验、真实 Chromium 下的光学生命周期与 UA 识别、日夜壁纸导入导出往返以及 PR 原有回归测试，并完成类型检查与生产构建。
7. 推送补丁更新原 PR 并合入 `main`，随后在本地通过三方合并接回未提交改动，整合通知附件的属性与 URL 解析及 `fjmc` 字段回填，核对 CLI 与 Harness 源码完整性，重新执行共享运行时、附件与类型检查。
8. 归档验收结果与长期记忆并留存恢复快照路径；本轮仅完成仓库合并与本地验证，暂不发布新版安装包。
