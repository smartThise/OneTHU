# 完整模式首次首页与默认模板一致


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 现行功能与使用说明请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

用户反馈在 Windows 上首次打开完整模式时首页排布显得拥挤，手动从模板菜单重新套用“默认首页”后即恢复正常。

## 排查与修复

在全新空存储下启动 Chromium，首次生成的首页像素坐标与默认模板完全一致。进一步排查定位到根因：旧版导览流程会提前写入一份注册表初始默认布局，导致白板首次初始化时将其识别为“已有用户定制”，进而走入旧版四格主栏加窄侧栏的兼容迁移分支；此前已经落盘的旧自动默认白板同样停留在拥挤布局。

- 首次初始化白板时，无论本地尚无存档，还是仅存有旧导览预写的原始注册表默认布局，统一直接调用 `homeStarterItems()` 生成初始排布，确保与手动套用“默认首页”模板完全同源。
- 针对本地已保存的旧白板，仅当条目集合、尺寸规格、像素坐标与宽高、手动调整标记及折叠状态全部精确吻合历史自动默认产物时，才自动升级为新默认布局，并同时兼容“先由旧网格换算像素”与“先注入首页组件”两种历史初始化顺序。
- 横屏与竖屏存档各自独立校验；凡经过手动移动（哪怕 1px）、删除、折叠、固定、透明度调节或规格修改的布局均完整保留，严格比对全量几何与状态字段后再执行升级。
- OnePage 与其余模式维持原有逻辑，正常的默认首页重复加载保持幂等。

## 验证范围

已完成白板数据模型、重置、模板回归及 TypeScript 类型检查。浏览器端测试直接加载真实首页，注入历史自动默认存档后刷新验证自动迁移，再真实点击“模板 → 默认首页”逐项比对像素坐标与宽高，并在 1280、1024、900 CSS px 三档宽度下截图复核。测试在 macOS Chromium 中注入 Windows 平台标识完成，Windows WebView2 真机渲染效果留待实机确认。
