# 组件预览数据隔离修复


有真实用户反馈在首页搜索与白板组件中刷出了内置的“高等数学A(1)”及示例作业、课件条目。排查确认根因位于组件添加抽屉：`PreviewDataProvider` 渲染组件预览卡时直接向全局共享缓存写入了示例数据，并替换了模块级的网络学堂快照；若用户在抽屉尚未关闭前添加真实组件或执行搜索，新挂载的真实组件便会读到这份示例缓存并继续留在 React 状态中。

修复方案采用 React Context 彻底隔离预览数据作用域：由纯函数按需生成只读示例种子集，每个预览抽屉实例各自持有独立的只读数据上下文，而真实业务页面、后台快照更新与异步数据落盘继续读写原有的真实缓存通道。预览态数据钩子全程保持纯内存只读——零订阅真实学堂事件广播、零请求学校线上接口、零写入本地持久化缓存且零触发云同步。供历史浏览器回归脚本注入模拟数据的全局 fixture API 现已严格限定仅在 `DEV` 开发构建下开放（正式生产构建调用时直接拦截拒绝），产品内的组件预览卡片已全面脱离该全局入口。

验收覆盖以下核心场景：真实搜索与白板组件和单个或多个预览抽屉同屏共存时，无论添加新组件还是关闭抽屉，真实与示例数据始终泾渭分明；预览打开期间后台完成的真实数据刷新与持久化缓存完整保留；预览重载（reload）全程零网络请求、零全局广播。测试采用匿名虚构课程夹具，完整覆盖 React StrictMode 双重挂载与中英文实时切换。完成类型检查、状态隔离回归与生产构建验证后，按用户明确指令就地更新 `0.11.1` 正式安装包：保持对外版本号 `0.11.1`，Android `versionCode` 递增至 `11009`，基于同一修复提交重新构建三端安装包并将公开版本 tag 对齐至最新构建源码。

## 执行结果

上下文隔离实现、StrictMode 并发与双语切换验证（9 项）、生产环境边界单元测试、前端生产构建及二级课表浏览器回归（85 项）全部通过。源码修复与三端正式安装包替换均已完成，当前线上 `0.11.1` 统一对应构建源码 `7413291a`，Android 端内部构建号为 `11009`。
