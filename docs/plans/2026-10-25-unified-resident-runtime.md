# Unified Resident Runtime Implementation Plan


**Goal:** 让桌面端、OH 与 CLI 共用同一套登录身份、任务记录与后台调度器，关闭桌面窗口后已授权的常驻任务仍能在后台继续运行。

**Architecture:** 由独立的 Node daemon 持有本机唯一的运行时与标准 profile；桌面端通过仅对主窗口开放的 Rust 私有桥接连接 daemon，OH 则复用桌面服务入口。应用界面中的校园客户端从可信本机接口恢复同一份会话，登录成功、切换账号与退出登录均附带 epoch 版本栅栏完成交接，以常驻后台作为认证态与任务状态的唯一权威来源。

**Tech Stack:** TypeScript/Node SDK、HTTP JSON-RPC loopback、Tauri/Rust、React/OneGUI。

## 决策与边界

- 确立常驻后台为唯一状态所有者，避免双调度器共享文件带来的并发竞态，也避免在桌面端退出瞬间临时搬迁任务可能引发的异常丢单。
- 本机默认标准 profile 继续使用 `OneTHU CLI` 目录，现有的独立 CLI 安装可直接无缝衔接；用户通过 `--data-dir` 显式指定的独立目录则继续保持隔离。
- Node 运行时随 macOS 与 Windows 桌面端安装资源一并分发，构建与加载时严格核对平台、CPU 架构及官方 Node 校验和；Android 端保持原有的应用内运行时。
- daemon 发现令牌保存在本机私有发现文件中，仅由主窗口 Rust 桥接读取；认证快照只走本机可信的 `desktop.*` 私有接口，与对外的 MCP 及插件服务目录完全隔离。
- 依靠持久化的 epoch 计数与显式登出标记拦截过期的旧界面缓存，防止已退出的会话被意外恢复。`bootstrap` 仅用于首次接管，后续显式登录在核验账号一致后完成切换；密码继续沿用原有的本地存储策略，独立会话快照中仅保留会话态。
- 存量旧任务按任务 ID、执行历史及已发送/已下载账簿平滑迁移并记录来源，遇到两侧记录冲突时完整保留双方数据并提示用户处理。桌面端先彻底停用本地调度器再交由后台运行，确保同一时刻只有一个任务管理器工作。
- OH 与 CLI 的执行权限由同一套本机策略统一管控，关闭桌面窗口不影响后台既有授权；一旦撤销授权或退出账号，后台在途任务会立即中止。
- 已配置的 IM 通知凭据迁移后专供后台发送出站通知，保持单一入站轮询链路；已绑定的接收人信息计入通道标识，并在迁移时核验目标一致。

## 实施与验证

1. SDK：更新 `src/node/session.ts`、`src/index.ts` 及任务与通知模块，补充可信桌面私有接口、身份导入/导出、幂等迁移与持久化登出标记；覆盖过期快照、跨账号切换、并发退出、历史去重与接收人绑定测试。
2. CLI：在 `src/daemon.mjs` 中实现私有 `desktop.*` 方法分派及协议版本、构建身份探测；验证 MCP 隔离、未知方法拦截、调用时限与断连取消。
3. 原生桥接：新增 `apps/desktop/src-tauri/src/cli_daemon.rs`，落实主窗口调用限制、发现文件权限核验、独立进程拉起与版本协调，并在桌面打包资源中内置自包含的 Node 与 CLI 产物。
4. 桌面端：`state/cliTasks.ts` 桌面分支统一代理至后台，`lib/clients.ts` 接入会话恢复、登录交接与同步登出，`state/cliRuntime.ts` 对接共享策略，OneGUI 实时展示后台真实运行状态；Android 端沿用原有路径。
5. 存量任务与 IM 配置迁移：迁移成功后写入完成标记，失败时保留原存档并返回明确错误；后台已有同名记录时保留现状并提示冲突。
6. 跑通 SDK、CLI、Rust 原生与桌面端全套检查，重新编译 dev 应用与常驻后台，实测同一任务在 GUI 与 CLI 双端同步可见、关闭应用后后台进程 PID 与任务历史继续生效，且重开应用能够直接恢复同一账号。
7. 同步更新中英文使用文档与共享记忆，如实记录实机测试覆盖范围；本轮专注本地验证，暂不发版，也不对外发送真实预约、邮件或 IM 测试消息。

## AUTH_HANDOFF_UNVERIFIED 修复与实机续验（2026-10-25）

机器重启并重新挂载外置磁盘后，工作区原有改动保持完好；重新编译原生桥接后继续通过 `~/Library/Caches/onethu/OneTHU.app` dev wrapper 开展实测。

### 已确认的原因与修补

- SDK 此前统一过滤了所有 `wengine_vpn_ticket`，而实际上带 `wrdvpn1-` 前缀的票据正是有效 HTTP 会话的一部分。现已保留服务端下发与可信快照中的网关票据，并调用学校只读身份接口核验真实账号归属。
- Info 服务的 Cookie 接口在首次访问对应子系统前往往返回空响应体。核验流程现已加入一次只读入口预热并重新拉取 Cookie，若暂时无法完成核验则安全保留原有会话。
- Info 刷新响应体与底层 HTTP `Set-Cookie` 此前写入了不同的路径层级，导致旧的应用子路径值压过了新下发的根路径值。现已让 `InfoClient` 与身份核验共用同一套解析器，同步更新逻辑域名与 WebVPN 应用路径，同时确保响应正文无法篡改网关票据或注入额外 Cookie 属性。
- 图形端原先仅导出 JavaScript 层可见的 Cookie，漏掉了原生网络层的完整连接状态，恢复时又先清空了原生 Cookie 仓。现已新增仅主窗口可调的完整原生导出与带版本校验的原子导入，待原生层成功落盘后再同步更新两份 JS Cookie jar 与本地会话镜像。
- 将学校登录成功与后台交接状态解耦处理：待交接意图持久化保存，遇到后台短暂未就绪时先保持图形端正常登录并支持后续免密重试交接；一旦用户显式登出或切换账号，则通过版本栅栏立即淘汰旧的交接意图，并在后台延迟恢复完成后主动刷新界面状态。
- 实机首次调用 `learn.courses` 时还暴露出交接后网络学堂 CSRF 令牌尚未初始化的问题，现已补齐统一、可重试的只读 Learn 预热流程（写操作仍保持单次提交不重放）。进程退出时通过关闭标记与网络请求取消干净隔离在途调用，持久化的账号代次保持稳定。
