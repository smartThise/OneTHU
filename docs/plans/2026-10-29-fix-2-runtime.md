# 0.11.4-fix-2：统一应用服务与可选 CLI


## 目标和决定

OH 直接调用应用内置的服务目录与本机授权，面向外部的 CLI/MCP 开关专门用于管控外部进程接入。手机端以及未安装独立 CLI 的桌面端均可直接使用完整的应用内服务与定时任务；按需安装 CLI 后，桌面端与后台常驻进程自动共享同一账号、任务记录及日历与邮箱数据。CLI 默认优先连接正在运行的应用内服务，同时保留显式独立运行的配置能力。

独立 CLI 与 Node 运行时从桌面端默认安装包中剥离，改为按平台提供独立的按需下载 ZIP 包，大幅精简主安装包体积。完整版的新手导览与设置页内置一键安装、状态查看与卸载入口，下载源固定指向本项目官方 Release，并在落盘前后依次核验系统平台、版本号、压缩包整体摘要及包内逐文件哈希。执行卸载时会先平稳停止后台常驻进程并落盘保存运行数据，仅清理运行程序文件，完整保留用户的登录账号与历史任务。

## 实施顺序

1. 对照本地 DSH MadModel 插件实现，修复慢响应重复发送、并发请求堆积与阻塞式续签问题，并补充主动取消、429 限流退避与空响应容错测试。
2. 将 OH 内部任务查询与管理调用同外部 CLI 监听开关解耦，同时继续保留写操作弹窗确认、账号代次校验与任务授权范围限制。
3. 新增私有的账号隔离共享日历文档接口，使桌面 GUI 与后台 SDK 读写同一份日程事件与邮箱配置。首次迁移时自动合并不同 UID 的日程条目，遇到相同 UID 但内容不一致时明确提示冲突；后续每次写入均附带版本号乐观锁校验以保护并发修改，关闭桌面应用后 CLI 仍可无缝读写同一份数据。
4. 实现 CLI 可选组件的安装与生命周期管理，将桌面端恢复为轻量默认包，并同步更新导览流程、设置面板、中英文词典、独立打包脚本与 CI 验收流水线。
5. 完整回归统一认证、移动端 OH、日程双向读写、数据迁移与冲突保护及组件卸载流程，更新版本号与验收报告，构建三端正式包并核对全部更新渠道。

## 验收证据

- 通过本地模拟服务完整验证 MadModel 请求串行化、中途取消与 429 限流退避逻辑，自动化测试全程使用模拟凭据。
- 关闭外部 CLI 监听开关时，应用内 OH 查询与常驻任务照常工作，来自外部进程的请求则被准确拦截；Android 端直接在应用内运行，无需安装 Node 环境。
- 在 GUI 新建日程、由 CLI 修改或删除后再重新打开 GUI，双端读取结果完全一致；切换账号或携带过期版本号的写入请求均被准确拦截。
- 未安装 CLI 时桌面端可直接正常登录，可选组件安装失败时既有登录会话保持完好，卸载 CLI 后用户数据完整保留且应用内服务继续正常运行。
- CI 构建产物已核实不再捆绑 Node 与 CLI 体积，独立 CLI 分发包也顺利通过全新空白目录下的常驻启动冒烟测试。

发布报告中如实区分自动化验证与真机实测情况，并注明待开展 Windows 与 MatePad 实机账号测试的范围。
