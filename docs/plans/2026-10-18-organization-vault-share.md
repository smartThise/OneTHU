# OneTHU 新版本扩展：组织、暂存箱与分享口令（已排队，暂不实现）


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

> 2026-10-18 用户定案：本计划**先存档，不立刻开工**。当前优先收尾 OH / OneFlow / OnePage / OH MCP 的路由与操作审计修复；揪完虫子后再逐步实施本计划。
> UI 口径：继续 Codex / GPT 式美式简约，不另起一套视觉语言。

## 0. 总目标

在现有 OneTHU 基础上扩展三项彼此协同的核心能力：**轻量组织**、**万物暂存箱**与**万物分享口令**，并配套补齐**我的 OneTHU 名片**、**手机碰一碰**以及**通讯录与共享云盘**。底层优先复用校内既有基础设施（清华 GitLab、清华云盘、网络学堂、清华邮箱），无需额外部署自建后端。

## 1. 轻量组织（Group）

- 用户可创建组织、邀请同伴加入，围绕课程学习、项目研发或社团兴趣开展日常协作。
- 依托校内现有服务即可顺畅运转：使用清华 GitLab 承载组织代码库、Issue 与成员权限，使用清华云盘共享团队资料，并与网络学堂和清华邮件自然衔接。
- 每个组织配备专属的**组织名片**（详见 §6），同时作为组织邀请的直观载体。

## 2. OneTHU 暂存箱：万物皆可收纳

- 通用的跨类型内容容器，支持混合放入白板、小组件、摘录文字、本地文件、课程、作业、邮件、新闻、待办、日程、设置项、主题、壁纸、体育场馆信息、图书馆资源、研讨间与公共空间预约状态、选课信息、插件以及组织邀请等各类对象。
- 由清华云盘承担底层文件存储与中转，并通过**内容哈希**自动识别重复文件，多个暂存箱引用同一份文件时只占用一份云端空间。
- 暂存箱本体是一份结构化、可随时增删编辑的内容清单，记录各条目的对象引用与必要元数据，大体积附件则按哈希交由云盘托管。

## 3. OneTHU 口令：万物皆可分享

- 任意暂存箱均可一键生成精炼的分享口令，将**清华云盘分享链接与必要的识别校验信息**紧凑编码在一起，便于跨平台复制发送。
- 接收方将口令粘贴至 OneTHU 后，系统自动识别校验、拉取内容清单、解析各类对象并导入接收方的 OneTHU 环境。
- 每条口令对应云端独立的分享目录，借助清华云盘原生的权限机制管理访问范围、有效期限与随时撤销。
- 口令到期或被主动撤销后，系统在校验时会自动清理对应的分享目录；底层共享文件采用引用计数与哈希去重管理，仅在**没有任何其他有效分享引用**时才会真正从云盘移除。

## 4. 口令与暂存箱的关系

- 收到的口令可直接加载为暂存箱，方便接收方在此基础上继续筛选、编辑或二次整理。
- 尚未生成过任何分享口令的暂存箱遵循临时工作区语义：当该暂存箱被替换或清空删除时，其中未被引用的临时内容随之即时清理，保持本地与云端空间整洁。

## 5. 整体目标

- 组织：凝聚项目与学习同伴，建立清晰的协作关系。
- 暂存箱：将散落在各处的异构内容统一收纳管理。
- 口令：让整组跨类型内容能够轻量分享、跨端传递与一键导入。
- 云盘 + 哈希去重：承担可靠存储、分享中转与文件复用，节省云盘配额。
- 串起一套**零自建后端依赖**、依托清华校内服务稳定运转的团队协作与内容流转体系。

## 6. 我的 OneTHU 名片

- 支持用户自由配置五项核心信息：**头像、个人主页、社交账号、手机号、个人简介**，版面清爽克制。
- 手机号等隐私字段设有独立显隐开关，由用户自主决定每次分享时是否附带。
- 组织名片作为组织邀请的具象化卡片，涵盖组织名称、简介以及加入方式（GitLab 组织地址或共享资料库入口等）。

## 7. （手机）碰一碰

- 接入移动端 NFC 能力；两机触碰时支持自由勾选要传递的内容组合：
  1. 当前暂存箱口令；
  2. 个人名片；
  3. 组织名片（邀请）。
- 发送方可在三项中任意单选或多选；当名片或组合内容体积较大时，系统会自动将整组载荷统一封装为精简短口令后再经 NFC 传递。
- 通讯录：
  - 集中管理已加入的组织名片与收到的好友名片，名片浏览与交换配备利落流畅的美式简约动效。
  - 互加好友后可直接开通双人共享云盘通道，用于投递口令、日常留言、互传文件与课程资料。
- 鉴于上述流转体系深度依托清华云盘，本版本起将**清华云盘设为常驻基础连接**，移除设置页中的手动断开入口并补充清晰说明。

## 7.5 手机版 UI / 交互与动效（用户 2026-10-18 追加）

移动端手势与视觉反馈直接决定核心体验，**需要对手机版 UI 开展系统性升级**，在排期中单独列为一个阶段并纳入整体验收：

- **任意元素拖入暂存箱**：支持从首页卡片、搜索结果、对话消息、邮件、文件、课程、作业、新闻、日程、设置项等任意已接入元素发起长按拖拽；手指拾取时呈现清晰的缩放抬升与跟手浮层，手机屏幕底部常驻悬浮暂存箱目标，随手指靠近依次呈现高亮、磁吸与触感反馈。
- **统一拖放识别**：建立统一的「可拖元素 → 对象类型与引用」识别协议（DOM 属性标记配合对象类型注册表），拖拽过程仅传递轻量引用与摘要；遇到暂不支持收纳的元素时给出明确的回弹提示。
- **克制流畅的动效**：涵盖元素吸入暂存箱的收拢压缩动画、暂存箱抽屉开合、列表滚动、批量收纳层叠动效、异常回弹以及从暂存箱拖回白板的反向展开动画。全部动效严格复用既有设计令牌（时长与缓动曲线），并完整适配 `prefers-reduced-motion`。
- **暂存箱面板形态**：手机端采用贴底上拉抽屉，桌面端提供侧板与浮层面板，支持混合对象列表、按类型筛选、批量勾选与一键生成口令。
- **名片与碰一碰动效**：包含名片展开、翻转、互换动画，NFC 触碰成功后的收拢传递反馈，以及好友共享云盘通道开启时的过渡动效，延续干净利落的美式简约质感。
- **性能与无障碍**：拖拽手势全程保持主线程顺滑响应，长列表启用虚拟化或懒加载，并为键盘与读屏软件用户提供「加入暂存箱」的上下文菜单路径。

## 7.6 对象可拖性 / 统一中转 / 课程共享 / 文字获取（用户 2026-10-18 追加）

前置基础梳理：应用中大量业务条目原本仅面向点击浏览设计，在接入全局拖拽前需要先完成一轮底层盘点，抽象出统一的公共基础层：

- **对象可拖性普查**：逐类盘点白板卡片、搜索结果、邮件与新闻、课程/作业/公告/课件、日程、设置项、主题、壁纸、体育/图书馆/研讨间/选课信息、插件及组织邀请，梳理各自的 DOM 结构、唯一稳定标识、长按选中可行性、纵向滚动手势仲裁以及桌面与手机端差异，整理为「可拖来源登记表」。
- **统一拖拽识别层**：以 `data-vault-catch` 作为统一 DOM 入口标记，配套集中的对象类型注册表（`kind` → 提取器、标题、副标题、去重键与打开方式）；各业务组件只需声明自身类型与主键，由注册表统一构造标准载荷。
- **统一文件中转系统**：构建覆盖上传、下载、流式哈希计算、引用计数与分享目录中转（本地暂存 → 清华云盘 → 分享目录）的公共管线，统一处理断点重试、哈希去重与异常回滚，让桌面文件拖入、剪贴板粘贴、手机系统分享面板与云盘既有文件走同一条稳定通道。
- **课程共享方略**：针对网络学堂的课程、作业、公告与课件制定清晰的分享规范，界定轻量引用与快照边界、访问权限与过期时间、作业学术诚信保护（屏蔽个人作答与评测细节）以及附件体积上限。
- **文字摘录获取**：支持将正文选区、卡片标题摘要、邮件与新闻段落、便笺内容提取为暂存箱文字条目，配套完成富文本与 HTML 清洗、字数上限控制、来源标记与去重。
- **移动端长按与手势边界**：在手机端逐类适配长按拾取（不便直接拖动的复杂视图提供「收进暂存箱」菜单入口），明确拖拽期间的页面滚动锁定、视口边缘自动滚屏以及连接系统级分享面板的交互边界。
- 上述调研结论先整理归档至 `docs/plans/` 与 `docs/research/` 子文档，在暂存箱 UI 全面铺开前率先落地基础层。

## 9. 验收要点（草案）

- 暂存箱可混合收纳任意已注册类型的对象；同一份文件放入多个暂存箱时在云盘仅存一份。

两份前置技术调研已归档入库：
- 云盘、文件通道、口令、课程与文字规范：[seafile-vault-capabilities](../research/2026-10-18-seafile-vault-capabilities.md)

### 10.1 云盘方案定案

- 现有 Seafile 接口已具备文件上传、下载与创建分享链接能力，接下来需补齐**分享链接查询与撤销、密码保护 UI、流式内容哈希、传输进度与取消、回收站清理以及账号级好友共享接口**。
- **优先落地**统一文件通道、Rust 端流式 `file_sha256` 计算与持久化传输队列，基于真实文件哈希实现内容去重与秒传复用。
- 分享口令演进至 Phase 2：保持 `ONV1` 向后兼容读取，新增 `ONV2` 格式（采用 SHA-256 摘要、有效期时间戳、字段白名单与长度上限，且云分享仅编码云盘引用）；云盘适配器通过实测验证「目录级分享 / 密码 / 有效期 / 撤销」链路，若目录分享受服务端策略限制则自动回退为单文件 `manifest` 分享。
- 云盘常驻策略：**保留离线本地读取能力，写入、生成分享口令与新文件入箱统一要求连接清华云盘**；移除设置中的手动断开入口，并在退出登录或切换校园账号时自动清理旧云盘令牌，独立分批上线以保障现有同步平稳过渡。
- 课程、作业、公告与课件仅分享「对象引用 + 标题与截止时间」；个人作业作答、提交记录、成绩、私有会话链接与 OJ 代码一律隔离在分享清单之外，默认设置 7 天有效期。
- 摘录文字条目限制正文 ≤4KB、标题 ≤120 字、摘要 ≤512 字，仅保存纯文本内容并对剪贴板读取给出清晰提示。

### 10.2 手机端方案定案

- 梳理现有代码中的 4 套独立 Pointer 手势实现（原先 300/450/500ms 阈值并存），统一收敛至公共的 `lib/catch/` 基础层（提取器 + 手势竞技场 + 类型注册表），让全局遵循一致的手势判据。
- 统一手势参数：通用长按阈值设为 380–420ms、指针容差 8–10px；白板排布、标签页重排与轮播滑动等强局部语义手势保持更高优先级；未达到长按阈值前完全保持正常页面滚动；进入拖拽态后底栏自动设为 `pointer-events:none` 防止误触。
- 暂存箱悬浮落点：置于独立的 `fixed` 图层（位于底栏之上、模态抽屉之下），保持底栏原有三槽布局舒展；拖拽激活时自动展开，距离 `<120px` 高亮、`<64px` 磁吸并触发触感反馈。
- 移动端跨应用分享统一调用系统原生分享面板（`ACTION_SEND`），契合移动操作系统 WebView 的标准边界。
- NFC 传输采用 Android HCE + ReaderMode 组合（替代已废弃的 Android Beam），无 NFC 硬件的设备与桌面端自动提供二维码、短口令与剪贴板方案；NDEF 解析仅接收通过完整性校验的 `ONV1.`/`ONV2.`/`ONTOUCH1.` 载荷，自动忽略普通外部网页链接。
- 前置优先修复项：动效护栏对齐、补齐手机端根级返回退出命令、统一 `is-phone` 与 `useExpanded` 横竖屏断点、长列表虚拟化以及读屏菜单路径。

### 10.3 Phase 1.5 已落地（本轮）

- `CollectStar` 收藏星标统一接入 `data-vault-catch`，使邮件、新闻、课程、作业、公告、课件、体育场馆、图书馆与研讨间等 60 余处收藏点直接支持长按拖入暂存箱。
