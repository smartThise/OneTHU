# 图书馆座位登录与 token 稳定性排查

> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

> 最后更新：2026-11-18 01:30

## 结论

排查期间匿名访问图书馆座位系统官方首页与馆列表接口均正常返回 HTTP 200，排除了“图书馆整站宕机”的情况；个别手机设备出现的报错需结合客户端会话恢复逻辑、所处网络环境及 WebVPN 通道状态综合定位。

代码审查在当前 `dev3` 分支中确认了两处会导致部分设备登录失败的会话缺陷，现已完成修复并通过本地隔离测试验证。后续待对方设备确认当前安装的包版本、更新至包含本次修复的新版后，即可在实机网络环境下进一步复核。

## 反馈与证据

- 用户本人设备可正常使用，另一位手机用户在查看“我的预约”时遇到报错：`access_token 获取失败（首页无 token，会话可能已失效）`。
- 对方截图中的顶栏仍显示旧式“OneTHU / 首页 / 设置”布局，提示可优先在应用“关于”页核对是否为早期安装包。
- 代码实际请求的首页地址固定为 `https://seat.lib.tsinghua.edu.cn/home/web/f_second`。
- 旧版报错模板在 URL 末尾紧接着拼上了 `）。建议：退出 OneTHU……`，聊天软件或网页在自动识别超链接时容易把紧随其后的中文标点与文字一并编码进链接尾部，导致转述截图中出现 `%EF%BC%89%E3%80%82...`（客户端实际发出的请求仍是干净的固定地址）。新版提示已将请求 URL 从报错正文中移除，避免链接识别粘连。
- 在无 Cookie、未登录状态下直接读取[官方首页](https://seat.lib.tsinghua.edu.cn/home/web/f_second)，服务端仍会返回 HTTP 200 与约 25 KB 的 HTML，其中包含馆区列表以及值为空的 `userid` 和 `access_token` 字面量。
- 同样以匿名状态请求[馆列表](https://seat.lib.tsinghua.edu.cn/api.php/areas/1/tree/1)，也会返回 HTTP 200、`status: 1` 与 `data.list`；该接口本身属于公开馆区目录，无论是否登录都会正常返回数据。
- 公开页面脚本中出现的 `/api.php/check` 属于验证码校验接口，无法用作登录态探针，因此本轮保持原有接口范围，未新增对该路径的调用。

## 已修复

### 匿名目录被误判为已登录

原 `#libAlive()` 仅检查馆列表接口是否返回包含 `list` 的 JSON，而匿名访客同样满足这一条件；一旦 CAS 票据兑付失败，客户端仍会误判为“图书馆会话已建立”，直到用户点开“我的预约”时才暴露出首页缺失 token。

现已改为直接读取官方首页并校验明确的 token 字面量来判定会话存活。探活阶段解析出的 token 与 `userid` 会一并写入缓存供后续读取预约直接复用，省去二次抓取首页的开销；恢复失败时维持原有的两轮有界重试上限。

### 已有 ID 会话的确认页被遗漏

`#roamIdTicket()` 原先仅识别 302 票据跳转或成功页链接，遗漏了 `checkSingle` 二次确认页；确认页提交逻辑此前只写在依赖内存密码的 `#idLoginProbe()` 分支中，导致从持久化状态恢复已有登录态、内存中未保存明文密码的设备无法走完确认流程。

现已将 `checkSingle` 确认页处理并入 SSO 快路径，直接复用既有的确认 POST 与票据兑付方法；当直连 ID 不可达而回退至 WebVPN 时，确认 POST 也会保持在同一 WebVPN 通道内完成。整个恢复过程无需额外索取密码，且保持预约与取消接口行为不变。

### token 解析与诊断

新增纯函数 `parseLibrarySession()`，仅提取结构明确的 token 字面量与参数，兼容无引号、单引号、双引号对象字段以及 `window.ska` 赋值写法；同时移除了原先“在 `access_token` 后盲目匹配下一对引号”的宽松兜底，防止把页面内的 logout 函数或其他 JS 脚本片段误提为登录凭据。

更新 token 时不再沿用上一页残留的旧 `userid`；诊断日志仅记录 token 与用户字段是否存在，严格隐去 token 前缀与具体学号。报错引导文案也更新为“先点击重试，若持续失败再重新登录账号”，无需直接退出整个应用。

`LibraryTab` 内的五处错误提示改为渲染时动态解析应用内建文案，让已经展示在屏幕上的报错也能随语言切换即时更新；学校服务端返回的原始错误原因则保持原样呈现。配套新增的三个中英双语词条已通过独立的 `docs/i18n/library-seat-seed.json` 纳入词典生成流水线。

## 验证

运行 `node tools/library-seat-session-test.mjs`，15 个本地隔离场景全部通过，其中前 7 项针对图书馆座位系统：

1. 准确过滤匿名空值、logout JS 代码片段与外部脚本路径，仅采纳合法 token。
2. 兼容各类对象属性与 `window.ska` 赋值语法，同步提取配套用户标识。
3. 无内存密码但存在已有 ID 会话遇到确认页时，可顺利完成确认并读取预约。
4. ID 直连不可达回退后，确认页请求继续保持在 WebVPN 通道内完成。
5. 匿名公开目录响应不再触发已登录判定，恢复失败严格控制在两轮重试以内。
6. 会话延迟生效时可在第二轮顺利恢复，并发发起的预约查询与馆列表请求共享同一条恢复链。
7. 确认取票失败时返回有界错误提示，全程零额外密码登录或预约写操作。

其余 8 项覆盖同样复用 `#roamIdTicket()` 的紫荆宿舍与图书馆研讨间服务，分别验证 302 票据、成功页锚点、直连确认页与 WebVPN 确认页四类分支，确认会话恢复后零多余座位 token 请求、零额外密码登录或业务写入。

运行 `node --import ./tools/ts-resolve-register.mjs tools/library-seat-i18n-test.mjs`，验证已缓存错误在中英文来回切换时的实时更新、旧版报错字符串兼容、外部服务端原因原样保留、五处界面接线以及三键词典与 seed 的一致性。

`pnpm --filter @onethu/core typecheck` 与 `pnpm --filter @onethu/desktop typecheck` 均通过。

以上测试直接驱动真实的 `InfoClient` 实例并在 HTTP 边界完成本地模拟隔离，全程未使用真实校园账号，未发起实际登录、预约或取消请求，也未读取本机保存的 Cookie 或 Token。

## 后续验收边界

- 待对方手机核对当前 App 版本与网络环境后，需重新打包并安装包含本轮修复的新版 APK 进行实测。
- 若更新后在特定网络下仍有异常，可优先采集脱敏后的阶段状态（ID 是否返回确认页、确认 POST 是否拿到票据、WebVPN 兑付是否成功、座位首页是否仍为空 token），采集时注意排除完整首页 HTML、Cookie、Token 及带有 `ticket` 参数的跳转链接。
- 座位系统的 callback、home 与 book 请求须始终统一走 WebVPN 单通道；即便公网环境能够直接打开座位首页，也应将 `seat.lib` 保留在 WebVPN 路由内，避免直连与 WebVPN 混用造成会话分裂（详见共享记忆与历史提交记录）。
