# 0.11.4 会话恢复修复


**目标：**修复 Windows 端启动恢复阶段卡住登录流程、网络学堂局部异常波及主账号会话，以及迟到的旧探测结果覆盖新会话的问题，同时完整保留统一的 CLI 会话、二次验证与账号 epoch 隔离机制。

**问题现象：**桌面端启动恢复满 10 秒后虽已切出登录页，底层的 `resumeRequest` 却仍在等待后台 daemon 返回 `exportSession`，而 daemon 将该接口排在了耗时较长的完整网络恢复队列之后。同时原生日志记录到学校主身份登录成功，但网络学堂恢复失败、旧版 `student/index` 入口返回 404 以及后续学习接口返回 403。

## 实施顺序

1. 拉起真实的 daemon 子进程并配合挂起的模拟学校请求稳定复现问题，明确修复目标：恢复期间私有快照须即时响应，用户退出登录能够立即打断在途的旧恢复任务，迟到的旧网络响应不得重新激活已退出的账号。
2. 将 daemon 的状态查询、私有快照读取、显式授权的登录交接以及退出登录操作与启动期的联网恢复队列解耦。SDK 启动恢复阶段仅核验学校主身份，把网络学堂子会话推迟到具体学习业务调用前按需建立，并保证恢复流程单飞（single-flight）且严格校验 epoch。
3. 使用独立的学习客户端执行带明确超时的只读启动探测；原生网络请求补齐主动取消与真实的 `timeout_ms` 超时控制，超时后及时释放互斥锁，拦截过期的旧候选结果更新当前 CSRF 令牌，并在同一 epoch 下保护已就绪的桌面端 Cookie 免受后台状态波动覆盖。
4. 更新已失效的网络学堂首页地址常量，复核真实的只读课程列表与详情请求；补充覆盖 WebVPN 网关引导页、401/403 错误、网络挂起、中途登出或切换账号、迟到响应以及并发恢复的回归测试。
5. 跑通统一认证、CLI/SDK、学习会话恢复、账号隔离与全量类型检查，随后更新本机 dev 应用完成真实账号只读验收；报告中将本地自动化验证与待在 Windows 真机上进一步复测的项目清晰分开记录。

## 验收记录

- 主恢复锁解耦、学习探测超时上限与同 epoch 会话保护均已落地；复现夹具中旧版 daemon 触发的 3 项超时用例在新版 daemon 下全部通过。
- Windows CI 实跑期间暴露出的 PowerShell ACL 模块环境依赖与插件退出时的文件句柄占用问题已一并修复，真实 DACL 权限校验与完整 SDK 测试套件全部通过。
- 前端启动阶段无需再阻塞等待 Info 预热及任务、通知同步：先回填本机保存的同账号凭据即刻发布 `ready` 状态，后台异步完成后续同步。SDK 199 项、私有会话交接 13 项与登录状态 67 项测试全部通过。
- 本机 dev 应用同版本刷新后仅需约 99ms 即可完成无感会话恢复，学习页正常加载出 12 门课程，首页今日组件也未再出现登录态报错。
- 最终 Windows 验证构建对应 GitHub Actions `40368403050`、源码提交 `db22eb5a`，安装包校验详情记录于专项修复报告中；当前尚未替换公开版本号与正式分发渠道。
