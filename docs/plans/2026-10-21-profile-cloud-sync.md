# 资料库误报与个人资料跨设备同步


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 现行功能与使用说明请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

## 问题确认

通过只读请求核查真实清华云盘接口返回格式：个人资料库包含 `type=repo, virtual=false, owner=当前账号`，而群组资料库返回 `type=grepo` 且原本就不含 `virtual` 字段。这是 Seafile 服务端对群组库的标准响应格式；旧版前端将个人库的字段要求直接套用到群组库上，因而误触发了客户端版本过旧提示。修正该判定后，个人库归属核验与虚拟子库禁删保护继续照常生效。

与此同时，个人名片、好友索引与本地组织索引此前仅保存在单机 `localStorage` 中；既有的 OH 记忆同步与 GitLab 组织协作各自面向独立业务数据，因此需要为个人资料建立专门的跨设备云盘同步机制。

## 实现范围

- 共享库与群组库直接依据 `type=grepo` 等服务端类型识别归属，无需检查个人库专属的 `virtual` 标记；仅在目标同名个人库归属不明或旧版宿主缺失核心元数据字段时阻止自动建库。
- 新增私有资料库 `OneTHU-Profile`，严格按已验证的云盘账号隔离存储，既保持完全私有（零公开链接或外部共享），也绝不上传登录凭据或 API Key。
- 每台设备各自写入独立的设备记录文件，读取时自动归并个人名片、联系人与组织索引；每个条目维护独立版本号与删除墓碑（tombstone），防止新登录的空设备冲掉既有资料、已删条目意外复活或双端并发写入互相覆盖整张列表。
- 跨设备同步本地组织索引与资源引用；而组织成员身份与协作权限每次仍由当前设备直接向 GitLab 及云盘服务端实时核验。
- 在完整模式启动、修改个人资料及应用切回前台时自动触发拉取与推送，并做定时收敛；极简模式与实用模式保持轻量，跳过加载这批完整模式专属数据。切换账号、切换模式或退出登录时立即拦截在途旧请求，防止跨状态回写。
- 当前设备升级后首次同步会自动迁移本地存量资料；其余设备同样升级至包含该同步功能的版本后，即可上传并汇合各自原有的本地记录。

## 冲突合并规则与交互实现

常规编辑默认自动同步与无感合并：每条记录携带因果上下文与共同祖先摘要，修改不同字段、增删不同成员或项目条目以及合并字符串集合时均自动完成三方合并，仅在“同一字段被并发改成不同值”或“一端删除而另一端修改”等真实冲突下才唤起用户裁决。

真实冲突统一交由全局唯一的 OneGUI ModalHost 呈现，避免多标签页或设置页重复弹出多层遮罩。按用户反馈去掉一切 JSON 源码、字段路径与技术比对表，直接复用真实的 `IdentityCard` 名片视觉：桌面端左右并排、手机端支持左右横滑对比“这台设备 / 另一台设备”，并在卡片下方用自然语言高亮姓名、手机号或具体成员角色等差异项。点击“保留这张名片 / 使用另一张名片”仅裁决存在冲突的字段，其余兼容改动全部保留；涉及删除冲突时清晰标出删除状态。冲突裁决采用明确的二选一交互（底层手动解决接口同样严格限定 `local/remote`），不设“两边都保留”、稍后处理、关闭按钮或点击遮罩 / 按 Escape 跳过；兼容变更继续自动合并，互斥的成员或角色冲突则严格按所选版本落定。其余无冲突条目照常后台同步，各设备仅更新各自的设备文件，保留其他设备的原始快照。此外，组织协作状态与本机权限缓存仅服务于当前设备的服务端实时校验，日常刷新时间戳的推进不会触发同步写入。

原生层在每次同步前后还会对目标资料库执行严格复核：确认归属当前登录账号、库名精确为 `OneTHU-Profile`，且不存在群组挂载、子目录导出、公开外链或对他人共享。考虑到名片头像可能令单次同步体积超出常规文本接口的 2 MB 上限，上传通道采用独立的 12 MB 有界内存缓冲直传，全程不在本地磁盘留下通讯录明文临时文件。

## 验证结果

已完成真实云盘元数据只读核对，归属回归测试继续覆盖“共享写权限不可删库”与“字段缺失时阻止盲目建库”，并新增多设备合并、删除墓碑、并发编辑、空设备保护、账号隔离、模式切换单测，以及挂载真实状态模块配合模拟云盘的双设备端到端验收。真实的 Windows 与 macOS 双机跨端联调仍待在两台实体设备上更新验证。

本轮具体测试结果：

- Seafile 生命周期测试 18 项全部通过：真实群组库缺少 `virtual` 字段时正常放行，同名个人库归属不明时继续安全拦截。
- 合并模型测试全部通过：覆盖空设备保护、多端最终收敛、删除墓碑传播、跨账号隔离、异名字段自动合并、真实冲突强制二选一，以及离线分支基于已合并共同祖先继续演进。
- 模拟认证云盘配合两个隔离浏览器设备上下文完成 16 项端到端检查（直接运行真实名片、组织与同步模块）：包括在切换账号瞬间故意挂起旧账号读取请求，验证晚到的旧响应不会污染新账号；在真实通讯录页面触发唯一冲突弹窗，于 `390×844` 手机视口下横滑查看另一台设备名片，核验仅展示两张版本卡片、按 Escape 保持锁定且无“稍后处理”绕过项，随后点击“使用另一张名片”完成合并收敛，并人工核查桌面与手机端前后截图。
- Rust 原生测试 49 项通过（另有 11 项线上联调测试按既有配置忽略），非法文件名与超大负载在发起网络请求前即被拦截；Windows 异步建窗防死锁护栏通过。
- TypeScript 类型检查与中英文词典完整性检查通过，新增界面文案与翻译种子均已入库并重新生成翻译交接文件。
- 上述双设备浏览器测试运行在 macOS Chromium 的两个隔离实例中（其一注入 Windows 平台标识以覆盖对应前端分支），Windows 物理机环境待后续实机验证；真实云盘核查全程保持只读，未上传、修改或删除任何用户线上资料。

## 升级后同步步骤

macOS 与 Windows 两端均需升级至包含本轮修复的版本：建议先在存有完整历史资料的 Mac 端进入完整模式并连接同一清华云盘账号，待界面提示“名片、好友与组织索引已同步”后，再在 Windows 端通讯录点击“立即同步”（或将窗口切至前台触发自动同步），即可拉取汇合原有本地资料。GitLab 个人访问凭据继续保留在各设备本地独立配置，组织操作权限由各端实时向服务端核验。
