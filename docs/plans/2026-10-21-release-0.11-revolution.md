## 云盘镜像与下载链路（目录规范校准）

清华云盘固定公开分享地址：https://cloud.tsinghua.edu.cn/d/56f78a2a0b144a6ab737/ 。正式目录结构统一固定为 `/Android/`、`/macOS/`、`/Windows/` 三个系统目录（各目录内同时保留 `0.10` 与 `0.11` 安装包），并在分享根目录放置 `SHA256SUMS.txt` 与 `latest.json`。此前按版本号误建的 `/v0.11.0/` 副本目录已清理移除，后续统一沿用按系统分目录结构。

- 官网中英文下载页按操作系统清晰列出版本号、CPU 架构与包体大小：主按钮直连清华云盘对应安装包，副按钮指向 GitHub Release，同时附带云盘目录入口、汇总校验文件与单包 SHA256；官网首页同步提供云盘快捷下载入口，禁用 JS 环境下同样可直接点击下载。
- `tools/check-release-mirrors.py` 以匿名方式读取云盘三个系统目录并按语义版本号选出最新安装包，强制核对其与 GitHub Latest Release 的版本号、字节大小、`SHA256SUMS` 及 Release API digest 完全一致；随后完整下载三个云盘安装包校验实际哈希，并比对双源 `latest.json` 中的各平台路径、版本号与哈希值，发现任何缺漏、版本滞后或摘要偏差即报错退出。
- 官网 Pages 工作流在每次部署前先运行上述校验脚本，刷新 `assets/downloads.json` 后再生成静态页面；每日定时任务或手动触发部署时同样重跑全量核验，并在页面上注明最新核验日期，全程零跨域凭据且不固化易过期的临时 `seafhttp` 下载地址。
- 发布准备流程：先运行 `python3 tools/check-release-mirrors.py --manifests <输出目录>` 生成待发布的双源清单（带 `--manifests` 时专注生成新清单），将生成的 `cloud-latest.json` 更名为 `latest.json` 上传至云盘根目录、`github-latest.json` 更名为 `latest.json` 上传至 GitHub Release 后，再运行不带 `--manifests` 的完整发布门禁做端到端核验。
- 完整发布门禁命令：`python3 tools/check-release-mirrors.py --output ../onethu.github.io/assets/downloads.json`。全程仅访问公开分享链接，无需云盘 Token 或登录态；如遇 GitHub API 匿名速率限制，可传入仅发往 `api.github.com` 的 `GH_TOKEN`。
- 异常路径单测：`python3 tools/check-release-mirrors-test.py` 全部通过，覆盖版本号排序、缺包、旧版残留、字节数不符及哈希不匹配等拦截场景。
- 客户端更新器实测：`node tools/update-sources-live-test.mjs` 直接加载真实的 `updater.ts` 逻辑（仅将 Tauri HTTP 桥替换为只读网络适配器），三平台双源清单读取及模拟 GitHub 故障自动回退云盘全部通过（`hashAvailable=true`），测试过程不触发实际安装 IPC。
- 官网下载页浏览器验收：`node tools/site-download-browser-test.mjs` 覆盖 `320/390/768/1440` 四档宽度、中英文双语及禁用 JavaScript 共 8 组矩阵，逐项确认直链可达、按钮触控尺寸合规、零横向溢出及哈希折叠展开正常，截图归档于 `/Volumes/OneTHUBuild/artifacts/release-0.11/download-page/`。
