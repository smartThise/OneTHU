# OH 学校模型请求修复


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

用户已授权参照 DSH 的请求模型立即收敛并发问题。根据 2026-10-20 的诊断结果：旧版流式请求每隔 3 秒便会额外派生一次未取消的 POST，单次用户提问最多可同时堆积 4 个在途请求；在本机搭建延迟响应且并发上限为 3 的模拟接口即可稳定复现 429 限流报错。

## 实现范围

1. 彻底移除请求竞速逻辑，确保单次 HTTP 请求与流式响应读取均可随时取消；遇到临时错误时，仅在尚未输出任何内容的前提下执行有界串行退避并严格遵守 `Retry-After`，一旦已有文本或工具调用输出则直接报错终止，避免重复重放。
2. 桌面端与移动端宿主共用同一套单飞运行门禁，每轮对话持有独立的取消标志；运行期间拒绝新发起的请求，直到上一轮任务在后端真实退出后才释放门禁，取消旧有的按超时强行接管与共享标志重置逻辑。
3. 认证校验明确区分凭证有效、凭证确已失效与临时网络抖动三类状态；网络波动和 429 限流不再误触发强制重新续签，路由探测与 Cookie 维护各自独立刷新。
4. 前端界面严格以后端完成事件为准结束运行态，取消按钮同时覆盖发送前预检与在途流式请求两个阶段；遇到 429 时保留服务端原始错误并提供原消息重试入口，将续签按钮收敛至登录凭证刷新场景。
5. 同步重新构建桌面 bundled sidecar 并更新当前 dev 安装包，逐一核对版本号与二进制哈希。

## 验收

- 服务端响应耗时超过 3 秒时，客户端全程仅发出唯一一次请求。
- 触发 429 后的多次重试严格串行执行、彼此零重叠，并按服务端返回的等待时长退避。
- 在等待响应头、读取流式分块以及退避等待三个阶段点击取消，服务端均可立即观测到连接断开。
- 已经产生流式输出后若连接中断，直接报错结束，零自动重放。
- 覆盖运行期重复提交拦截、单轮运行超过 15 秒保持稳定、取消后立即发起新对话以及前端预检阶段取消。
- Rust 核心库与 sidecar 单元测试、TypeScript 类型检查及相关 UI 守卫全部通过。
- 错误与高并发路径全部通过本机模拟服务覆盖，避免对学校线上模型服务造成压测负担。

## 完成记录（2026-10-20）

- 推理传输层改为同线程驱动的异步 HTTP，点击取消会直接丢弃在途请求与响应流，零残留后台线程。响应头超时设为 60 秒、流空闲超时设为 120 秒；最多执行 3 次串行尝试并严格遵循 `Retry-After`。一旦已产生正文、思考过程或工具调用增量便停止自动重放；遇到被截断的工具参数直接按失败处理，防止执行不完整的工具调用。
- sidecar 与内嵌宿主共享统一的每轮门禁机制，取消操作按 `runId` 精准定位目标轮次；任务运行期间会拦截重复提交以及新建、切换、删除、导入或恢复会话操作，稳妥保护正在执行的任务。进度事件全程携带 `runId`，防止后台 IM 触发的对话结果混入本地正在预检的会话。
- token 校验准确区分明确失效与暂时性网络故障，预检、路由探测与凭证签发三路各自合并并发请求（singleflight）。临时失败进入退避期时保留上一次成功验证记录，而在等待期间已过期的 token 则严格拦截；网络切换后迟到的旧路由探测结果也会自动丢弃，确保最新路由结果生效。
- 前端取消逻辑贯穿预检与流式运行两个阶段，必须收到后端真实结束信号后才复位运行状态。限流提示卡完整展示服务端响应并支持一键重试当前消息；事件缓冲区采用单调递增序号，单轮事件超过 300 条的长回复依然能够完整连续渲染。
