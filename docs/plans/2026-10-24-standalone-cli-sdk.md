# OneTHU 独立 CLI / SDK 实施计划


**目标：** 让 CLI 支持独立安装、构建、登录并直接运行学校服务与无界面插件；桌面端复用同一套 SDK 并叠加图形界面，MCP 同样接入相同的服务入口。

**架构：** `@onethu/core` 与 `@onethu/info-lib` 继续承载学校底层协议；新增 `@onethu/sdk` 统一管理会话宿主、结构化学校服务、执行策略、课程资料归档与插件生命周期；`@onethu/cli` 则提供终端命令与 MCP 协议封装。桌面应用向 SDK 注入原生网络、文件与弹窗确认实现，独立运行时则注入纯 Node 实现。

**技术：** 基于 TypeScript 与 Node.js 20.18.1+，复用现有学校 SDK，采用 ESM 格式分发并封装跨平台文件存储与子进程管理。CLI 默认独立运行，传入 `--desktop` 时显式连接正在运行的桌面端服务。

## 决策与权衡

1. 终端命令统一命名为 OneTHU CLI，可嵌入包命名为 OneTHU SDK，MCP 则明确定位为工具接入协议，三者层次分明。
2. 从现有业务代码中提炼可注入的宿主环境接口，使桌面与 Node 共用同一套学校解析逻辑，Node 端登录直接复用最新的 InfoHelper 认证链。
3. 独立 CLI 维护专属的数据目录与稳定设备指纹，账号及 Cookie 仅写入本机私有目录并通过进程锁保障并发安全，与桌面端本地密文存储相互独立。连接桌面端需显式开启，异常回退时严格保持在同一账号内。
4. 自动执行设为设备本机授权开关，桌面端默认关闭，独立 CLI 可由用户显式配置。开启后免去逐次人工确认，同时继续执行权限核对、账号匹配、调用时限校验以及结果未明时停止重试等安全守卫；该开关仅限本机用户配置，与 MCP 及插件调用隔离。
5. 插件沿用既有的 JS / Rust manifest 规范与命令协议，安装阶段仅做静态清单校验（无需执行插件代码）并默认保持禁用，启用后运行经用户认可的本地插件代码；纯图形界面接口则通过明确的 capability 标识予以区分。
6. 能力目录完整公布各接口的参数结构与宿主支持范围，清晰标注依赖图形界面的专属操作，仅对外开放已打通的真实服务。

## 实施与验证

### 1. Node 会话
- 新增 `packages/sdk/src/node/`、`src/auth/` 与 `test/auth*`。
- 复用 InfoHelper 的 SM2 加密、稳定设备指纹与二次验证流程，完整提供 restore/login/2fa/logout/status 能力。
- 验证 Cookie 跳转跟踪、安全落盘与独占进程锁、退出清理及敏感字段脱敏；自动化测试全程在本地模拟环境中运行，把短信验证码发送与信任设备登记留给用户实际登录时操作。

### 2. 共享服务
- 将网络学堂完整资料服务下沉至 SDK，桌面端文件系统读写改为通过适配器注入。
- 统一共享能力目录、参数校验与结果脱敏，在 Node 环境下完整适配学校查询、场馆与研讨间预约、日历、云盘等无界面服务。
- 资料下载继续执行校园域名校验、账号代次约束、超时控制、同名文件保护与 SHA-256 哈希核验。
- 对齐上一轮 CLI 测试用例，并补充脱离桌面进程的纯独立运行测试。

### 3. 插件
- 新增 `packages/sdk/src/plugins/`，支持本地插件包的 inspect/install/list/enable/disable/commands/call/uninstall 全生命周期管理。
- 通过 JS 子进程与既有的 Rust JSON-RPC 承载插件运行，并严格按 manifest 声明的权限转发 SDK 调用。
- 校验插件 ZIP 包的路径边界、解压大小、CRC、符号链接与平台入口；使用自建测试插件完成端到端验收，并梳理图形界面专属能力的提示方式。

### 4. 终端与 MCP
- CLI 默认拉起独立 SDK 运行，同时保留显式连接桌面端的 `--desktop` 模式。
- 交互式登录从终端安全读取密码与二次验证码；自动化脚本可通过 `stdin` 传入凭据，避免密码暴露在命令行参数中。
- MCP stdio 模式直接挂载 SDK 实例；HTTP 模式仅监听本机回环地址并校验本地私有凭据，拦截来自浏览器的跨域请求。
- 提供 standalone build / pack 打包脚本，将编译产物完整随包内置，脱离源码仓库也可直接安装运行。

### 5. 桌面授权与交付
- 将执行策略抽成纯逻辑模块供桌面端与 Node 端共用，并在高级设置中新增本机自动执行开关与清晰的中英文说明。
- 将该开关的修改入口严格限定在本机界面，与云同步、远程指令和插件完全隔离；关闭开关时立即中止尚未提交的待执行请求。
- 完成全量测试、双语文档、能力对照表、独立安装验收并同步更新共享记忆。

本计划在当前工作区既有改动的基础上接续推进，完整保留已完成的代码，待实测通过后如实记录验收状态。

## 2026-10-25 实施记录

本轮在既有 CLI/MCP、MadModel 与学习资料修复的本地开发基础上继续完成开发与验证，保持当前分支与工作区改动完好，暂未执行新版本发布。

### 已落地

- `packages/sdk`：实现独立 Node 会话与 2FA 流程、稳定设备指纹、本机私有存储及目录锁；直接复用学校底层协议，集中注册网络学堂、场地预约、校园信息、选课、邮箱、CalDAV、云盘、GitLab、外部作业与本地记忆服务。
- `packages/cli`：默认独立运行，传入 `--desktop` 时复用桌面图形宿主；支持终端登录、只读目录与 Schema 查询、服务调用、课程归档及 stdio MCP，并配齐内含 SDK bundle 的 macOS/Windows 安装脚本。
- 设备自动执行策略：采用本机开关控制，默认逐次确认；在最终提交前统一核对调用来源、权限范围、账号 epoch 与截止时间，且仅允许本机直接修改开关状态。
- 共享任务引擎：支持 interval/daily/once 定时规则、课程资源变更巡检、DDL 提醒、增量下载、通知通道授权、持久化执行历史与暂停取消；只读操作支持有限重试，结果未明的外部写操作停止自动重放。
- 独立 daemon：采用私有令牌与随机回环端口，供 CLI 自动发现复用，支持前后台运行及当前用户的 macOS LaunchAgent / Windows 计划任务自启动注册。
- 插件：支持从本地目录或 ZIP 安装，经静态 manifest 审核后默认禁用，运行时提供 JS worker 与 Rust JSON-RPC 双通道及取消、账号校验能力，在当前用户权限下运行经用户启用确认的本地插件代码。
- 通知与 IM：打通本机收件箱、飞书、微信 iLink 与 HTTPS webhook，实现私聊对象固定绑定、事件去重、指令取消与断线重连，任务通知严格投递至已绑定的接收者 ID。
- 自然语言助手：支持接入用户自填的 OpenAI 兼容 API，受显式工具范围、轮次与费用预算及短会话记忆约束；MadModel 登录与微信扫码继续沿用桌面嵌入界面及已同步的本地凭据。
- 桌面端：基于 OneGUI 提供常驻任务列表、课程选择、归档目录与通知通道配置，支持新建、编辑、暂停、立即运行、查看历史与本机收件箱，原生下载支持中途取消；OH 内建任务管理工具也在收尾核查中一并补齐。
- 独立分发：CLI 安装包内置完整运行产物；SDK 单独打包出脱离 workspace 内部依赖的 `.tgz` 与公开类型声明，并随附项目与第三方开源许可。

### 设计依据

任务系统参考了 Hermes 的定时任务持久化、执行与投递设计，以及 OpenClaw 的任务生命周期、持续会话与通知对象绑定思路，在 OneTHU 内部独立实现了调度器与宿主适配接口。确定性的学校巡检逻辑与大模型工具循环解耦，日常定时检查无需消耗模型调用。

实现过程中同步加固了多处跨模块边界：仅允许实际持锁方释放并发写锁；异步等待授权返回后再次核验账号 epoch；插件反向调用宿主时全程保留原始账号守卫；HTTP 连接断开时联动取消在途操作；daemon 遇到非法令牌时返回鉴权错误并保持进程稳定；SDK 关闭时即使遇到存储异常也确保释放进程锁与目录锁；自动执行配置须成功落盘后才生效；IM 通道在宿主关闭阶段等待初始化任务排空后再退出。

### 验证原则与边界

自动化验证统一使用合成学校响应、本机 HTTP/WebSocket、隔离数据目录与真实子进程，全程无需注册真实信任设备、提交学校预约或发送真实邮件与 IM 消息；独立运行时的端到端测试结果与早先桌面伴随式 CLI 的真实下载记录分开归档说明。

UI 验收覆盖真实组件在中英文 1440px 宽屏与 390/430px 窄窗下的完整点击交互，验收报告存档于 `output/cli-task-ui-fixture/QA.md`。Windows WebView、文件 ACL、开机自启、独立模式下的学校真机登录以及真实 IM 与外部模型联调留待后续实机测试；免打扰静默时段、登录失效去重提醒以及其余纯 GUI 页面的 SDK 化排入后续迭代。
