# 登录二次认证页与登录前语言切换


## 现场表现与排查范围

Windows 0.11 的现场日志显示：OAuth 登录页返回 `HTTP 200`（`17524` 字符），SM2 凭据 POST 正常发出并收到 `HTTP 200`（`1661` 字符），紧接着落入 `unexpected-page / credential-entry`。这说明认证请求已顺利发出并收到服务端响应，单凭脱敏日志摘要尚不足以直接区分具体页面形态。

结合源码审查定位到一处可复现回归：学校 React 版二次认证页在首屏 HTML 中可能仅带有 `<title>二次认证</title>`，而正文区域只有空的挂载节点；新引入的 `isFinishedIdEntry` 仅扫描可见正文而忽略了页面标题，从而直接阻断后续 2FA 流程（旧版自有认证代码此前已有针对该页面形态的兼容记录）。在离线测试中构造同形页面，修改前可稳定复现同一错误及单次凭据 POST。由于现场脱敏日志不含响应正文，那 `1661` 字符是否确属此类空壳二次认证页，有待用户安装 Windows 新包后实测确认。

## 修改内容

- 登录与 ID 漫游流程统一识别可见 `<title>` 及正文中的二次认证标记，同时支持解码 HTML 字符实体，且跳过 `<script>` 内容；若页面中存在密码表单、公钥表单或明确的学校错误提示，则优先按对应凭据页或错误页归类。全程保持单次提交，不重放密码或新增自动重试。
- 在登录表单、2FA 方式选择与验证码输入三个界面顶部加入 OneGUI 语言切换控件：入口采用双语标识，候选项读取既有语言注册表，顺排在表单上方的正常文档流中以避免遮挡输入区。
- 语言切换直接复用全局语言偏好与持久化机制；切换瞬间完整保留已填写的账号、密码、验证方式、信任设备勾选项与验证码，且零网络请求开销。
- 应用状态保存结构化错误原因，由渲染层的纯格式化函数实时按当前语言展示，同时在捕获瞬间记录诊断摘要；学校服务端返回的原始错误详情保持原样呈现。
- Android 对外版本号保持 `0.11.0`，内部 `versionCode` 递增至 `11003`，沿用正式发布签名证书。

## 后续修复：首次登录回退与残留冷却

用户随后在 Windows 上实测反馈：首次登录进入主界面后立即被退回登录页，等待 20 秒再次登录才成功。现场诊断日志显示网络学堂返回 `id-login-link`，而稍后的日志已正常拉取到 79 条作业、27 条通知与 61 个文件——可见主会话本身已建立成功，只是单个网络学堂子会话恢复受阻时触发了整站退出。初版浏览器验收仅检查离开登录页的瞬间状态，遗漏了进入首页后的数据加载阶段，本轮一并补齐该验收覆盖：

- 当主认证链真正走完时，由当前 `attempt` 的成功钩子立即清零本轮登录冷却；密码错误、未知认证页与受限请求则继续保留节流保护，且延迟完成的旧认证链禁止清理后续新链的冷却门禁。
- 校园信息、网络学堂数据与学期列表在会话恢复失败时仅在各自模块内展示服务错误，保持主界面稳定在线，移除这些业务数据 hook 中直接调用的 `backToLogin()`。
- 并发触发会话恢复时优先复用已在途的恢复 Promise，待其结算后再评估下一轮节流状态，防止第二个数据 hook 在首个恢复尚未完成时被提前拦回。
- 受信设备直登与新完成 2FA 的会话共用同一套网络学堂预热逻辑，统一完成子会话准备后再切入主界面；单一校园子服务暂时不可用时仅作局部提示，保留已通过的主认证态。
- 已挂载宿主统一认证 hook 的 `LearnClient` 严格走宿主通道，不再回落到旧版独立账密登录分支，避免绕过统一冷却门禁或打断进行中的 2FA；无宿主的独立脚本客户端保留原路径。
- 针对现场日志暴露出 URL 矩阵参数（如 `;jsessionid=`）仍可能携带 Java 会话标识的问题，JS 与 Rust 两侧日志脱敏器现已同步剥离明文及百分号编码的矩阵参数，实际发出的请求地址保持不变。

补充验证：生产构建浏览器测试增至 117 项全部通过，完整覆盖受信直登、微信与 TOTP 验证、故意缺失学堂子会话、等待真实业务数据 hook 报错后主界面保持在线、登录成功后冷却清零及零密码重放；另有恢复行为 7 项、门禁与指纹 28 项、认证行为 30 项、JS 日志隐私 23 项、Rust `native_security` 11 项以及类型检查与生产构建全部通过。受影响 Windows 设备上的真实校园账号表现待用户安装新版后最终确认。

此前基于 `6a5803ff` 构建的 macOS/APK 安装包及 Windows Actions `39597291885` 尚未上传即收到上述新反馈，该批次已标记为 **DO-NOT-PUBLISH** 并作废，改用合入本次修复后的同一提交重新构建三端；正式渠道在此期间一直维持上一版稳定安装包在线。
