# 导览权限须知与许可闸门


## 用户要求与落地

- 无论首次启动、从帮助页重播导览还是在设置中重置导览，统一从双语第 −1 步启动，完整顺序为「权限须知 → 语言选择 → 三模式导览」。完成一次后常规重启应用直接进入主界面；从缺少许可记录的旧版本升级后会补看一次，所有可选权限初始均交由用户本人决定。
- 云盘与 OH 智能体两项服务独立开关，初始状态均为关闭。用户勾选确认已阅读须知后方可保存并继续，且可自由拒绝任一可选项；授权结果仅保存在当前设备本地，与云端同步完全隔离。
- 未开启云盘授权时，完整模式在导览入口、设置页及底层状态 setter 处均锁定拦回并说明原因；用户原有的完整模式偏好与白板布局数据妥善保留在本地，运行期自动回退至实用模式，后续开启云盘授权即可无损恢复原设置。
- 在云盘许可说明、未授权提示页、未连接引导页、资料库列表与目录浏览页统一展示「如果想要撤销授权，请前往设置重新导览。」及“重新导览”快捷按钮，中英文文案同步配备。
- 三种模式的设置页均支持随时查看与调整授权状态；撤回授权时完整保留本机名片、好友、组织、白板布局及云端既有文件。

## 数据流向与权限范围

OneTHU 是运行在用户设备上的本地客户端：界面渲染、核心业务逻辑与数据缓存均驻留本机，校园会话及用户选择记住的凭据也保存在本地存储中；当使用校园信息功能或用户主动启用的外部服务时，客户端通过原生网络层直接连接学校接口与对应目标服务。

开启云盘授权后，客户端可读取云盘账号信息、资料库列表及用户主动打开的文件；跨设备同步、组织与好友协作通道、短口令分享等功能会按需创建并维护专用资料库或文件，用户主动发起的上传、删除与共享操作也会同步写入云盘。权限须知据此如实说明读写范围：开启云盘总许可仅开放上述专库维护与用户主动操作，用户云盘中既有的其他私人文件保持原状，且 OH 智能体的写操作仍须走独立的逐次确认机制。

开启 OH 智能体授权后，对话消息、附件及回答问题所需的工具返回结果会发送给用户所选的大模型服务、清小搭或自行配置的 API / MCP / IM 端点，相应外部数据处理适用各服务提供方自身的隐私政策。客户端继续保留敏感操作确认拦截，提醒用户避免输入密码、验证码等机密信息，并将外部网页或技能包中的文本严格作为不可信数据处理，一切权限变更均以用户本人在界面上的操作为准。

## 实现与防绕过设计

- `state/privacyConsent.ts`：采用默认关闭、分项独立授权与串行落盘机制，仅在原生层成功写入文件后才向内存态放行权限。桌面与移动原生端以受保护的本地文件为唯一权威源，`localStorage` 仅作前端只读镜像；纯浏览器测试环境则使用隔离的本地存储夹具。
- `src-tauri/src/privacy_consent.rs`：原生进程启动时立即加载许可文件，文件缺失或校验损坏时一律按未授权处理；修改命令仅接受来自 `main` 主窗口的调用，且许可文件独立存放在通用 `state_write` 可写目录之外。
- 原生 Seafile 公共客户端入口统一挂载许可拦截，全面覆盖资料库列举、目录浏览、文件读取、上传、删除、共享与权限管理，同时拦住云盘 profile SSO 及获取 token 的内置 WebView 通道。
- 通用原生 HTTP 通道对重定向逐跳核验目标域名（含清华 WebVPN 封装下的云盘加密路径），附件下载与二进制预览接口同样执行目标域名与重定向检查。
- 客户端检查官方应用更新时使用专用的匿名无状态客户端（不携带任何 Cookie 或 `Authorization` 头），仅放行官方公开分享目录及其下属安装包下载路径；即便用户拒绝私有云盘授权，软件版本检查与更新下载依然正常可用。
- 前端 token 读取器在未获云盘授权时屏蔽本地已存口令，自动重连与后台同步一并静默停用，撤回授权瞬间立即作废所有在途响应。同时将账号身份版本号与许可修订号拆分为两条独立计数，确保撤回授权时完整保留本地个人资料，仅在真正切换校园账号时执行账号清理。
- OH 桌面端 sidecar 与移动端 embedded 运行时在 `run` 入口前置校验许可，并在工具桥每次执行前二次复核；一旦用户撤回授权，立即中止当前对话并关停 OH 运行时，日后重新开启授权时自动恢复原有的插件开关配置。MCP 配置读写同样纳入该许可门禁。
- 上述许可闸门精准管控 OneTHU 内置云盘通道与 OH 工具桥；用户在安装第三方插件或技能包时仍应甄别可信来源。撤回授权会立即阻断后续新请求，此前已送达外部服务的数据或已在远端完成的操作则遵循对应外部服务自身的管理规则。

## dev 原生预览附带修复

重编本地 macOS 开发预览版后，捕获到一处原生崩溃栈位于 `overlay_win::macos_prevent_activation`：此前将 IPC 改为异步后，代码在 Tokio 工作线程中直接调用了 AppKit 的 `_setPreventsActivation:`，触发 macOS `NSWMWindowCoordinator` 的主线程断言（`SIGTRAP`）。现已将该窗口属性设置派发回主线程执行，并新增窗口线程静态护栏；重编启动后确认应用进程持续稳定驻留，并通过 CUA 在真实 OneTHU 原生窗口中核验双语许可页正常显示（验证全程保持用户原有本地许可状态未动，并在 `open` 命令返回零退出码后继续核验窗口持续驻留）。
