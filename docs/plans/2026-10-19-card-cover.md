# 名片自定义卡面（2026-10-19）


> 归档说明：本文记录当时的设计方案与阶段性验收情况；0.11 当前功能与使用指南请查阅 [文档入口](../README.md)（[English overview](../en/index.md)）。

需求背景：支持上传并自定义个人名片的背景卡面图片，可自由拖拽调整取景位置与缩放比例、自动备份至清华云盘，并根据卡面背景明暗自动切换清晰可读的黑/白字色。

## 数据结构

`state/nameCard.ts` 中为 `PersonalCard` 扩展可选字段 `cover?: CardCover`：
```ts
{ src: string;        // 压缩后的 JPEG dataURL（随名片口令一起带出去）
  focusX/focusY: 0..1 // 取景焦点
  zoom: 1..2.5
  ink: "light" | "dark" // 自动/手选的字色
  cloud?: { repoId; path; shareUrl? } // 云盘备份位置
  updatedAt }
```
- 保存时自动对焦点与缩放范围做边界收敛，并将编码后的图片体积控制在 1.5MB 字符以内；`contentExchange.personalShareCode` 的 `contentKey` 纳入 `cover.updatedAt`，更换卡面后会自动就地刷新固定名片口令对应的云端清单，原口令编码保持不变。
- 卡面随暂存箱、碰一碰与名片口令载荷一并携带，接收方即使处于离线状态也能立即看到完整封面。

## 卡面编辑器（`components/CardCoverEditor.tsx`）

操作流程：选择本地图片 → 客户端自适应压缩（长边 ≤1600px，动态调节 JPEG 质量以落入体积上限）→ 在预览卡片上直接拖拽取景并滑动调节缩放 → 选择字色模式（自动 / 白字 / 黑字）→ 保存或移除封面。编辑器预览框采用与「我的名片」主页一致的 hero 档 540px 宽度上限，确保编辑时所见的构图与字号比例同最终展示完全一致。

## 自动字色与对比度计算

- 按名片文字实际分布的三个重点区域加权采样：顶部品牌行、中部姓名带与底部联系方式行。优先检查姓名带与底部区域：任一区域亮度 `< 0.3` 时选用白字；两处均明亮时选用黑字；中间过渡地带则分别计算叠加渐变蒙层后白字与黑字方案的实际对比度，自动选取对比度更高的一方。
- 配套渐变蒙层：白字方案叠加柔和压暗蒙层（顶部 34% → 底部 64%），黑字方案叠加柔和提亮蒙层（顶部 34% → 底部 58%），兼顾画面通透感与文字清晰度。
- 手动指定：遇到局部光影反差较大的实拍照片时，用户也可以随时手动切换为固定白字或黑字。

## 云盘备份（`lib/cardCover.ts`）

保存卡面时同步上传至 `OneTHU` 资料库的 `/Cards/cover-<时间>.jpg`（依次调用 `ensureOneThuRepo`、`write_temp_file` 与 `seafile_upload`），尝试生成长期分享链接并将 `cloud` 引用写入名片记录。更换或移除封面时会自动清理云盘旧图；若当前尚未连接云盘，本地卡面依然即时生效，并温和提示「到云盘页确认登录后重试」。

## 细节排查：协同全局自动文字对比度引擎

全局对比度引擎 `lib/textContrast.ts` 会遍历带文本的 DOM 元素，依据纯 CSS 背景色计算可读字色并写入**内联 `color` 样式**。由于该扫描器不解析底层 `<img>` 封面像素，原先会将带封面的名片视作浅色底并统一覆写为黑字。解决方案是为启用了自定义封面的名片容器添加 `data-tx="keep"` 标记（让 `settle` 与 `settleIcon` 主动跳过该子树），同时在卡面专属字色规则中配合 `!important` 覆盖历史残留的内联字色。

## 测试

`tools/namecard-browser-test.mjs` 共 23 条断言全部通过：涵盖纯白底图自动黑字、纯黑底图自动白字、上亮下暗实景照片自动白字、手动切换黑/白字时计算样式实时生效、封面文件准确写入模拟云盘 `/Cards/` 目录，以及深色封面正确挂载 `is-cover-light` 类名；全量 `pnpm guard` 绿灯通过。
