# 当前 Mac 的系统浏览器接入


面向用户的核心目标很直接：直接用日常习惯的系统浏览器打开校园网网址，免装浏览器扩展，也无需切换到单独的校园浏览器窗口；同时与机器上已有的网络代理和平共存，并根据 Windows、macOS、Android 各自的系统机制分别适配。

## 接入与代理共存

在 macOS 上，网关会逐一读取每个启用中网络服务的现有 HTTP、HTTPS、SOCKS 代理及绕过列表，动态合成对应的 PAC 脚本：白名单内的校园域名发往 OneTHU 本机监听端口，其余所有网址原样走该网络服务原先配置的代理或直连出口。原有绕过列表中的域名通配符、IPv4 CIDR 网段以及 macOS 默认的 `169.254/16` 简写规则均完整保留。

浏览器直接访问 `id.tsinghua.edu.cn` 与 `oauth.tsinghua.edu.cn` 统一身份站点时，继续沿用原有的代理或直连路径，与共享会话代理解耦；用户可以在日常浏览器里正常使用自己原有的登录态、修改账号设置或管理信任设备。SDK 内部的统一认证依然由既有账号运行时独立维护，这两个身份站点在浏览器侧的 Cookie 与 OneTHU 完全隔离。

修改系统网络设置前先写入预写恢复日志（WAL），随后安装 PAC 脚本并切停该服务的手动代理开关。停止网关时按字段逐一比对还原：若检测到用户或 Clash 等工具在运行期间主动调整了某项系统代理设置，便保留这项外部新改动并如实汇报状态，避免反复覆写争抢系统配置；任何底层网络配置发生变动后，再次启动前都会重新生成适配计划。若检测到系统当前已挂载自定义 PAC/WPAD、带密码鉴权的手动代理或 PAC 语法无法等价表达的特殊绕过规则，网关会明确提示并保持现有网络连接原封不动。

独立校园浏览器继续保留为免改系统设置的可选调试入口，系统浏览器接入则启用单独的本机监听端口。macOS 系统监听端口通过底层 TCP 套接字反查发起连接的进程 UID，核实与运行 OneTHU 的当前系统用户一致后再放行，并对每条浏览器请求逐一校验来源、目标主机与账号 epoch。这样既将校园会话严格限定在当前登录的系统用户下，又省去了在各个浏览器里弹出代理账号密码输入框的繁琐步骤。

本机根证书为当前安装实例独享生成，私钥安全保存在用户私有目录中。经用户明确确认并写入系统钥匙串信任后，日常浏览器即可直接通过操作系统标准信任链完成 TLS 握手，无需传入任何忽略证书校验的危险启动参数。与此同时，SDK 与原生层的校内上行传输继续走各自的直连通道，防止流量回流进本机代理造成死循环。

## 网页兼容与真实验收

网络学堂与信息门户前端所需的 `XSRF-TOKEN` 按各自站点的精确域名与路径作用域定向投影，核心认证 Cookie 则始终留在后台共享运行时中。图书馆等子系统可通过当前会话的只读预热接口自动初始化业务身份；一旦遇到认证过期或缺失，便引导用户回到 OneTHU 主界面完成登录，由共享运行时统一管理账号生命周期。选课系统等纯 HTTP 上游则通过本机 HTTPS 门面平稳映射承接。

实机验收要求完整走通真实的用户交互链路：在日常浏览器中点击课程卡片、顺畅拉起新标签页，并核对渲染出的页面内容与接口返回的真实业务数据。若学校页面弹出原生 `alert` 提示框，需如实记录触发原因并在可见窗口下核对交互体验。

## 平台覆盖

| 平台 | 本轮实现范围 | 已有代理策略 | 尚须完成 |
| --- | --- | --- | --- |
| macOS | 系统 PAC、用户证书信任、同 UID 连接鉴权、Chrome/Safari 实机验证 | 按服务保留手动 HTTP/HTTPS/SOCKS 与绕过规则；检测配置被其他软件修改 | 真实启用/恢复及具体校园业务逐站记录 |
| Windows | 已有 CurrentUser 证书与 WinINet PAC 控制、私有代理认证入口 | 当前检测已有 PAC/WPAD/手动代理并拒绝覆盖 | 与 Mac 相同的无额外认证系统入口、手动代理组合、WinINet/WinHTTP 与实际浏览器验收 |
| Android | 现有 App 内共享校园会话 | 本轮不修改系统 VPN 或 Wi-Fi 代理 | 单独实现 VPN/代理与后台生命周期；处理 Clash/aTrust 冲突、用户 CA 和各 App 的证书限制 |

自带独立代理配置的浏览器、显式绕过系统代理的客户端以及内置证书公钥固定的应用均需按各自机制单独适配。Android 系统在同一用户资料下仅允许激活一个 VPN 服务，需要专门设计移动端传输与并存方案；微信等独立应用也会在真机上逐一实测，与桌面端浏览器的验证结果分开归档。

## 当前机器与恢复入口

本轮实测面向用户当前已登录的本机 Mac dev 环境，全程保持已打开的 OneTHU 主窗口与登录账号不变。宿主机以太网与 Wi-Fi 原有的 HTTP/HTTPS/SOCKS 代理指向 `127.0.0.1:7897`，USB 10/100 LAN 与 Thunderbolt Bridge 为直连，本机安装专属 CA 也已通过 macOS 钥匙串信任核查。

无论在应用设置页点击恢复按钮，还是在终端执行 `onethu gateway system-disable --confirm`，均可随时还原系统网络设置。万一遇到恢复异常，程序会完整保留诊断日志及仍在被引用的本地监听与 PAC 脚本，保障当前网络不断连并方便继续排查；用户退出账号时则会优先切断校园数据转发通道。所有表单提交与业务写操作全程保持由用户在页面内主动触发，代理层绝不擅自自动重放。

单元测试与协议夹具跑通后，还将在宿主机真实浏览器中逐一核验日常浏览、外部代理并存及一键恢复表现，并将完整实测数据归档至专项验收报告。
