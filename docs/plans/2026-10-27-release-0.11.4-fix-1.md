# OneTHU 0.11.4-fix-1 Implementation Plan


**Goal:** 修复 0.11.4 桌面端启动阻塞与平板端交互反馈问题，发布三端 `0.11.4-fix-1` 补丁版，并核对 GitHub、清华云盘与官网的完整更新链路。

**Architecture:** 当本地 CLI 后台暂不可用时，学校图形界面登录直接回退使用本机原生会话，保障主流程顺畅可用；待后台恢复就绪后，再在账号归属、epoch 代次与登出意图的保护下完成延迟会话交接。整体完整保留 xiao-dreamr 的视觉样式及现有的 CLI、OH 能力；若个别修复难以收敛出干净边界，则随时可回退至样式合并基线。

**Tech Stack:** React / OneGUI、TypeScript、Tauri Rust、Node SDK/CLI、Android Gradle、GitHub Actions。

## Task 1: 反馈证据与边界

- 检查用户提供的最新截图（JPG）与 5.4 秒录屏，提取的关键帧仅保存在被 Git 忽略的本地 `output` 目录中，确保用户真实隐私数据留在本地。
- 复现 `CLI_START_FAILED` 异常阻断 `performLogin`、`currentFingerprint` 与 `resume` 主流程的具体代码分支。
- 定位实用模式设置面板误命中桌面三栏 `overflow:hidden` 样式规则，以及首页静默忽略课表加载报错的根因。

## Task 2: 登录独立于后台可用性

- 更新 `apps/desktop/src/lib/clients.ts` 与私有会话交接测试，先编写复现失败用例：确保后台启动失败时，学校登录、设备指纹读取与本机会话恢复依然能够正常走完，同时在遇到账号冲突、CLI 二次验证或用户显式退出时继续拦截不安全的会话移交。
- 持久化保存尚未绑定 epoch 的待交接意图；待后台恢复后，仅在后台处于空白未登出状态或已登录同一账号时执行绑定，遇到不同账号或已显式登出状态时保留现状。
- 完善 `cli_daemon.rs` 的启动诊断信息与子进程早退识别，同时延续原生日志的隐私脱敏规则与关闭主窗口后的后台常驻能力。
- 执行验证：`node tools/cli-session-handoff-test.mjs`、`node tools/login-attempt-state-test.mjs`，以及 SDK / CLI 单元测试与对应的 Rust 检查。

## Task 3: 平板设置与课程

- 调整 `SettingsOverlay` 在简洁与实用模式下的纵向滚动分类样式，同时保留完整模式的三栏桌面布局；在平板横竖屏视口下实测滚动触底、按钮点击与模型源切换反馈。
- 让首页「今日课程」复用与主课表一致的 primary + secondary 时间窗口数据源；加载中或拉取失败时展示对应的加载态与错误提示，仅在接口正常返回且当日确实无课时展示“今天没有课”空状态，并保留已结课与待上课的视觉区分。
- 使用合成课程数据补充数据源合并、加载状态切换与上课时间筛选的回归测试。

## Task 4: fix-1 版本与更新兼容

- 将界面版本展示、Cargo、Tauri、CLI 与 SDK 的版本号统一更新为 `0.11.4-fix-1`，Android `versionCode` 在 `11013` 基础上递增。
- 更新版本号比较器、云盘目录匹配与官网下载页解析逻辑以支持 `-fix-N` 补丁后缀；针对已安装的旧版 `0.11.4` 客户端，采用向后兼容的发布版本标记触发更新提醒，并在弹窗中准确显示 `0.11.4-fix-1` 名称。
- 逐一验证 `base → fix-1`、`fix-1 → fix-2`、`fix → 后续正式版` 的新旧排序以及跨平台下载链接与校验摘要，确保热修复补丁版能够被正确识别为新版本。

## Task 5: 验证与发布

- 待类型检查、i18n 词典、前端生产构建、认证账号边界及移动端触摸交互测试全部通过后冻结源码，并同步对齐 `main` 与 `dev3` 分支。
- 基于同一冻结提交触发 macOS 与 Windows GitHub Actions 构建，同时在本地使用正式证书构建 Android 安装包，逐一核验版本号、ABI 架构、标准 Logo、内置 CLI 与 Harness 架构及文件哈希摘要。
- 将三端产物完整上传至 GitHub Release 草稿与清华云盘各系统目录，复核无误后公开为 Latest，并同步更新官网中英文页面与下载镜像快照。
- 以匿名方式完整下载三平台云盘镜像并复算 SHA256，确认新版应用内 updater 与旧版客户端版本比较逻辑均能顺利检测到本次补丁更新。
- 报告中将浏览器及协议自动化验证与真机设备实测分项写明，如实标注 Windows 与 Android 的真机测试情况，并将最终发布结论归档至长期记忆。
