# 原型与数据模型


中文 · [English](../en/architecture/prototype-and-data.md) · [系统总览](../architecture.md)

## 产品对象与模式

OneTHU 围绕真实的校园学习与生活事务建模，让课程、作业、通知、文件等同一业务实体能够在功能列表、全局搜索、日程表、自由白板和智能体工具之间顺畅流转。每项实体都保留完整的来源标识，展示组件统一消费规范化后的数据模型，页面路由则携带定位该实体所需的上下文参数。

| 模式 | 交互组织 | 数据策略 |
| --- | --- | --- |
| 极简 | 固定首页与五个主要入口、搜索/OH | 保留既有账号与配置，隐藏高阶工作区界面 |
| 实用 | 日常事务、主要功能区与简化设置 | 按该模式暴露服务与交互 |
| 完整 | 白板、标签页、OneGO、组织及扩展 | 提供可组合的工作空间 |

当前所选模式保存在应用状态中，切换模式即可平滑调整界面复杂度与开放的能力范围。内容接收、外部分享与高阶工具在执行前也会同步核验当前模式、隐私授权与登录账号，确保后台执行边界与界面可见范围保持一致。免责声明中的云盘同步与智能体服务授权各自独立持久化，用户撤回授权后会立即中止相关的在途执行。实现见 [experienceMode](../../apps/desktop/src/state/experienceMode.ts) 与 [privacyConsent](../../apps/desktop/src/state/privacyConsent.ts)。

## 页面实例、标签页与工作区

每个 `ExplorerTab` 记录自身的唯一 `id`、页面类型、路由参数、显示标题、所属工作区及最近访问时间。除首页采用固定标识外，其余标签页均拥有相互独立的路由上下文：普通跳转默认优先复用已打开的同类实例，而执行“复制标签页”则会显式创建第二个独立实例，例如并排打开两个选课标签页时，各自的筛选与选课状态互不干扰。

`ExplorerWorkspace` 用于保存一组标签页快照以及可选的主题色、图标和当前活跃归属。系统设置、插件中心和 OH 管理通过高于标签内容区的全局浮层打开；界面上的 OneGO 负责展示用户收藏的常用页面与工作区，OneShot 则提供高频核心功能的快捷入口，两者在状态层对应各自专属的数据模型。

当用户从白板卡片内部打开某项具体作业或寻迹页面时，最终仍会进入统一的标签内容壳——内容留白、滚动容器和设备安全区统一由外层页面边界承担，白板组件入口只需传入对应的实体定位参数即可。源码：[explorer.ts](../../apps/desktop/src/state/explorer.ts)。

## 原子与深链

“原子（Atom）”引用将应用内一切可收藏、搜索、拖动和分享的对象连接到统一解析器，当前注册表涵盖页面、白板组件、业务实体与活跃标签页四类引用。`AtomView` 负责将任意原子引用解析为标准化的标题、图标、来源说明、打开函数以及可选的实时预览组件。

实体类引用携带着定位目标所需的业务主键与展示元数据，打开后再由对应的服务客户端拉取最新详情——例如网络学堂课程 ID、雨课堂 classroom ID、公告通知 ID 和课件附件引用各自遵循所属系统的标识规则。对于早期版本遗留的分隔符拼接 key，解析器保持向后兼容读取，并对标签页参数做确定性排序和编码，确保深链引用长期稳定。

全局搜索在本地即时匹配静态功能入口与已浏览过的数据缓存；若需深入检索特定业务（如全量邮件、云盘文件或课程库），则由用户在对应分类下按需发起服务端查询，兼顾搜索响应速度与校内接口负载。源码：[atoms.tsx](../../apps/desktop/src/state/atoms.tsx)、[favorites.ts](../../apps/desktop/src/state/favorites.ts)。

## 白板文档与几何

顶层 `BoardDoc` 包含文档版本号、白板集合、当前活动板及排列顺序。每块 `Board` 区分内置系统板与用户自建板，并支持按 portrait / landscape 朝向分别保存布局；板上的每个 `BoardItem` 则封装了业务组件规格（`WidgetSpec`）、网格坐标 `cell`、可选的自由画布像素矩形 `rect` 以及折叠、固定、尺寸档位等元数据。

```text
WidgetSpec（业务内容）
        + BoardItem（身份、尺寸、状态）
        + Board（页面与朝向）
        = 可恢复的白板文档
```

自由画布图层直接消费像素级 `rect` 渲染，而传统的网格 `cell` 契约仍继续服务于插件、OH 工具编排与旧版数据迁移。两套坐标变换在 `boardCore.ts` 模型层实时双向同步，围绕统一的基准列数、宽屏换算比例和参考画布尺寸解释布局，使同一块白板在不同视口宽度下都能保持协调的排版比例。

拖拽或缩放手势进行期间只更新瞬态几何预览，松手落定后再一次性写入持久化文档。手机端通过显式的编辑模式开关控制是否允许改动卡片位置与尺寸，日常浏览模式下完整保留页面上下滚动与卡片点击体验。历史撤销面向近期编辑步骤，“恢复默认”则用内置模板文档重建初始版面；自动内容尺寸拟合也会主动识别并保留用户手动调整过的卡片尺寸。

源码：[boardCore.ts](../../apps/desktop/src/state/boardCore.ts)、[boardEdit.ts](../../apps/desktop/src/state/boardEdit.ts)、[boardHistory.ts](../../apps/desktop/src/state/boardHistory.ts)、[FreeBoard.tsx](../../apps/desktop/src/components/FreeBoard.tsx)。

## 暂存、分享与导入

暂存箱支持随时收集文本片段、原子引用和本地文件。跨区域拖动时，手势协调器会明确区分“移动原组件位置”和“向目标容器投递内容”：一旦目标区域成功接收投放，当次手势即告完成，原组件保持原有几何位置不变。点击与起拖位移阈值、悬浮按钮坐标及高亮投放提示归属前端交互状态管理，实际收集的条目内容则由暂存数据模型负责持久化。

向外分享时，客户端会将受支持的内容打包上传到用户已授权的在线存储空间，并生成简短口令供接收方取回；提取阶段会依次校验短口令有效性、远端文件读取权限以及所指向的校内原实体对当前账号是否仍可访问。导入操作会在本地创建新副本并完整保留接收方原有的暂存箱内容，外部传入的文本、附件和技能说明均作为普通静态资料安全载入。

NFC 近场传递当前作为实验特性提供并附有设备可用性提示，日常跨设备流转推荐使用更为稳定的短口令方式。详细的支持对象与使用说明见 [暂存与组织指南](../sharing-and-organizations.md)、[OH 应用服务](../oh-app-services.md)。源码：[vault.ts](../../apps/desktop/src/state/vault.ts)、[vaultShare.ts](../../apps/desktop/src/state/vaultShare.ts)、[vaultDrag.ts](../../apps/desktop/src/components/vault/vaultDrag.ts)。

## 数据归属与持久化

| 数据 | 存储/权威 | 同步或暴露方式 |
| --- | --- | --- |
| 学校会话、指纹、信任因子 | 设备私有会话存储 | 原生/daemon 私有交接，公开工具只给状态 |
| 页面、工作区、白板偏好 | GUI 文档与本地状态 | 通过应用保存/同步流程恢复 |
| Learn 枚举资源 | 当前账号资源表 | 公开 `resourceRef`，内部保留认证地址 |
| 日程、邮箱/日历相关配置 | 当前宿主的版本化账号文档 | 已安装 daemon 的桌面共享读取/写入 |
| 常驻任务与执行账本 | 当前任务管理器 | 安装/卸载交接，账号与批准范围核验 |
| 个人名片、组织、好友索引 | 归属确认的本地与远端数据 | 云盘/GitLab 授权与版本冲突处理 |
| 模型与 IM 配置 | 各账号/设备私有配置 | 状态接口投影公开字段 |

运行时目录通过 Windows 文件系统 ACL、Unix 当前用户私有权限以及单实例 profile 锁实现操作系统级的访问隔离；SDK 中的部分模型连接配置与本地状态直接以这种私有文件形式存放在本机磁盘上，用户在管理个人设备登录权限与系统备份时应妥善做好本机防护。

## 共享数据与合并

桌面端安装常驻后台后，日程表及相关账号文档会通过 `sharedCalendar.ts` 与私有 `desktop.data*` 接口统一读写后台持有的单一权威数据：每次写入均附带内容版本号，若遇并发冲突则完整保留冲突详情与持有者信息供上层处理。移动端及未安装后台的桌面环境直接读写应用内存储；后续安装或卸载后台组件时，系统会自动完成数据迁移与定时任务交接。

处理多端或多人协作变更时，可无损合并的条目优先自动保留双方新增内容；遇到个人名片字段或组织核心配置这类互斥修改时，则交由用户显式选择保留版本。协作读写要求远端成员权限、云盘共享资料库归属与当前登录账号三者同时成立；分享内容中的源文件引用负责定位资料路径，实际能否下载仍由远端存储服务按接收方权限实时判定。

本地组织索引与远端的组织成员、协作项目、团队公告及共享文件资源各自按独立的同步周期演进：在本地新建组织索引与在云盘端完成共享目录授权分属前后两个阶段，状态面板会清晰呈现各自的就绪进度。完整协作流程与现行行为见 [共享与组织](../sharing-and-organizations.md)。

## 失败后的保留范围

遇到瞬时网络超时时，界面可继续展示本地已有的最近缓存，并清晰标注数据来源与上次更新时间；若服务端明确返回会话已失效或无访问权限，界面则会直接呈现对应的登录或权限提示，引导用户重新认证。切换校园账号时，系统会立即中止原账号的所有在途请求及待提交写入，待视图状态清空刷新后再加载新账号的数据。对于文件上传、邮件发送与场馆预约等写操作，若因网络中断导致返回结果未知，客户端会优先向远端查询实际执行状态；本地取消操作仅用于阻断尚未发出的后续提交。
