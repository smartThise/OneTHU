## 0. 背景与问题定义

### 0.1 用户画像（统一画像）

- **清华学生**（涵盖本科生与研究生，日常场景基本一致），以 Android 移动端为主力使用环境，涵盖各院系专业背景；
- 体验痛点反馈：功能覆盖全面，但初看容易感到「偏极客、无从下手、眼花缭乱」，视觉观感「偏朴素、工具感重」。

### 0.2 核心设计约束（方案基线）

| 约束 | 说明 |
|------|------|
| **原子收藏机制完整保留** | 收藏体系（`state/favorites.ts` / `favs.tsx` / `Collect.tsx` / `FavAtomPicker.tsx` / 小组件绑定）是产品的核心特色，交互逻辑与底层数据结构**原样保留**。本方案在收藏体系**之外**补充常用推荐区，二者互补并存（见 §2.5） |
| **统一学生视角** | 面向全体清华学生统一设计：首次启动省去学历询问，界面统一呈现；研究生收入等少数特定模块按常规功能归组并在说明中标注适用人群 |
| **功能完整保留** | 秉承「能力做加法，界面做减法」的理念：完整保留全部既有功能入口，重点梳理层级与默认可见性 |
| **轻量自研控件体系** | 延续手写设计令牌与自研组件的轻量架构，保持无外部重型 UI 组件库依赖 |
| **业务数据层稳定** | `@onethu/core` 与 `@onethu/info-lib` 的业务逻辑保持稳定；本次升级聚焦于界面架构、视觉体验与文案表达 |

### 0.3 三个核心问题与改造主线

| # | 问题 | 主线 | 章节 |
|---|------|------|------|
| P1 | 原有入口按后台系统划分，首屏信息密集、缺少任务主线 | **任务导向的信息架构** | §2 |
| P2 | 视觉风格偏朴素、同屏信息密度偏高 | **MD3 视觉改造 + 动态色调 + 舒展降密** | §3 |
| P3 | 账号绑定藏在设置深处、首启步骤偏长、提示语偏技术化 | **入口场景化 + 渐进首启 + 亲和文案** | §4 |

### 0.4 成功标准（验收指标，融合外部建议 §7）

1. **新用户 5 分钟即刻上手**：新装应用 → 登录统一身份认证 → 直接看到带真实课表的「今日」页，全程无需提前配置外部账号；
2. **典型任务可用性测试**（邀请 5–10 名非计算机专业学生）：查明日作业、交雨课堂作业、查校园卡余额、交电费、看洗衣机状态、亲友报备入校——每项任务**点击 ≤ 3 次、10 秒级完成**，并记录完成率、求助率与走错入口次数；
3. **首屏清爽克制**：默认「今日」页卡片 ≤ 6 张，底部主导航固定为 5 项；
4. **文案门禁全绿**（按扩展后的新词表校验，见 §4.5）；
5. **启动性能稳定**：Android 冷启动与首帧耗时保持在现版 ±10% 范围内；
6. **收藏体验专项回归**：个人收藏与桌面小组件绑定在改版后与现版保持完全一致。

## 2. 主线一：任务导向的信息架构（P1）

### 2.1 核心原则（吸收外部建议并贴合项目实际修订）

- **围绕学生真实任务编排入口**：从「看作业、交电费、查洗衣机」等日常意图出发组织界面，淡化「雨课堂」「info」等后台系统边界；
- **能力做加法，界面做减法**：首屏保持清爽聚焦，长尾服务通过分组目录、全局搜索与 AI 面板顺畅直达；
- **账号绑定融入业务现场，设置页专注集中管理**：在用户首次使用某项具体服务时就地引导连接（§4.3）；
- **系统推荐与个人收藏互补并存**（修订外部建议 4.3）：**个人收藏体系原样保留**，同时新增「常用推荐」作为轻量补充（见 §2.5）。

### 2.2 新信息架构：底部 5 Tab

```
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│  今日    │  待办    │  服务    │  收藏    │  我的    │
│  Today  │  Tasks  │Services │  Favs   │   Me    │
└─────────┴─────────┴─────────┴─────────┴─────────┘

今日：问候语 → 下一节课卡 → 今日作业 DDL 卡 → 余额速览条（校园卡+电费）
      → 最近通知（≤3 条）→ 常用推荐区（§2.5）
待办：全部作业（将现有合并作业视图升级为独立一级页签，保留外部作业源与忽略机制）
服务：分组目录（学习 / 日程 / 生活 / 预约 / 行政）+ 顶部全局搜索框
收藏：现有收藏页原样迁入一级页签，进一步强化直达体验
我的：个人信息、账号与绑定、通知设置、外观、日历、高级模式开关、帮助、关于
```

与外部建议的取舍说明：外部咨询方案将底部 5 Tab 设为「首页 / 待办 / 消息 / 服务 / 我的」，缺少收藏位置；结合本项目的核心特色，本方案将通知消息融入「今日」通知卡与「待办」页签，为「收藏」留出专属的一级入口。

### 2.3 实施步骤

1. [ ] 新增 `state/navigation.ts` 功能注册表（见 §2.6 元数据结构），集中声明 §1.2 全量功能清单、分级、检索关键词与账号绑定依赖；**页面 ID 沿用既有命名，保持现有路由平滑兼容**；
2. [ ] 升级 `Layout.tsx` 外壳：在原有「桌面侧栏 + 移动端抽屉（`<860px`）」基础上，为移动端**新增**固定底部导航栏（按 §2.8.1 三档断点切换）；`TabManageModal.tsx` 继续服务于各聚合页（LifePage / ReservePage / 收藏夹）的栏目管理，与底部主导航各司其职；
3. [ ] 演进「今日」页卡片集（依托既有 `lib/homeCards.ts` 注册表与 `HomeWidgets.tsx` 卡片架构）：按 §2.2 收敛默认展示的卡片数量，补充余额速览条与常用推荐卡，并复用 `restoreDefaultTodayCards` 更新默认布局；
4. [ ] 将 `AssignmentsPage` 升级为「待办」一级页签直达视图；
5. [ ] 新增「服务」分组目录页（复用 `InfoPage.tsx` 页签骨架）并将现有收藏页接入「收藏」一级页签；
6. [ ] 入口映射逐项核对：在 PR 中对照 §1.2 全量清单逐条勾选新入口路径，确保每项既有功能均清晰可达。

### 2.4 时间敏感的动态提升（P2，可选增强）

在选课季、考试周、教学评估季及长假报备窗口期，支持将对应服务从 `group` 临时提升至「今日」页推荐卡片。实现方式是在 `navigation.ts` 中预留 `boostWindow` 日期区间字段，由 `Today.tsx` 按当前日期动态读取，首版先行预留数据结构。

### 2.5 常用推荐区（与个人收藏互补并存）

- 在「今日」页底部补充「常用」横滑卡片：排序逻辑**直接复用现有的 `lib/usage.ts`（本地使用计数 `onethu.usage.counts.v1`）与 `lib/suggest.ts`（`suggestAtoms`）**，无需额外采集数据；
- **个人收藏体系保持原貌**：一级「收藏」页签、长按收藏与桌面小组件绑定均维持既有体验；推荐区则为尚未手动整理收藏夹的同学提供开箱即用的快捷通道；
- 长按推荐条目可选择「固定到推荐位」（独立保存在本地），与个人收藏夹分属两套数据、互不影响；
- 空状态友好呈现：尚无本地点击记录时，按 §1.2 的 `core` 顺序展示精选高频入口。

### 2.6 功能注册表 metadata（吸收外部建议 §5，前端单文件集中维护）

```ts
// state/navigation.ts 中每项：
{
  id: "yuketang_homework",        // 沿用现有页面/原子 ID
  name: "雨课堂作业",

  visibility: "core",             // core|group|buried|advanced
  needBind?: "yuketang",          // 绑定依赖键，供 ConnectGate 使用
  keywords: ["雨课堂", "作业", "课件"],   // 供搜索与 AI

}
```

全局搜索（结合既有收藏项检索、`lib/suggest.ts` 索引与 `lib/infoApps.ts` 即输即筛体验）、「服务」页分组、常用推荐、AI 意图解析以及 `ConnectGate` 绑定引导**统一消费同一份注册表数据**，作为整套信息架构的核心枢纽在 M0 阶段先行定稿。

### 2.8 双端布局规范（移动端与桌面端分端适配）

> 原则：**一套数据、一套令牌、两套专属外壳与布局**。桌面端充分发挥宽屏多栏优势，移动端专注单手触控效率：移动端采用底部 5 Tab 导航，桌面端沿用并升级侧边导航栏，在视口断点处清晰切换形态。

#### 2.8.1 断点与外壳

## 7. 关键架构决策记录（ADR）

1. **坚持轻量自研组件体系**：综合权衡 APK 安装包体积、移动端 WebView 渲染性能以及现有 22 个定制组件与校园专属交互的契合度，基于三层设计令牌演进手写组件的长期维护成本更低、体验把控更精细。
2. **选用 MD3 作为视觉与交互基底**：核心用户群以移动端高校学生为主，MD3 的卡片层级、底部导航与手势反馈高度契合主流移动应用的操作直觉。
3. **令牌层先行重构，组件分五批演进**：依托 Compat 兼容映射层实现全站无感换肤，再按控件类别分批精细打磨，每批均可独立验证与安全回退。
4. **完整保留个人收藏，补充常用推荐**（修订外部建议 4.3）：原子收藏与小组件绑定是深度用户的得力工具，常用推荐区则作为并存的自动化补充，让尚未整理收藏夹的新老同学也能快速直达高频服务。
5. **面向「清华学生」统一设计，省去身份分层**（修订外部建议 4.6）：本科生与研究生的日常校园事务高度重合，首次启动免去学历询问，界面统一清爽；研究生收入等少数特定模块作为常规功能归入行政分组，辅以清晰的适用人群说明即可。
6. **功能注册表单一数据源**：导航菜单、服务分组、全局搜索、命令面板、常用推荐与 `ConnectGate` 绑定引导统一读取 `state/navigation.ts`，消除多处重复维护带来的同步偏差。
7. **通过高级模式分层收纳进阶能力**：插件管理、Trace 与开发者工具在标准模式下温和收起以保持日常界面简洁专注，开启高级模式后即可完整调用全部进阶能力。
